# Карточки

## Union / intersection

```card
front: Что означает тип A | B (union)?
back: Значение это либо A, либо B. Доступны только операции, общие для обоих типов, пока тип не сужен.
tags: [ts, union]
```

```card
front: Что означает тип A & B (intersection)?
back: Значение удовлетворяет обоим типам сразу. Для объектов — должно иметь все свойства из A И из B.
tags: [ts, intersection]
```

```card
front: Для объектов | даёт больше или меньше гарантированных свойств, чем &?
back: "| даёт меньше (только общие свойства); & даёт больше (объединение всех). Кажется вывернутым, но логично."
tags: [ts, union, intersection]
```

## Литеральные типы

```card
front: Что такое литеральный тип? Пример.
back: "Тип, которому принадлежит ровно одно значение: \"north\" или 42. Union литералов (\"GET\" | \"POST\") = типобезопасный набор вариантов (аналог enum через iota в Go)."
tags: [ts, literal]
```

```card
front: Почему const b = "north" имеет тип "north", а let a = "north" — тип string?
back: const неизменна → TS фиксирует точный литеральный тип. let можно переприсвоить → TS расширяет до общего string.
tags: [ts, literal, inference]
```

```card
front: Union литералов или enum — что предпочесть в современном TS?
back: "Обычно union литералов: проще, лучше выводится, не оставляет следа в рантайме. enum — исключение, генерирует реальный объект."
tags: [ts, enum, literal]
```

## Сужение типов

```card
front: Что такое narrowing (сужение типов)?
back: TS читает обычные JS-проверки (typeof, instanceof, in, === null) и автоматически уточняет тип внутри ветки (control flow analysis).
tags: [ts, narrowing]
```

```card
front: Чем сужать примитивы, а чем классы?
back: Примитивы — typeof (typeof x === 'string'). Классы/конструкторы — instanceof. Для type instanceof не работает (стирание).
tags: [ts, narrowing]
```

```card
front: Что такое пользовательский type guard и как выглядит его сигнатура?
back: "Функция с возвращаемым типом-предикатом: function isUser(x: unknown): x is User. Если вернула true, TS считает аргумент типом User. Нужна для легализации внешних данных."
tags: [ts, typeguard]
```

## Дискриминированные union

```card
front: Что такое дискриминированный (tagged) union?
back: "Union вариантов с общим полем-тегом литерального типа (status: 'ok' | 'error'). Проверка тега сужает весь объект до нужной формы."
tags: [ts, discriminated]
```

```card
front: Какое преимущество дискриминированного union перед (value, error) из Go?
back: "Делает невозможные состояния непредставимыми: нельзя иметь data и message одновременно, нельзя прочитать data, не доказав успех. Компилятор гарантирует, а не договорённость."
tags: [ts, discriminated, go]
```

```card
front: Как сделать проверку исчерпанности switch по дискриминированному union?
back: "В default присвоить значение переменной типа never: const _: never = s. Если добавят новый вариант и забудут case, эта строка перестанет компилироваться."
tags: [ts, never, exhaustive]
```

## Типы как множества, границы сужения

```card
front: Как думать про | и & через множества значений?
back: Тип — множество допустимых значений. A | B — объединение множеств (значений больше, гарантий меньше). A & B — пересечение (значений меньше, гарантий больше). never — пустое множество, unknown — всё.
tags: [ts, union, intersection, mental-model]
```

```card
front: Чем сужать массив, если typeof для него бесполезен?
back: Array.isArray(x) — TS понимает эту проверку. typeof [] даёт "object", поэтому им массив не отличить.
tags: [ts, narrowing, arrays]
```

```card
front: Что такое функция-утверждение (asserts x is T)?
back: Функция, которая бросает ошибку, если условие не выполнено; после её вызова TS считает тип уточнённым. Удобна для инвариантов на границе.
tags: [ts, asserts, typeguard]
```

```card
front: Почему сужение может «потеряться» внутри колбэка?
back: Колбэк выполнится позже, и значение (особенно let или свойство объекта) к тому моменту могло измениться. TS осторожничает. Лечится копированием в локальную const до колбэка.
tags: [ts, narrowing, pitfall]
```

```card
front: Надёжный приём, когда сужение свойства объекта «не держится»?
back: Скопировать значение в локальную const (const value = box.value) и проверять/использовать её — к const сужение прилипает надёжно.
tags: [ts, narrowing]
```

```card
front: Почему набор опциональных полей — плохая модель вариантов данных?
back: Проверка одного поля ничего не говорит TS про остальные, и невозможные комбинации остаются выразимыми. Правильно — дискриминированный union с полем-тегом.
tags: [ts, discriminated, design]
```
