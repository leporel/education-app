# Урок 01 — Значения, функции и замыкания на практике

Цель урока — пощупать руками три вещи, без которых дальше нельзя: как ведут себя
значения, что функция — это значение, и как работают замыкания. Всё, что ниже, можно
вставлять в консоль браузера (F12 → Console) или в Node.

## Разогрев

Три вопроса для самопроверки (ответь, не подглядывая в теорию):

- Сколько примитивных типов в JS и какой из них отвечает за все числа?
- Чем `null` отличается от `undefined`?
- Почему `[]` в условии `if` ведёт себя как «истина»?

## Новая тема: значения, которые тебя удивят

JavaScript любит делать вид, что всё хорошо, даже когда всё странно. Прогоним
несколько строк и научимся не доверять интуиции из статически типизированных языков.

```js
typeof 42;          // "number"
typeof 42n;         // "bigint"
typeof "hi";        // "string"
typeof true;        // "boolean"
typeof undefined;   // "undefined"
typeof null;        // "object"  ← историческая бага языка, живёт с 1995-го, не чини
typeof function(){} // "function"
```

`typeof null === "object"` — это знаменитый баг, который не стали чинить, чтобы не
сломать старый код. Просто прими как факт и узнавай в лицо.

Теперь — про «одно число на всё»:

```js
1 / 0;              // Infinity   (не паника, не ошибка — просто Infinity)
-1 / 0;             // -Infinity
0 / 0;              // NaN        ("Not a Number", но typeof NaN === "number" 🙃)
NaN === NaN;        // false      ← NaN не равен даже самому себе!
Number.isNaN(NaN);  // true       ← вот так правильно проверять на NaN
```

В Go деление на ноль для целых — это паника. В JS — мирный `Infinity`. Разные
философии: Go предпочитает упасть громко, JS — продолжить любой ценой.

## Функция — это значение: маленький практикум

```js
// кладём функции в массив и вызываем по очереди
const ops = [
  (a, b) => a + b,
  (a, b) => a - b,
  (a, b) => a * b,
];

for (const op of ops) {
  console.log(op(6, 2));   // 8, 4, 12
}

// функция, возвращающая функцию
const greeter = (greeting) => (name) => `${greeting}, ${name}!`;
const ru = greeter("Привет");
const en = greeter("Hello");
ru("Слава");   // "Привет, Слава!"
en("World");   // "Hello, World!"
```

`greeter` — это фабрика функций. `ru` и `en` — две разные функции, каждая «помнит»
своё `greeting`. Помнит — потому что замкнулась над ним. Переходим к главному.

## Разобранный пример: приватный счётчик на замыкании

Задача: сделать счётчик с операциями `inc`, `dec`, `value`, причём так, чтобы извне
нельзя было залезть в его внутреннее число напрямую. В Go ты бы спрятал поле за
неэкспортируемым именем структуры. В JS приватность даёт замыкание:

```js
function createCounter(start = 0) {
  let count = start;                 // приватная переменная — снаружи не видна

  return {
    inc() { count += 1; return count; },
    dec() { count -= 1; return count; },
    value() { return count; },
  };
}

const c = createCounter(10);
c.inc();    // 11
c.inc();    // 12
c.dec();    // 11
c.value();  // 11
c.count;    // undefined — снаружи поля count просто нет, оно живёт в замыкании
```

Разбор по шагам:

1. `createCounter` создаёт локальную переменную `count`.
2. Возвращает объект с тремя функциями. Все три замкнулись над одной и той же `count`.
3. После `return` сама `createCounter` завершилась — но `count` жива, потому что на
   неё ссылаются методы возвращённого объекта.
4. Снаружи к `count` не подобраться: единственный доступ — через методы. Это и есть
   инкапсуляция без классов и без `private`.

## Итог

Запомнить после урока: **числа в JS — единый float-тип со своими сюрпризами
(`NaN`, `Infinity`); функция — это значение, которое можно передавать и возвращать;
замыкание — функция плюс её «рюкзачок» переменных, и именно оно даёт приватность без
классов.** На замыканиях держится половина реального JS/TS-кода — этот урок стоит
прожить руками, а не просто прочитать.
