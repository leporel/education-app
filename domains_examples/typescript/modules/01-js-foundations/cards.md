# Карточки

## Природа TS и JS

```card
front: Что компилятор TypeScript делает с типами перед запуском кода?
back: Проверяет их, а затем стирает. В рантайме типов TS не существует — выполняется обычный JavaScript.
tags: [ts, erasure]
```

```card
front: Можно ли в рантайме узнать TS-тип переменной (как reflect.TypeOf в Go)?
back: Нет. Типы стёрты. Спрашивать в рантайме можно только про JS-значения (typeof, instanceof), но не про TS-типы.
tags: [ts, erasure]
```

## Значения и типы

```card
front: Сколько примитивных типов в JavaScript и какие?
back: "Семь: number, string, boolean, undefined, null, bigint, symbol. Восьмой тип — object (включая функции)."
tags: [js, types]
```

```card
front: Какой единственный числовой тип в JS и как он устроен?
back: number — всегда 64-битный float (IEEE 754). Отдельных int/float нет. Безопасные целые до 2^53; дальше bigint.
hint: Поэтому 0.1 + 0.2 !== 0.3
tags: [js, number]
```

```card
front: Чем null отличается от undefined?
back: undefined — «значение не задавали» (по умолчанию от языка). null — «намеренно пусто» (кладёт программист).
tags: [js, null]
```

## Переменные

```card
front: Когда использовать const, let, var?
back: По умолчанию const; let только если нужно переприсваивать; var — никогда (легаси с плохой видимостью).
tags: [js, variables]
```

```card
front: const user = {...}; user.name = "Bob" — это ошибка?
back: Нет. const запрещает переприсвоить переменную, но не запрещает менять поля объекта.
tags: [js, const]
```

## Функции и замыкания

```card
front: Что такое замыкание (closure)?
back: Функция вместе с переменными из области, где она была создана. Она «уносит» их с собой и видит даже после завершения внешней функции.
tags: [js, closure]
```

```card
front: Чем отличается arrow-функция от обычной в плане this?
back: Arrow-функция не имеет своего this — берёт его лексически из окружающего кода. Обычная function получает this в зависимости от того, как её вызвали.
tags: [js, this, arrow]
```

```card
front: От чего зависит значение this в обычной функции?
back: От того, КАК функцию вызвали, а не где написали. user.greet() → this=user; оторвали fn=user.greet; fn() → this потерян.
tags: [js, this]
```

## Прототипы

```card
front: Как в JS работает наследование на базовом уровне?
back: "Через прототипы: у объекта есть скрытая ссылка на объект-прототип. Нет свойства — движок ищет в прототипе по цепочке (делегирование, не копирование)."
tags: [js, prototype]
```

## Равенство и truthiness

```card
front: === или == — что использовать и почему?
back: "Всегда === (и !==). == приводит типы по непредсказуемым правилам (0 == \"\" → true). Исключение-идиома: x == null ловит null и undefined разом."
tags: [js, equality]
```

```card
front: Перечисли все falsy-значения в JS.
back: false, 0, "" (пустая строка), null, undefined, NaN, 0n. Всё остальное truthy — включая [] и {}!
tags: [js, truthy]
```

```card
front: Чем ?? отличается от || для значения по умолчанию?
back: "|| подставляет fallback на любое falsy (включая 0 и \"\"). ?? — только на null/undefined. Для «0 и пустая строка валидны» нужен ??."
tags: [js, nullish]
```

## Модули и event loop

```card
front: Два вида экспорта в ES Modules?
back: Именованные (export function foo, импорт в { foo }) и один default на файл (export default, имя при импорте выбираешь сам).
tags: [js, modules]
```

```card
front: Сколько потоков выполняет твой JS-код и как тогда работает асинхронность?
back: Один поток. Долгие операции отдаются окружению (браузер/Node), их колбэки ставятся в очередь и выполняются через event loop, когда основной код освободится.
tags: [js, eventloop]
```

```card
front: Почему setTimeout(fn, 0) выполнится после следующей строки синхронного кода?
back: Колбэк уходит в очередь задач, а очередь обрабатывается только после того, как текущий синхронный код доработал до конца.
tags: [js, eventloop]
```

## Объекты, массивы и ссылки

```card
front: Чем объект JS отличается от структуры Go в плане формы?
back: "Форма не фиксирована: свойства можно добавлять и удалять в рантайме. Обращение к несуществующему свойству даёт undefined, а не ошибку."
tags: [js, objects]
```

```card
front: "const a = { n: 1 }; const b = a; b.n = 42; чему равно a.n?"
back: 42. Объекты и массивы живут по ссылке — присваивание копирует ссылку, а не значение. Примитивы копируются по значению.
tags: [js, objects, reference]
```

```card
front: Что проверяет === для двух объектов?
back: "Тождественность ссылок («тот же самый объект?»), а не равенство содержимого. { n: 1 } === { n: 1 } → false."
tags: [js, objects, equality]
```

```card
front: Как сделать поверхностную и глубокую копию объекта?
back: Поверхностную — { ...obj } (только верхний уровень, вложенные объекты общие). Глубокую — structuredClone(obj).
tags: [js, objects, copy]
```

```card
front: Чем for...of отличается от for...in?
back: for...of идёт по ЗНАЧЕНИЯМ (массивы, Map, Set), for...in — по КЛЮЧАМ (строкам) и для массивов не предназначен.
tags: [js, iteration]
```

```card
front: Что вернёт [10, 9, 1].sort() и почему?
back: "[1, 10, 9] — sort без компаратора сравнивает элементы как строки. Для чисел нужно .sort((a, b) => a - b). И sort мутирует исходный массив."
tags: [js, arrays, pitfall]
```

```card
front: Какие методы массива возвращают новый массив, а какие мутируют исходный?
back: "Новый: map, filter, slice, concat, toSorted. Мутируют: push, pop, splice, sort, reverse. Перед sort часто делают копию [...arr]."
tags: [js, arrays]
```

```card
front: Когда брать объект, когда Map, когда Set?
back: Объект — фиксированный набор известных полей. Map — произвольные меняющиеся ключи (любого типа), есть size и удобный перебор. Set — уникальные значения.
tags: [js, map, set]
```

## Деструктуризация, spread, rest

```card
front: "Что делает const { city: town = \"нет\" } = user?"
back: Достаёт свойство city, кладёт в переменную town (переименование) и подставляет "нет", если свойства нет (значение по умолчанию).
tags: [js, destructuring]
```

```card
front: Одни и те же ... — когда рассыпают, а когда собирают?
back: "Внутри литерала или вызова — рассыпают (spread: [...a], f(...args)). В позиции объявления или параметра — собирают (rest: const [h, ...t], function f(...args))."
tags: [js, spread, rest]
```

```card
front: Как «обновить» одно поле объекта, не мутируя его?
back: "{ ...base, port: 8080 } — копия плюс переопределение. При совпадении ключей побеждает тот, что правее."
tags: [js, spread, immutability]
```

```card
front: Как в JS делают «именованные аргументы»?
back: "Передают один объект и деструктурируют его в параметрах: function f({ name, age = 18 }) {}. Порядок аргументов перестаёт иметь значение."
tags: [js, destructuring, functions]
```

## Опциональная цепочка и hoisting

```card
front: Что делает user.address?.city, если address отсутствует?
back: "Вернёт undefined вместо TypeError: ?. прерывает цепочку, если слева null/undefined. Формы: obj?.prop, fn?.(), arr?.[0]."
tags: [js, optional-chaining]
```

```card
front: Когда ставить ?. , а когда не надо?
back: "Когда отсутствие значения — нормальный сценарий. Если поле обязано быть по логике, ?. маскирует настоящий баг: лучше упасть громко."
tags: [js, optional-chaining, style]
```

```card
front: Что такое hoisting и TDZ?
back: Hoisting — объявления регистрируются до выполнения, поэтому function-объявление видно выше по коду. TDZ — запрет обращаться к let/const до строки объявления (ReferenceError); var в этом случае молча даёт undefined.
tags: [js, hoisting]
```

## Ошибки

```card
front: Чем обработка ошибок в JS принципиально отличается от Go?
back: "В Go ошибка — возвращаемое значение, которое видно в сигнатуре. В JS ошибка — исключение: throw летит вверх по стеку, а в типах функции нет никакой информации о том, бросает она или нет."
tags: [js, errors, go]
```

```card
front: Что можно бросить через throw и почему это важно для TS?
back: Что угодно — строку, число, объект, не только Error. Поэтому переменная в catch имеет тип unknown и требует сужения (err instanceof Error).
tags: [js, errors]
```

```card
front: Чем finally похож на defer и чем отличается?
back: Похож тем, что выполняется в любом случае. Отличается тем, что привязан к блоку try, а не к функции, и не имеет очереди вызовов.
tags: [js, errors, go]
```
