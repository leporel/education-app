# Карточки

## Основы классов

```card
front: class в JS — это отдельный механизм или что-то поверх прототипов?
back: Синтаксический сахар над прототипами. Под капотом всё те же объекты с цепочкой прототипов, запись просто привычнее.
tags: [ts, class, prototype]
```

```card
front: Что такое parameter properties (сокращённая инициализация полей)?
back: "Объявление поля прямо в параметрах конструктора с модификатором: constructor(public readonly x: number) {} — TS сам создаст поле и присвоит."
tags: [ts, class]
```

```card
front: Что такое геттер (get value())?
back: Метод, к которому обращаются как к свойству (c.value, без скобок). Удобно для вычисляемых/защищённых свойств.
tags: [ts, class, getter]
```

## Модификаторы доступа

```card
front: "Чем private отличается от #-приватных полей?"
back: "private — проверка только во время компиляции (в рантайме поле доступно через as any). #field — настоящая рантайм-приватность, извне недоступно никак."
tags: [ts, class, private]
```

```card
front: Гарантирует ли private приватность в рантайме?
back: "Нет. Это compile-time контракт (как readonly). Настоящая рантайм-приватность — только #-поля стандарта JS."
tags: [ts, private]
```

## Наследование и абстракции

```card
front: Чем abstract class отличается от обычного?
back: Нельзя инстанцировать (new). Может иметь abstract-методы без реализации, которые наследники обязаны определить, плюс общие конкретные методы.
tags: [ts, abstract]
```

```card
front: Нужен ли implements, чтобы класс подходил под интерфейс в TS?
back: Нет — структурная типизация сработает и без него (как в Go). implements даёт явную проверку и понятную ошибку при забытом методе; документирует намерение.
tags: [ts, implements, go]
```

```card
front: Есть ли наследование классов в Go? А в TS?
back: В Go наследования нет (только встраивание структур = композиция). В TS есть полноценное наследование через extends с полиморфизмом.
tags: [ts, inheritance, go]
```

## Композиция vs наследование

```card
front: Почему предпочитают композицию наследованию?
back: Глубокие иерархии хрупки (хрупкий базовый класс, жёсткая связь, плохо описывают реальность). Композиция = собирать поведение из независимых частей. Go возвёл это в закон.
tags: [ts, composition]
```

```card
front: Практический ориентир по глубине наследования?
back: Глубже двух уровней — стоп, спроси, не лучше ли композиция. Наследование — для редких честных «is-a», композиция — для всего остального.
tags: [ts, composition]
```

## this и декораторы

```card
front: Что произойдёт, если передать метод класса как колбэк напрямую (setInterval(this.tick))?
back: "Потеряется this (метод оторван от экземпляра). Решение: обернуть в стрелку (() => this.tick()) или объявить метод стрелочным полем."
tags: [ts, this, class]
```

```card
front: Что такое @-декораторы и нужно ли писать свои на старте?
back: Способ декларативно навесить поведение на класс/метод/поле. Используются в основном фреймворками (NestJS, Angular, ORM). Свои писать на старте не нужно — достаточно узнавать синтаксис.
tags: [ts, decorators]
```

## static и свои ошибки

```card
front: Что такое static-член класса и где его типично применяют?
back: Поле/метод самого класса (обращение ClassName.x), у экземпляров его нет. Типично — константы и фабричные методы (Temperature.fromCelsius) вместо голого new.
tags: [ts, class, static]
```

```card
front: Зачем делать private constructor?
back: Чтобы объект создавался только через фабричный static-метод — там можно провалидировать аргументы и дать осмысленное имя (как NewX(...) в Go).
tags: [ts, class, static]
```

```card
front: Зачем нужны свои классы ошибок (class MyError extends Error)?
back: Классы существуют в рантайме, поэтому по ним работает instanceof — единственный надёжный способ разобрать ошибку по типу и достать её поля. type-алиас для этого не подойдёт (стирается).
tags: [ts, errors, class]
```

```card
front: Три правила гигиены при наследовании от Error?
back: "1) вызвать super(message); 2) задать this.name; 3) исходную ошибку передавать через { cause: err } (аналог оборачивания %w в Go)."
tags: [ts, errors]
```

```card
front: Как разобрать ошибку в catch, если типов ошибок несколько?
back: "Цепочкой instanceof от конкретных к общим: ValidationError → AppError → Error → иначе «брошено не Error». Тип в каждой ветке сужается, поля доступны."
tags: [ts, errors, narrowing]
```
