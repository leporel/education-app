# Карточки

## Зачем TS и стирание

```card
front: Какую главную проблему JavaScript решает TypeScript?
back: Сдвигает обнаружение ошибок типов «влево» — с рантайма (прод) на этап написания кода (редактор/компиляция).
tags: [ts, why]
```

```card
front: Существуют ли типы TypeScript во время выполнения программы?
back: Нет. Компилятор проверяет типы и стирает их. В рантайме выполняется обычный JS без какой-либо информации о TS-типах.
tags: [ts, erasure]
```

```card
front: Можно ли доверять типу внешних данных (JSON с сервера), объявленному в TS?
back: Нет. TS верит на слово (as User — обещание, не проверка). Внешние данные нужно валидировать в рантайме (напр. zod).
tags: [ts, erasure, validation]
```

## Структурная типизация

```card
front: Структурная vs номинальная типизация — в чём разница?
back: "Номинальная: совместимость по имени типа (Go-структуры, Java). Структурная: по форме/набору свойств (весь TS). «Крякает как утка — значит утка»."
tags: [ts, structural]
```

```card
front: "type Celsius = number; type Fahrenheit = number; let f: Fahrenheit = celsiusValue — TS пропустит?"
back: Да. Для TS оба типа — это number (одна форма). В Go именованные типы номинальны и такое не прошло бы. Для номинальной защиты в TS нужны брендированные типы.
tags: [ts, structural, go]
```

```card
front: Чем структурная типизация TS отличается от структурности в Go?
back: В Go структурно совместимы только интерфейсы (по методам). Именованные типы Go номинальны. В TS структурно ВСЁ.
tags: [ts, structural, go]
```

## any / unknown / never

```card
front: Что делает тип any и почему он опасен?
back: Отключает проверку типов для значения. Опасен тем, что «заразен» — тихо распространяется и сводит на нет пользу TS.
tags: [ts, any]
```

```card
front: Чем unknown лучше any для внешних данных?
back: unknown тоже «что угодно», но с ним ничего нельзя делать, пока не сузишь тип проверкой. Заставляет проверить данные перед использованием.
tags: [ts, unknown]
```

```card
front: Что означает тип never?
back: Значение, которого не может быть. Тип функции, которая всегда бросает исключение или не возвращает управление. Используется для проверки исчерпанности (модуль 04).
tags: [ts, never]
```

## Вывод типов и стиль

```card
front: Нужно ли аннотировать тип каждой переменной в TS?
back: Нет. TS выводит типы сам (inference). Аннотируй границы — параметры функций, возвращаемые значения, публичные API. Внутри доверяй выводу.
tags: [ts, inference, style]
```

## Запуск и настройка

```card
front: Три способа запустить .ts-файл в 2026?
back: Node 24 нативно (node app.ts, только стирает типы), tsx (на esbuild, для разработки), tsc (компиляция в .js). ts-node — легаси.
tags: [ts, tooling]
```

```card
front: Что делает команда npx tsc --noEmit?
back: "Только проверяет типы, не генерируя .js файлов. Линия обороны: запускают перед коммитом / в CI."
tags: [ts, tsc]
```

```card
front: "Зачем в tsconfig нужен strict: true?"
back: Включает строгие проверки, главная — strictNullChecks (обязательная обработка null/undefined). Без strict TS теряет половину пользы. Новый проект — всегда strict.
tags: [ts, tsconfig, strict]
```

## Утверждения типа и чтение ошибок

```card
front: Что делает x as T в рантайме?
back: Ничего. Утверждение типа — обещание компилятору, оно стирается. Это не приведение типа (как int(x) в Go) и не проверка (как v, ok := x.(T)).
tags: [ts, assertion]
```

```card
front: Что делает non-null assertion x! ?
back: Говорит компилятору «здесь точно не null/undefined» и снимает ошибку. Никакой проверки не выполняет — если соврал, упадёт рантайм.
tags: [ts, assertion]
```

```card
front: Что предпочесть вместо as/!, когда это возможно?
back: "Сужение типа проверкой: if (typeof x === 'string'), if (el), type guard. Проверка работает и в рантайме, а as/! — только мнение компилятора."
tags: [ts, assertion, narrowing]
```

```card
front: Как читать ошибку «Argument of type 'string' is not assignable to parameter of type 'number'»?
back: Слева от «assignable» — что ты дал (string), справа — куда даёшь (number). Источник не подходит цели.
tags: [ts, errors]
```

```card
front: Что означает «Object is possibly 'null'»?
back: Включён strictNullChecks, и значение может быть пустым — нужно обработать null/undefined перед использованием (проверка или ??).
tags: [ts, errors, strict]
```

```card
front: Кто в TS-проекте проверяет типы, а кто запускает код?
back: Проверяет tsc (--noEmit). Запускает Node (или tsx), который типы просто стирает. «Запустилось» не значит «типы сошлись».
tags: [ts, tooling]
```
