# Модуль 04 — Поток управления, `with` и ошибки

> В Go обработка ошибок выглядит как лестница `if err != nil { return err }`. В Elixir
> ошибки — это чаще всего **значения** (`{:error, reason}`), которые ты разбираешь
> сопоставлением, а для цепочек «сделай это, потом то, и останавливайся на первой неудаче»
> есть отдельная конструкция — `with`. Плюс есть и настоящие исключения (`raise`/`rescue`),
> но философия Elixir — «исключения для исключительного, ошибки для ожидаемого, а сломанный
> процесс — пусть падает».

## Цель

После модуля ты:

1. Выбираешь между `case`, `cond`, `if`/`unless` осознанно (что под какую задачу).
2. Свободно владеешь идиомой `{:ok, value}` / `{:error, reason}` как «ошибками-значениями».
3. Пишешь `with` для happy-path-цепочек и понимаешь его `else`-ветку — против лестницы
   `if err != nil`.
4. Различаешь три «выхода из нормы»: `raise`/`rescue` (исключения), `throw`/`catch`
   (нелокальный выход, редко), и падение процесса (модули 07–08).
5. Понимаешь философию: ошибка-значение vs исключение vs «let it crash» — когда что.
6. Знаешь грабли `with`: `WithClauseError` при узком `else` и то, что `else` не различает
   шаги (лечится тегированием шагов).
7. Умеешь объявить своё исключение через `defexception`.
