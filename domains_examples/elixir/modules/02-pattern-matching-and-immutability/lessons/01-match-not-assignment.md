# Урок 01 — `=` это не присваивание

Цель: довести до автоматизма мысль «`=` сопоставляет, а не присваивает», научиться читать
`MatchError` и правильно ставить пин `^`. Это самый важный навык курса — на нём стоит всё.

## Разогрев

- Что делает `=` в Elixir? (сопоставляет образец слева с данными справа, связывая переменные)
- Когда match падает? (литерал/форма слева не совпали со значением справа)
- Чем `^x = v` отличается от `x = v`? (пин сопоставляет со значением x; без пина — пере-связывает)

## Шаг 1. Угадай до запуска

Для каждой строки скажи себе: «свяжет переменную, вернёт значение, или MatchError?». Потом
проверь в `iex`.

```elixir
# (A)
a = 10
10 = a            # ?

# (B)
{:ok, n} = {:ok, 5}    # ?

# (C)
{:ok, n} = {:error, :nope}   # ?

# (D)
[x, y] = [1, 2, 3]     # ?

# (E)
[x | y] = [1, 2, 3]    # ?
```

Ответы: (A) ок, `10 = a` сопоставляет 10 со значением `a` (10), вернёт `10`. (B) ок, `n = 5`.
(C) ❌ `MatchError` — `:ok` ≠ `:error`. (D) ❌ `MatchError` — длины не совпали (2 против 3).
(E) ок — `x = 1`, `y = [2, 3]`.

Правило: **читай `=` как вопрос «совпадает ли форма?»**, а не как команду «положи значение».

## Шаг 2. Читаем MatchError

```elixir
iex> {:ok, value} = {:error, :timeout}
** (MatchError) no match of right hand side value: {:error, :timeout}
```

Расшифровка: «правая часть `{:error, :timeout}` не подошла под образец слева `{:ok, value}`».
Конкретно — `:ok` против `:error`. В Elixir это **штатный** способ сказать «данные не той
формы, которую я ждал». Не глуши его на каждом шагу `try/rescue` — часто правильнее дать
упасть (модуль 04 и «let it crash» в 07–08).

## Шаг 3. Пере-связывание ≠ мутация

```elixir
iex> x = 1
1
iex> remember = x      # remember держит 1
1
iex> x = 2             # пере-связали имя x на 2
2
iex> x
2
iex> remember          # старое значение цело!
1
```

`x = 2` не «изменило 1 на 2». Значение `1` неизменно; просто имя `x` теперь указывает на
новое значение `2`, а `remember` всё ещё держит старое. Это ключ к неизменяемости: меняются
**имена**, не **значения**.

## Шаг 4. Пин `^`: проверить, а не пере-связать

Голая переменная слева всегда связывается заново. Если надо сопоставить с её *текущим
значением* — пин.

```elixir
iex> mode = :read
:read
iex> mode = :write     # БЕЗ пина: просто пере-связали, никакой проверки
:write
iex> mode
:write
```

Упс — мы хотели проверить, что `mode` это `:read`, а вместо этого молча его перезаписали.
С пином:

```elixir
iex> mode = :read
:read
iex> ^mode = :read     # проверка: совпадает ли с текущим значением :read? да
:read
iex> ^mode = :write    # проверка: :read == :write? нет
** (MatchError) no match of right hand side value: :write
```

Где это кусается по-настоящему — в `case`/`receive`, когда хочешь «обработать только то, что
равно уже известной переменной»:

```elixir
known_pid = self()

receive do
  {^known_pid, msg} -> handle(msg)   # только сообщения от known_pid
  _other -> :ignore
end
```

Без `^` образец `{known_pid, msg}` пере-связал бы `known_pid` чем угодно из сообщения — и
фильтр исчез бы. Пин — твой способ сказать «это значение, а не дырка для связывания».

## Шаг 5. Match в аргументах функций (тизер модуля 03)

Сопоставление работает прямо в «голове» функции — это и есть диспетч по образцу:

```elixir
defmodule Resp do
  def handle({:ok, value}), do: "Готово: #{value}"
  def handle({:error, reason}), do: "Ошибка: #{reason}"
end

Resp.handle({:ok, 42})          # => "Готово: 42"
Resp.handle({:error, :timeout}) # => "Ошибка: timeout"
```

Две *clause* одной функции; Elixir выбирает ту, чей образец совпал. Это заменяет `switch` по
тегу из Go и будет центральной идиомой. Здесь же видно, зачем нужна конвенция `{:ok, _}` /
`{:error, _}`: она создана ровно под такой матч.

## Итог

`=` — это сопоставление: «совпадает ли форма?», а не «присвой». `MatchError` — нормальный
сигнал «не та форма», а не катастрофа. Пере-связывание меняет имя, не значение
(неизменяемость цела). Пин `^` превращает переменную в литерал образца — без него ты
пере-связываешь там, где хотел проверить. Дальше — экскурсия по контейнерам данных, которые
ты будешь деструктурировать этим самым сопоставлением.
