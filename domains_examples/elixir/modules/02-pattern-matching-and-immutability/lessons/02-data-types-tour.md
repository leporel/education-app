# Урок 02 — Экскурсия по типам данных

Цель: бегло ориентироваться в контейнерах Elixir (кортеж, список, мапа, keyword list,
строка), уметь их деструктурировать и выбирать правильный под задачу. Якорь — Go: где
аналог, где грабли.

## Шаг 1. Кортежи: фиксированная форма, тегированный результат

```elixir
point = {3, 4}
{x, y} = point          # x = 3, y = 4
elem(point, 0)          # => 3 (доступ по индексу, быстрый)
put_elem(point, 0, 99)  # => {99, 4} — НОВЫЙ кортеж, point не изменился
```

Главная идиома — тегированный результат вместо Go-шного `(value, err)`:

```elixir
def find(id) do
  if id == 1, do: {:ok, "Сэм"}, else: {:error, :not_found}
end

case find(1) do
  {:ok, name}      -> "Нашли: #{name}"
  {:error, reason} -> "Не нашли: #{reason}"
end
```

> **Go-контраст.** В Go: `name, err := find(1); if err != nil {...}`. В Elixir результат —
> **одно** значение-кортеж с тегом, которое ты разбираешь сопоставлением. Тег (`:ok`/`:error`)
> сразу говорит, какая ветка. Это конвенция всей стандартной библиотеки.

## Шаг 2. Списки: связные, рекурсия по голове и хвосту

```elixir
nums = [1, 2, 3]
[head | tail] = nums    # head = 1, tail = [2, 3]
[0 | nums]              # => [0, 1, 2, 3] — добавление в голову, дёшево (O(1))
nums ++ [4]             # => [1, 2, 3, 4] — в хвост, дорого (копирует левый список, O(n))
length(nums)            # O(n)! список связный, длина не хранится
Enum.at(nums, 2)        # => 3, но это O(n) — не делай так в цикле
```

Рекурсия по списку — каноничный паттерн (предтеча `Enum`):

```elixir
defmodule MyList do
  def sum([]), do: 0                      # база: пустой список
  def sum([head | tail]), do: head + sum(tail)   # шаг: голова + сумма хвоста
end

MyList.sum([1, 2, 3])   # => 6
```

> **Go-ловушка.** `[1,2,3]` — **не** slice. Нет O(1) индексации, `length` это O(n), доступ
> к произвольному элементу — O(n). Список — для последовательной обработки. Нужен «массив с
> индексом» — бери кортеж (фиксированный) или мапу (`%{0 => ..., 1 => ...}`), а на практике —
> просто `Enum`/`Stream` (модуль 05).

## Шаг 3. Мапы: ассоциативный контейнер

```elixir
user = %{name: "Сэм", age: 30}      # атомные ключи
user.name                            # => "Сэм" (точка — только для атомных ключей, строгая)
user[:age]                           # => 30 (скобки — мягкие, nil если нет)
user[:email]                         # => nil

updated = %{user | age: 31}          # обновить существующий ключ (упадёт, если ключа нет)
added = Map.put(user, :email, "x@y") # добавить/обновить любой ключ → НОВАЯ мапа
Map.get(user, :email, "—")           # => "—" (значение по умолчанию)

%{name: who} = user                  # деструктуризация: who = "Сэм" (лишние ключи ок)
```

Строковые ключи (например, из JSON) — через `=>`:

```elixir
json = %{"name" => "Сэм", "age" => 30}
json["name"]                         # => "Сэм" (точка тут НЕ работает — ключ не атом)
```

> **Go-параллель.** Мапа ≈ `map[K]V`, но неизменяемая (любое изменение — новая мапа) и с
> двумя стилями доступа: строгий `.key` (как обращение к полю структуры, падает) и мягкий
> `[key]` (как `v, ok := m[k]`, но без `ok` — просто `nil`). `%{m | k: v}` ≈ «обнови
> существующее поле»; `Map.put` ≈ «добавь или обнови».

## Шаг 4. Keyword lists: опции

```elixir
opts = [trim: true, limit: 5]        # == [{:trim, true}, {:limit, 5}]
opts[:trim]                          # => true
Keyword.get(opts, :limit, 10)        # => 5

String.split("a, b,  c", ",", trim: true)   # последний арг — keyword list опций
# => ["a", " b", "  c"]
```

Используются как **именованные опции** в конце списка аргументов — то, для чего в Go берут
variadic-функции или option-структуры. Порядок сохраняется, ключи могут повторяться (в
отличие от мапы), поэтому удобны для DSL (например, `Ecto`).

## Шаг 5. Строки и одна классическая ловушка

```elixir
s = "Привет"
s <> ", мир"            # => "Привет, мир" (конкатенация бинарей)
"длина: #{String.length(s)}"   # интерполяция (UTF-8 графемы)
byte_size(s)            # байты (UTF-8: кириллица по 2 байта)
String.upcase(s)        # => "ПРИВЕТ" — новая строка, s неизменна

# Ловушка charlist:
'abc'                   # это НЕ строка, а charlist — список кодпойнтов [97, 98, 99]
"abc" == 'abc'          # => false
is_list('abc')          # => true (!)
```

Если `IO.inspect` вдруг печатает `[104, 105]` вместо `"hi"` — ты случайно сделал charlist
(одинарные кавычки) или Erlang-функция вернула его. Конвертация: `to_string('abc')` /
`String.to_charlist("abc")`. По умолчанию — **всегда двойные кавычки**.

## Итог

Пять контейнеров, каждый под свою задачу: **кортеж** — фиксированная форма и тегированный
результат `{:ok, _}`; **список** — связный, для последовательной обработки и рекурсии (не
массив!); **мапа** — ассоциативный доступ со строгим `.key` и мягким `[key]`; **keyword
list** — опции в хвосте аргументов; **строки** — двойные кавычки (binary), и берегись
charlist в одинарных. Всё это ты разбираешь одним и тем же сопоставлением из урока 01.
Дальше — функции, где этот матч становится диспетчером.
