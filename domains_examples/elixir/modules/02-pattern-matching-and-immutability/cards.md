# Карточки

## Match operator

```card
front: Что на самом деле делает `=` в Elixir?
back: Это оператор сопоставления с образцом (match), а не присваивание. Пытается сделать левый образец равным правому значению по форме, связывая встреченные слева переменные. Если форма/литерал не совпали — MatchError.
tags: [elixir, match]
```

```card
front: Почему `5 = x` (где x = 5) легально, а `6 = x` — нет?
back: Слева образец-литерал. `5 = x` сопоставляет 5 со значением x (5) — совпало, ок. `6 = x` сопоставляет 6 с 5 — не совпало, MatchError. Это не присваивание в литерал (как было бы в Go), а проверка совпадения.
tags: [elixir, match]
```

```card
front: Что значит `[h | t] = [1, 2, 3]`?
back: "Образец «голова | хвост»: h = 1 (первый элемент), t = [2, 3] (остаток списка). Основа рекурсии по спискам. Списки — связные, поэтому это дёшево."
tags: [elixir, list, match]
```

```card
front: Почему MatchError — это хорошо?
back: Если данные пришли не в ожидаемой форме, ты узнаёшь немедленно и в точке несоответствия, а не «тихо неправильно» три функции спустя. Это fail-fast, фундамент «let it crash».
tags: [elixir, match, fail-fast]
```

## Пин и пере-связывание

```card
front: Что делает пин-оператор `^`?
back: Говорит «не связывай переменную заново, а сопоставь с её ТЕКУЩИМ значением». `^x = v` совпадёт, только если v == x, иначе MatchError. Без пина `x = v` просто пере-связало бы x на v.
tags: [elixir, pin]
```

```card
front: "`x = 1; x = 2` — это мутация значения?"
back: "Нет. Это пере-связывание имени: значение 1 не изменилось, просто x теперь указывает на 2. Кто держал старое значение — по-прежнему видит 1. Данные неизменяемы, имена — пере-связываемы."
tags: [elixir, rebind, immutability]
```

```card
front: Зачем `_` и `_name` в образцах?
back: "`_` — wildcard: совпадает с чем угодно, значение не нужно. `_name` — связывается, но компилятор не ругается на неиспользование; служит самодокументированием. Оба отбрасывают/игнорируют части данных при деструктуризации."
tags: [elixir, wildcard]
```

## Типы данных

```card
front: Что такое atom и где он используется?
back: "Константа, чьё значение — её имя (`:ok`, `:error`, `:pending`). Дёшев, мгновенно сравнивается. Метки, статусы, ключи мап. true/false/nil — тоже атомы. ВАЖНО: атомы не собираются GC — не создавай из недоверенного ввода (атом-исчерпание)."
tags: [elixir, atom]
```

```card
front: "Кортеж vs список: когда что?"
back: Кортеж {} — фиксированный размер, лежит подряд, быстрый доступ по индексу, дорогая «вставка»; идиома {:ok, val}/{:error, reason}. Список [] — связный, дёшево добавить в голову [x|list], доступ по индексу O(n); для последовательной обработки и рекурсии.
tags: [elixir, tuple, list]
```

```card
front: Чем `map.key` отличается от `map[:key]`?
back: "map.key — строгий доступ: работает только для атомных ключей и падает KeyError, если ключа нет. map[:key] — мягкий: любой тип ключа, возвращает nil при отсутствии. Строгий = fail-fast, мягкий = nil-терпимость."
tags: [elixir, map]
```

```card
front: Что такое keyword list и где его узнаёшь?
back: "Список кортежей {atom, value} с сахаром: [a: 1, b: 2] == [{:a,1},{:b,2}]. Сохраняет порядок, допускает повторы ключей. Идиома для опций функций: String.split(s, \",\", trim: true) — последний аргумент."
tags: [elixir, keyword-list]
```

```card
front: "\"строка\" vs 'charlist' — в чём разница и что брать?"
back: "\"двойные\" — binary (UTF-8 байты), основной строковый тип, бери его. 'одинарные' — charlist, список кодпойнтов, наследие Erlang для редких API. \"a\" != 'a'. Перепутать = строка вдруг печатается как список чисел."
tags: [elixir, string, charlist]
```

## Неизменяемость

```card
front: Почему неизменяемость не делает Elixir медленным от копирования?
back: "Structural sharing: BEAM переиспользует неизменные части данных. `[x | big_list]` не копирует big_list — новый список ссылается на старый хвост. Это безопасно именно потому, что старый хвост никто не изменит."
tags: [elixir, immutability, performance]
```

```card
front: Как неизменяемость связана с конкурентностью?
back: Если данные нельзя менять на месте, два процесса не могут устроить за них гонку — каждый работает со своей версией. Проблема, ради которой в Go нужны мьютексы и -race, здесь исчезает как класс. Неизменяемость — фундамент share-nothing-модели BEAM.
tags: [elixir, immutability, concurrency]
```

## Строки, бинарники, сигилы

```card
front: "Как сопоставить строку с префиксом и какое здесь ограничение?"
back: "Образцом с конкатенацией: \"https://\" <> rest = url, или в голове функции: def scheme(\"http://\" <> _), do: :http. Ограничение: слева от <> должен стоять ЛИТЕРАЛ известной длины — компилятор должен знать, сколько байт отрезать. Переменная слева (prefix <> rest) не скомпилируется."
tags: [elixir, string, match]
```

```card
front: "Что делает образец <<first, rest::binary>> = \"hello\"?"
back: "Разбирает binary: first = 104 (байт первой буквы), rest = \"ello\". Строка в Elixir — это binary, поэтому к ней применим полный синтаксис двоичного сопоставления (<<a::16, b::16>> и т.п.). Именно так на BEAM парсят бинарные протоколы — образцами, а не арифметикой смещений."
tags: [elixir, binary, match]
```

```card
front: "Как в современном Elixir пишут charlist и чем он отличается от строки?"
back: "Сигилом ~c\"abc\"; старая запись одинарными кавычками устарела и даёт предупреждение. Charlist — список кодпойнтов (is_list → true), нужен для некоторых Erlang-API; рабочий строковый тип — binary \"abc\". \"a\" == ~c\"a\" это false. Конвертация: to_string/1 и String.to_charlist/1."
tags: [elixir, charlist, sigil]
```

```card
front: "Что означают сигилы ~s, ~w, ~r, ~D?"
back: "~s(...) — строка без экранирования кавычек; ~w(a b c) — список слов [\"a\",\"b\",\"c\"] (с модификатором a — атомы); ~r/regex/ — регулярное выражение; ~D[2026-09-08] — Date (ещё ~T время, ~U DateTime). Заглавная буква (~S, ~W) отключает интерполяцию."
tags: [elixir, sigil]
```

## Сравнения

```card
front: "== или === : в чём разница?"
back: "== сравнивает значения с приведением чисел: 1 == 1.0 → true. === строгое: различает целое и дробное, 1 === 1.0 → false. Для большинства проверок хватает ==; === нужен, когда важен именно тип числа."
tags: [elixir, comparison]
```

```card
front: "and/or/not против &&/||/! — когда что?"
back: "and/or/not строгие: требуют настоящий булев слева, иначе BadBooleanError; только они разрешены в guards. &&/||/! мягкие (truthy/falsy: ложь лишь false и nil) и возвращают ОДИН ИЗ ОПЕРАНДОВ, а не булево — отсюда идиома name = input || \"гость\"."
tags: [elixir, boolean]
```

```card
front: "Почему 1 < :atom не ошибка, а true?"
back: "У BEAM есть тотальный порядок термов, чтобы любые значения можно было сравнить и отсортировать: number < atom < reference < function < port < pid < tuple < map < list < bitstring. Поэтому Enum.sort на разнородном списке не падает. Обратная сторона: случайное сравнение разных типов компилятор не поймает."
tags: [elixir, term-ordering]
```

## Вложенные структуры

```card
front: "Как обновить значение внутри вложенной мапы, не собирая её заново?"
back: "Семейством get_in/put_in/update_in: put_in(user, [:address, :city], \"Питер\") вернёт НОВУЮ мапу с изменённым полем, исходная цела. get_in читает по пути, update_in применяет функцию к значению по пути."
tags: [elixir, map, nested]
```
