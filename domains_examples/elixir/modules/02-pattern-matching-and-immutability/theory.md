# Сопоставление с образцом и неизменяемость

## `=` это не присваивание

Главный сюрприз Elixir прячется за самым невинным символом. В Go `x = 5` — присваивание:
«положи 5 в ячейку x». В Elixir `=` — это **оператор сопоставления с образцом** (match
operator). Он пытается сделать левую и правую части **равными по форме** и по ходу
**связывает** переменные, встреченные слева.

```elixir
x = 5        # образец слева — голая переменная x. Она связывается с 5.
5 = x        # ЛЕГАЛЬНО! Слева 5, справа x (=5). Формы совпали → ok, вернётся 5.
6 = x        # ❌ (MatchError) no match of right hand side value: 5
```

`5 = x` в Go было бы синтаксической ошибкой («нельзя присвоить в литерал»). В Elixir это
осмысленное сопоставление: «совпадает ли левый образец `5` с правым значением `5`?». Да —
match успешен. `6 = x`? Нет — `MatchError`, потому что 6 ≠ 5.

Образец слева может быть сложным, и тогда `=` **разбирает** структуру справа:

```elixir
{:ok, value} = {:ok, 42}     # связывает value = 42
[first, second] = [1, 2]     # first = 1, second = 2
%{name: n} = %{name: "Сэм", age: 30}   # n = "Сэм" (лишние ключи справа — не мешают)
```

Это и есть **деструктуризация** — но не как косметический сахар Go (`a, b := f()`), а как
фундаментальная операция языка. Из неё растут аргументы функций, `case`, `receive` — везде
одно и то же сопоставление.

> **Якорь Go.** Ближайшее в Go — множественное присваивание `a, b := f()` и type switch.
> Но в Go это разные синтаксисы для разных мест. В Elixir это **одна** идея — pattern
> matching — применённая единообразно везде. Выучил её один раз — понял половину языка.

## Когда match связывает, а когда падает

- Если в образце встречается **новая переменная** — она связывается со значением.
- Если в образце **константа/литерал** (`5`, `:ok`, `"x"`) — она должна *совпасть*, иначе
  `MatchError`.
- Если структура слева не подходит к данным справа по форме — `MatchError`.

```elixir
{:ok, v} = {:error, :timeout}   # ❌ MatchError: :ok ≠ :error
[a, b] = [1, 2, 3]              # ❌ MatchError: длины списков разные
[a | rest] = [1, 2, 3]          # ✅ a = 1, rest = [2, 3]  (| — «голова | хвост»)
```

`MatchError` — это **фича, а не баг**: если данные пришли не в той форме, ты узнаёшь об этом
немедленно и громко, в точке несоответствия, а не «тихо неправильно» тремя функциями позже.
Это и есть «fail fast», на котором стоит «let it crash».

## Переменные можно пере-связывать (rebind)

```elixir
x = 1
x = 2        # ок: x просто заново связывается с 2 (это не мутация значения!)
```

Выглядит как мутация, но это не она. Старое значение `1` не изменилось — просто имя `x`
теперь указывает на новое значение `2`. Любые ссылки, которые держали старое `x`, видят
по-прежнему `1`. Данные неизменяемы; **имена** — пере-связываемы.

## Пин-оператор `^`: «не связывай, сопоставь со значением»

Раз голая переменная слева всегда связывается заново, как сказать «сопоставь с *текущим
значением* этой переменной»? Поставить **пин** `^`:

```elixir
expected = 42
^expected = 42      # ок: сопоставляем с ЗНАЧЕНИЕМ expected (42), не пере-связываем
^expected = 43      # ❌ MatchError: 42 ≠ 43
```

Без пина `expected = 43` просто пере-связало бы `expected` на 43 и прошло. Пин — это «заморозь
переменную как литерал в образце». Особенно важно в `case`/`receive` и при матче по уже
известным значениям. Забыть `^` (и случайно пере-связать вместо проверки) — классическая
ошибка новичка.

```elixir
# Хочу обработать только сообщения от известного pid:
^known_pid = sender    # проверка, что sender именно known_pid; иначе MatchError
```

## `_` и именованные «мусорные» переменные

`_` — анонимный wildcard: «совпадёт с чем угодно, значение мне не нужно».

```elixir
{_, status} = {:ignore_me, :ok}    # status = :ok, первый элемент отброшен
[_head | tail] = [1, 2, 3]         # tail = [2, 3]; _head намекает, что не используем
```

`_name` (с подчёркиванием в начале) связывается, но компилятор не предупредит, что
переменная не используется. Полезно для самодокументирования.

## Экскурсия по типам данных

### Atoms (`:foo`)

Константа, чьё значение — её собственное имя. Дёшева, сравнивается мгновенно. Используется
как метки/статусы/ключи: `:ok`, `:error`, `:infinity`. `true`, `false`, `nil` — тоже атомы
(`:true` и т.д.). Имена модулей — атомы под капотом (`String` ≡ `:"Elixir.String"`).

> **Go-параллель.** Атомы — как строковые/iota-константы-метки, но без объявления:
> `:pending` существует, как только ты его написал. Цена: атомы **не собираются GC** —
> поэтому нельзя плодить их из недоверенного ввода (атом-исчерпание роняет узел). Не делай
> `String.to_atom(user_input)`; используй `String.to_existing_atom/1`.

### Числа

`42` (integer, произвольной точности — big integers из коробки), `3.14` (float, 64-бит).
`div(7, 2)` и `rem(7, 2)` для целочисленного деления; `/` всегда даёт float.

### Кортежи `{}`

Фиксированный по размеру, упорядоченный контейнер, лежит в памяти подряд: быстрый доступ по
индексу (`elem(t, 0)`), дорогая «вставка» (копируется весь). Идиома — **возвращать
результат тегом**: `{:ok, value}` / `{:error, reason}`. Это конвенция вместо `(value, err)`
из Go.

### Списки `[]`

**Связный список** (не массив!). Дёшево добавить в голову (`[x | list]`), дорого — в хвост
или взять по индексу (O(n)). Образец `[head | tail]` разбирает голову и хвост — основа
рекурсии по спискам.

```elixir
[1 | [2, 3]]        # => [1, 2, 3]
[h | t] = [1, 2, 3] # h = 1, t = [2, 3]
```

> **Go-ловушка.** Список Elixir — **не** `slice`. Индексация O(n), а не O(1). Для
> «массива по индексу» бери кортеж или мапу; список — для последовательной обработки.

### Мапы `%{}`

Ассоциативный контейнер ключ→значение, ближайший аналог `map` в Go. Ключи любого типа.

```elixir
m = %{"name" => "Сэм", "age" => 30}     # строковые ключи: синтаксис key => value
m2 = %{name: "Сэм", age: 30}            # атомные ключи: сахар name: value (= %{:name => ...})
m2.name                                  # => "Сэм"  (точка работает ТОЛЬКО для атомных ключей)
m2[:name]                                # => "Сэм"  (скобки — для любых ключей, nil если нет)
Map.put(m2, :age, 31)                    # => НОВАЯ мапа; m2 не изменилась
%{m2 | age: 31}                          # обновить СУЩЕСТВУЮЩИЙ ключ (упадёт, если ключа нет)
```

`map.key` падает (`KeyError`), если ключа нет — это «строгий» доступ. `map[:key]` мягкий —
вернёт `nil`. Разница важна и отражает стиль «fail fast против nil-терпимости».

Для **вложенных** структур есть отдельное семейство функций, чтобы не собирать мапу заново
руками:

```elixir
user = %{name: "Сэм", address: %{city: "Москва", zip: "101000"}}

get_in(user, [:address, :city])                  # => "Москва"
put_in(user, [:address, :city], "Питер")         # => новая мапа с изменённым городом
update_in(user, [:address, :zip], &String.slice(&1, 0..2))   # применить функцию к значению
```

Это ровно то, что в Go делается цепочкой `u.Address.City = ...` — только результат новый, а
исходные данные целы.

### Keyword lists

Список кортежей `{atom, value}` с сахаром: `[a: 1, b: 2]` ≡ `[{:a, 1}, {:b, 2}]`. Допускает
повторные ключи и хранит порядок. Идиома для **опций функций**: `String.split(s, ",", trim: true)`
— последний аргумент это keyword list. `# Go: ~ variadic-опции / option structs`.

### Бинарные строки и charlists

`"привет"` — это **binary** (UTF-8 байты), основной строковый тип. `<>` конкатенирует,
`#{}` интерполирует. А **charlist** — список кодпойнтов, наследие Erlang; нужен редко, для
некоторых Erlang-API. В современном Elixir его записывают сигилом `~c"привет"`, а старая
запись одинарными кавычками (`'привет'`) объявлена устаревшей — компилятор предупредит.
Перепутать типы — классическая боль: `"a" == ~c"a"` это `false`, `is_list(~c"a")` — `true`,
а в выводе `iex`/`IO.inspect` charlist показывается как `~c"a"` (и как список чисел вроде
`[104, 0]`, если среди кодов есть непечатаемые). Конвертация в обе стороны:
`to_string(~c"abc")` и `String.to_charlist("abc")`.

### Матч по строкам: `"prefix" <> rest`

Строки тоже сопоставляются с образцом — об этом часто забывают, а идиома встречается повсюду
(например, в капстоуне модуля 09):

```elixir
"https://" <> rest = "https://elixir-lang.org"   # rest = "elixir-lang.org"

def scheme("http://" <> _), do: :http
def scheme("https://" <> _), do: :https
def scheme(_), do: :unknown
```

Ограничение одно: **слева от `<>` должен стоять литерал известной длины** — компилятор должен
знать, сколько байт отрезать. `prefix <> rest = str`, где `prefix` — переменная, не
скомпилируется.

Под капотом строка это binary, и для неё есть полный синтаксис двоичного сопоставления:

```elixir
<<first_byte, rest::binary>> = "hello"   # first_byte = 104, rest = "ello"
<<a::16, b::16>> = <<1, 2, 3, 4>>        # разбор бинарных данных по битам и байтам
```

Вот за это Erlang и Elixir любят в телекоме и парсинге протоколов: разбор бинарного формата
пишется образцами, а не арифметикой смещений.

### Сигилы: `~s`, `~c`, `~w`, `~r`, `~D`

Сигил — короткая запись литерала: тильда, буква, разделители. Полезный минимум:

```elixir
~s(строка с "кавычками" внутри)   # binary — не надо экранировать кавычки
~c"charlist"                       # charlist (современная запись вместо 'charlist')
~w(one two three)                  # => ["one", "two", "three"] — список слов
~w(one two three)a                 # => [:one, :two, :three] — то же, но атомами
~r/^\d+$/                          # регулярное выражение
~D[2026-09-08]                     # Date (а также ~T[12:00:00], ~U[2026-09-08 12:00:00Z])
```

Заглавная буква (`~S`, `~W`) отключает интерполяцию и экранирование. `~w` будет попадаться в
примерах постоянно — считай его «списком слов без кавычек и запятых».

## Сравнения: `==` vs `===`, `and` vs `&&`, и порядок термов

Три вещи, которые Go-разработчик обычно обнаруживает случайно и не сразу.

**1. Два равенства.** `==` сравнивает значения с приведением чисел, `===` — строго, различая
целое и дробное:

```elixir
1 == 1.0     # true
1 === 1.0    # false
```

**2. Два набора булевых операторов.**

- `and` / `or` / `not` — **строгие**: требуют слева именно `true`/`false`, иначе
  `BadBooleanError`. Их берут, когда тип точно булев (и только они разрешены в guards).
- `&&` / `||` / `!` — **мягкие**, работают по truthy/falsy: ложь это только `false` и `nil`,
  всё остальное истина (включая `0` и `""`). Возвращают они не булево, а один из операндов —
  отсюда идиома значения по умолчанию: `name = input || "гость"`.

**3. Термы сравнимы всегда — и это не ошибка.** В Elixir можно написать `1 < :atom` и
получить `true`. Не потому, что это осмысленно, а потому, что у BEAM есть **тотальный порядок
термов**: любые два значения сравнимы, чтобы всё можно было отсортировать и сложить в дерево.

```text
number < atom < reference < function < port < pid < tuple < map < list < bitstring
```

Практические следствия: `Enum.sort/1` на разнородном списке не упадёт, а просто разложит
значения в этом порядке; `nil` — атом, поэтому он «больше» любого числа. Компилятор Go такое
сравнение просто не пропустил бы — здесь оно легально, и это цена динамики: случайное
сравнение разных типов не поймается, а тихо даст ответ.

## Неизменяемость: данные не меняются на месте

Любая «модификация» возвращает **новую** структуру; исходная остаётся как была.

```elixir
list = [1, 2, 3]
List.delete_at(list, 0)   # => [2, 3]
list                      # => [1, 2, 3]  — НЕ изменился
```

«А не дорого ли копировать всё подряд?» Нет: благодаря неизменяемости BEAM **переиспользует
неизменные части** (structural sharing). Добавление в голову списка `[x | list]` не копирует
`list` — новый список просто ссылается на старый хвост. Это безопасно именно потому, что
старый хвост никто не сможет изменить.

> **Зачем это вообще.** Неизменяемость — фундамент share-nothing-конкурентности (модули
> 07–08). Если данные нельзя поменять на месте, два процесса не могут устроить гонку за
> них: каждый работает со своей копией/версией. То, ради чего в Go нужны мьютексы и
> `-race`, здесь исчезает как класс проблемы. Цена — нужно перестроить мышление с «меняю
> поле структуры» на «строю новую структуру из старой».

## Глоссарий модуля

- **Match operator (`=`)** — оператор сопоставления с образцом, а не присваивание.
- **Образец (pattern)** — то, что слева от `=`: форма, с которой сверяют данные и по ходу
  связывают переменные.
- **Связывание (binding)** — присоединение имени к значению при удачном сопоставлении.
- **Пере-связывание (rebinding)** — повторное `x = ...`: новое значение у имени, старое
  значение цело.
- **Пин (`^x`)** — «сопоставь с текущим значением `x`», а не связывай заново.
- **Wildcard (`_`)** — образец «что угодно, значение не нужно»; `_name` — то же, но с именем
  для читателя.
- **`MatchError`** — данные не подошли под образец; штатный fail-fast.
- **Деструктуризация** — разбор составного значения на части образцом.
- **Атом** — константа, равная своему имени (`:ok`); не собирается GC, поэтому не создаётся из
  недоверенного ввода.
- **Кортеж (`{}`)** — фиксированный набор элементов подряд в памяти; идиома `{:ok, value}`.
- **Список (`[]`)** — связный список; `[head | tail]` — его канонический образец.
- **Мапа (`%{}`)** — ассоциативный контейнер; `map.key` строгий, `map[:key]` мягкий.
- **Keyword list** — список пар `{atom, value}` с сахаром `[trim: true]`; опции функций.
- **Binary** — двоичные данные, в том числе строки в UTF-8; сопоставляются через `<<...>>`.
- **Charlist** — список кодпойнтов, наследие Erlang; современная запись `~c"abc"`.
- **Сигил** — короткая запись литерала: `~s`, `~c`, `~w`, `~r`, `~D`.
- **Порядок термов (term ordering)** — тотальный порядок сравнения любых значений:
  number < atom < reference < function < port < pid < tuple < map < list < bitstring.
- **Structural sharing** — переиспользование неизменных частей данных вместо копирования.

## Типичные ошибки и заблуждения

- **`=` это присваивание.** Нет, это сопоставление. `5 = x` легально; `{:ok, v} = {:error, _}`
  падает `MatchError`. Думай «совпадает ли форма?», а не «куда положить значение».
- **Забыть пин `^`.** `expected = actual` *пере-связывает* `expected`, а не проверяет
  равенство. Чтобы сопоставить со значением переменной — `^expected = actual`.
- **Считать список массивом.** Список — связный, индексация и доступ к хвосту O(n). Для
  индексируемого доступа бери кортеж/мапу.
- **`map.key` vs `map[:key]`.** Точка строгая (падает `KeyError`, и только для атомных
  ключей), скобки мягкие (вернут `nil`). Путать = ловить то падения, то тихие `nil`.
- **Плодить атомы из ввода.** Атомы не собираются GC; `String.to_atom(user_input)` — путь к
  атом-исчерпанию и падению узла. Бери `to_existing_atom` или вообще строки.
- **Путать `"строку"` и `'charlist'`.** Двойные кавычки — binary (рабочий строковый тип),
  одинарные — список кодпойнтов из Erlang. `"a" != 'a'`. По умолчанию всегда двойные.
- **«Неизменяемость = всё медленно копируется».** Нет: structural sharing переиспользует
  неизменные части. `[x | big_list]` не копирует `big_list`.
- **«Пере-связывание `x = 2` — это мутация».** Нет: старое значение цело, просто имя теперь
  указывает на новое. Любой, кто держал старое значение, видит старое.
- **Писать charlist одинарными кавычками.** `'abc'` устарело и вызывает предупреждение;
  современная запись — `~c"abc"`. Рабочий строковый тип по-прежнему `"abc"` (binary).
- **«Сравнение разных типов упадёт».** Нет: у BEAM тотальный порядок термов, `1 < :atom`
  вернёт `true`. Компилятор не поможет — следи за типами сам.
- **Путать `and` и `&&`.** `and/or/not` строгие (нужен настоящий булев слева, иначе
  `BadBooleanError`) и только они допустимы в guards; `&&/||/!` работают по truthy/falsy и
  возвращают операнд, а не булево (`nil || "гость"` → `"гость"`).
- **Ждать, что `prefix <> rest = str` сработает с переменной слева.** В образце слева от `<>`
  обязан быть литерал известной длины: `"https://" <> rest` — можно, `prefix <> rest` — нет.
