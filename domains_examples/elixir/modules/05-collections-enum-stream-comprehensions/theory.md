# Коллекции: Enum, Stream, comprehensions

## `Enum`: твой цикл `for`

`Enum` — модуль функций над любым **перечислимым** (списком, мапой, диапазоном — всем, что
реализует протокол `Enumerable`). Это замена ручных циклов: вместо мутации счётчика и
аккумулятора ты описываешь *что* сделать с коллекцией.

```elixir
Enum.map([1, 2, 3], &(&1 * 2))            # => [2, 4, 6]
Enum.filter([1, 2, 3, 4], &(rem(&1,2)==0))# => [2, 4]
Enum.reduce([1, 2, 3], 0, &(&1 + &2))     # => 6  (свёртка с аккумулятором)
Enum.sum([1, 2, 3])                        # => 6
Enum.sort([3, 1, 2])                       # => [1, 2, 3]
Enum.group_by(["aa","b","cc"], &String.length/1)  # => %{1 => ["b"], 2 => ["aa","cc"]}
Enum.into(%{a: 1}, %{b: 2})                # вливание одной коллекции в другую
```

Пайплайн читается как конвейер (модуль 03):

```elixir
[1, 2, 3, 4, 5, 6]
|> Enum.filter(&(rem(&1, 2) == 0))   # [2, 4, 6]
|> Enum.map(&(&1 * &1))              # [4, 16, 36]
|> Enum.sum()                        # 56
```

> **Go-контраст.** В Go этот пайплайн — цикл `for` с `if` и накоплением в срез/переменную. В
> Elixir — декларативная цепочка. Минус (важный!): **каждый шаг `Enum` создаёт новый
> полный список**. `filter` материализует `[2,4,6]`, потом `map` материализует `[4,16,36]`.
> На маленьких данных не важно, на больших — лишние проходы и аллокации. Тут на сцену
> выходит `Stream`.

## `reduce` — мать всех свёрток

`map`, `filter`, `sum`, `count` — частные случаи `reduce`. Он берёт коллекцию, начальный
аккумулятор и функцию `(элемент, acc) -> новый_acc`:

```elixir
Enum.reduce([1, 2, 3, 4], 0, fn x, acc -> acc + x end)        # => 10
Enum.reduce(["a","b","c"], "", fn x, acc -> acc <> x end)     # => "abc"
# посчитать частоты:
Enum.reduce(~w(a b a c a), %{}, fn w, acc ->
  Map.update(acc, w, 1, &(&1 + 1))
end)                                                          # => %{"a"=>3,"b"=>1,"c"=>1}
```

Если знаешь `reduce` — поймёшь, как устроено всё остальное. Это та же рекурсия с
аккумулятором из модуля 03, обобщённая.

## Шпаргалка: `Enum` на каждый день

Функций в `Enum` больше сотни; вот те, которыми пишется 90% кода. Все принимают перечислимое
первым аргументом (data-first, модуль 03) и возвращают новые данные.

| Задача | Функция | Пример |
| --- | --- | --- |
| преобразовать каждый | `map/2` | `Enum.map(xs, &(&1 * 2))` |
| оставить/выкинуть подходящие | `filter/2`, `reject/2` | `Enum.filter(xs, & &1.active)` |
| преобразовать и «расплющить» | `flat_map/2` | `Enum.flat_map(rows, &String.split/1)` |
| свернуть | `reduce/3` | `Enum.reduce(xs, 0, fn x, acc -> acc + x end)` |
| свернуть с ранней остановкой | `reduce_while/3` | см. ниже |
| посчитать | `count/1,2`, `sum/1`, `frequencies/1` | `Enum.frequencies(~w(a b a))` |
| найти / проверить | `find/2`, `any?/2`, `all?/2`, `member?/2` | `Enum.find(xs, &(&1.id == 5))` |
| упорядочить | `sort/1,2`, `sort_by/2`, `min_by/2`, `max_by/2` | `Enum.sort_by(xs, & &1.age)` |
| сгруппировать / разделить | `group_by/2`, `split_with/2` | `Enum.group_by(xs, & &1.status)` |
| убрать повторы | `uniq/1`, `uniq_by/2` | `Enum.uniq_by(xs, & &1.email)` |
| нарезать | `chunk_every/2`, `take/2`, `drop/2` | `Enum.chunk_every(xs, 100)` |
| склеить | `zip/2`, `with_index/1`, `join/2` | `Enum.zip(names, ages)` |
| побочный эффект | `each/2` | `Enum.each(xs, &IO.puts/1)` |
| собрать в другой контейнер | `into/2` | `Enum.into(pairs, %{})` |

Два уточнения, которые экономят нервы.

**`each` против `map`.** `each` возвращает `:ok` и нужен **только** ради побочного эффекта
(печать, отправка сообщения). Если нужен результат — это `map`. Гонять `map` ради эффекта и
выбрасывать результат — расточительно и сбивает читателя с толку.

**`reduce_while` — свёртка с досрочным выходом.** `reduce` всегда проходит всю коллекцию.
Когда надо остановиться раньше (ответ найден, бюджет кончился), берут `reduce_while`: на
каждом шаге он возвращает `{:cont, acc}` (идём дальше) или `{:halt, acc}` (стоп).

```elixir
# суммируем, пока сумма не превысит 100
Enum.reduce_while(1..1000, 0, fn x, acc ->
  if acc + x > 100, do: {:halt, acc}, else: {:cont, acc + x}
end)
# => 91   (1+2+...+13 = 91; следующее число дало бы 105)
```

В Go это `break` внутри цикла; здесь выход помечается тегом — многословнее, зато видно в коде.

## `Stream`: ленивый `Enum`

`Stream` предоставляет **те же** операции (`map`, `filter`, ...), но **ничего не вычисляет**,
пока результат не понадобится. Он строит «рецепт» и прогоняет каждый элемент через всю
цепочку по одному, не материализуя промежуточные списки. Вычисление запускает только
терминальная операция `Enum` (`Enum.to_list`, `Enum.take`, `Enum.sum`...).

```elixir
1..1_000_000
|> Stream.filter(&(rem(&1, 2) == 0))
|> Stream.map(&(&1 * &1))
|> Enum.take(3)                       # => [4, 16, 36]
```

Здесь `Stream` обработает ровно столько элементов, сколько нужно для трёх результатов — не
миллион. С `Enum` тот же код сначала построил бы список из 500 000 чётных, потом 500 000
квадратов, и только потом взял три. Разница — между «секунда и мегабайты» и «мгновенно».

`Stream` ещё умеет **бесконечные** источники:

```elixir
Stream.iterate(1, &(&1 * 2)) |> Enum.take(5)   # => [1, 2, 4, 8, 16]
Stream.cycle([:a, :b]) |> Enum.take(5)         # => [:a, :b, :a, :b, :a]
File.stream!("big.log")                        # читает файл построчно, лениво
|> Stream.filter(&String.contains?(&1, "ERROR"))
|> Enum.count()
```

> **Правило выбора.** `Enum` — по умолчанию (просто, читаемо, для обычных коллекций).
> `Stream` — когда источник большой/бесконечный, или когда хочешь избежать промежуточных
> списков в длинной цепочке, или когда нужна ранняя остановка (`take`). Ленивость не
> бесплатна по константе — на крошечных данных `Enum` даже быстрее. Не «всегда Stream».

> **Go-параллель.** `Stream` похож по духу на конвейер горутин/каналов или на ленивые
> итераторы из других языков: данные текут по одному, обрабатываются на лету. Но без
> конкурентности — это просто ленивость в одном процессе. (Параллельную обработку даёт
> `Task.async_stream`, см. модули 08–09.)

## Comprehensions: `for`

`for` в Elixir — это **не** цикл со счётчиком, а **comprehension**: генераторы + фильтры →
новая коллекция. Удобно, когда есть вложенность или несколько источников.

```elixir
for x <- [1, 2, 3], do: x * x                       # => [1, 4, 9]
for x <- 1..3, y <- 1..3, do: {x, y}                # декартово произведение (9 пар)
for x <- 1..10, rem(x, 2) == 0, do: x               # фильтр: => [2, 4, 6, 8, 10]
```

`x <- enum` — генератор (можно несколько, они вкладываются). Голые выражения — фильтры
(оставляют элемент, если истинно). По умолчанию результат — список, но `:into` меняет
контейнер, а `:reduce` превращает в свёртку:

```elixir
for {k, v} <- %{a: 1, b: 2}, into: %{}, do: {k, v * 10}   # => %{a: 10, b: 20}
for c <- ~w(a b a c), reduce: %{} do
  acc -> Map.update(acc, c, 1, &(&1 + 1))
end                                                       # => %{"a"=>2,"b"=>1,"c"=>1}
```

В генераторе можно ещё и матчить с фильтрацией: несовпавшие элементы просто отбрасываются
(не падают!):

```elixir
for {:ok, v} <- [{:ok, 1}, {:error, :x}, {:ok, 3}], do: v   # => [1, 3]
```

Comprehension — это сахар; часто тот же результат пишут через `Enum`. Бери `for`, когда есть
вложенные генераторы или матч-фильтрация делает код яснее.

## Контейнеры: что когда

- **List** `[]` — последовательная обработка, рекурсия; не для индексированного доступа.
- **Map** `%{}` — ассоциативный доступ ключ→значение (модуль 02). `Map.update/4`, `Map.merge/2`.
- **MapSet** — множество уникальных значений: `MapSet.new`, `MapSet.member?`, объединение/
  пересечение. Аналог `map[T]struct{}` из Go, но как полноценный тип.
- **Keyword list** — опции (модуль 02), упорядочены, допускают дубли ключей.
- **Range** `1..100` (и `1..100//2` с шагом) — ленивое перечисление чисел, перечислимо `Enum`/`Stream`.

`Enum.into/2` и `:into` в comprehension — мост между контейнерами (список → мапа, поток →
множество и т.д.), потому что все они — `Enumerable`/`Collectable`.

## Глоссарий модуля

- **`Enumerable`** — протокол «по мне можно пройтись»; его реализуют список, мапа, `Range`,
  `Stream`, `File.Stream` и др. Именно поэтому `Enum` работает со всеми ними.
- **`Collectable`** — протокол «в меня можно собрать»; на нём стоят `Enum.into/2` и `:into`
  в comprehension.
- **`Enum`** — жадные операции: каждый шаг материализует новую полную коллекцию.
- **`Stream`** — ленивые операции: строится «рецепт», данные текут по одному.
- **Терминальная операция** — вызов `Enum`, который прогоняет ленивый поток (`to_list`, `take`,
  `sum`, `count`, `each`). Без неё `Stream` ничего не вычисляет.
- **Свёртка (reduce)** — обобщение всех обходов: коллекция + начальный аккумулятор + функция
  `(элемент, acc) -> acc`.
- **`reduce_while`** — свёртка с досрочным выходом через `{:cont, acc}` / `{:halt, acc}`.
- **Comprehension (`for`)** — генераторы `x <- enum` + фильтры → новая коллекция; опции
  `:into` и `:reduce`.
- **Генератор** — часть comprehension вида `образец <- перечислимое`; несовпавшие элементы
  отбрасываются (матч работает как фильтр).
- **`Range`** — `1..100` (и `1..100//2` с шагом): перечислимое без материализации списка.
- **`MapSet`** — множество уникальных значений с операциями объединения/пересечения.
- **`File.stream!/1`** — ленивое построчное чтение файла; типовой источник для `Stream`.

## Типичные ошибки и заблуждения

- **`Enum` над бесконечным/огромным источником.** `Enum.map(1..10_000_000, ...)` материализует
  всё; `Enum.map(Stream.cycle(...), ...)` вообще не вернётся. Для больших/бесконечных — `Stream`.
- **Думать, что `Stream` всегда быстрее.** На маленьких данных накладные расходы ленивости
  делают `Enum` быстрее. `Stream` выигрывает на больших данных, ранней остановке и
  избегании промежуточных списков.
- **`Enum.at(list, i)` в цикле.** Список — связный, `at` это O(n); в цикле O(n²). Нужен
  индексированный доступ — другой контейнер; нужен перебор — обычный `Enum.map/reduce`.
- **`acc ++ [x]` в свёртке.** Конкатенация в хвост списка O(n) → O(n²) в цикле. Накапливай в
  голову `[x | acc]` и `Enum.reverse` в конце, либо используй `reduce`/`for` напрямую.
- **Считать `for` циклом со счётчиком.** Это comprehension (генераторы+фильтры → коллекция),
  а не C-style `for(i=0;...)`. Счётчик с мутацией тут не нужен и невозможен.
- **Забыть терминальную операцию у `Stream`.** Цепочка `Stream.map |> Stream.filter` сама по
  себе ничего не делает — нужен `Enum.to_list`/`Enum.take`/`Enum.sum`, иначе получишь
  «ленивый рецепт», а не результат.
- **`map.key` после `Enum.into`.** Если строил мапу со строковыми ключами — `.key` (атомный)
  не сработает; помни про два стиля доступа из модуля 02.
- **`Enum.map` ради побочного эффекта.** Если результат не нужен — это `Enum.each` (он и
  возвращает `:ok`). `map` строит новый список, который ты потом выбрасываешь.
- **`reduce` там, где нужен ранний выход.** `reduce` всегда пройдёт всю коллекцию. Нужно
  остановиться на условии — `reduce_while` с `{:halt, acc}` (или `Enum.find`, если ищешь
  первый подходящий элемент).
- **Считать, что `Stream` даёт параллелизм.** Нет, это ленивость в одном процессе.
  Параллельная обработка — `Task.async_stream` (модули 08–09).
