# Упражнения

## Модель BEAM

```drill
type: multiple-choice
prompt: "Чем процесс BEAM принципиально отличается от горутины Go?"
options: ["Ничем, это одно и то же", "Процесс BEAM не делит память и общается только сообщениями; у него свой heap и GC", "Процесс BEAM тяжелее потока ОС", "Горутины изолированы, а процессы BEAM делят память"]
answer: "Процесс BEAM не делит память и общается только сообщениями; у него свой heap и GC"
check: exact
hint: Share-nothing — ключевое слово.
```

```drill
type: free-form
prompt: "Объясни «let it crash» так, чтобы Go-разработчик понял, почему это не значит «не обрабатывать ошибки»."
answer: "Счастливый путь пишется чисто; на непредвиденный сбой процесс честно падает, унося только своё изолированное состояние, а супервизор ловит падение и перезапускает процесс в известное чистое состояние. Это централизованная стратегия восстановления вместо размазанного по коду recover/обработки. Ошибки-значения (ожидаемые) всё равно обрабатываются явно — падают именно непредвиденные/сломанные состояния."
check: manual
```

```drill
type: multiple-choice
prompt: "Почему неизменяемость помогает конкурентности?"
options: ["Она ускоряет GC", "Нечего изменять на месте — значит нет гонок за общее состояние", "Она позволяет шарить указатели между потоками", "Никак не помогает, это просто стиль"]
answer: "Нечего изменять на месте — значит нет гонок за общее состояние"
check: exact
hint: Гонка возможна там, где есть мутируемое общее состояние.
```

## Язык и типизация

```drill
type: multiple-choice
prompt: "Как корректно описать систему типов Elixir на лето 2026?"
options: ["Полностью статическая, как в Go", "Динамическая, без всяких проверок типов", "Динамическая, но с растущей ВЫВОДИМОЙ set-theoretic типизацией, ловящей часть ошибок на компиляции", "Требует аннотаций типов в каждой функции"]
answer: "Динамическая, но с растущей ВЫВОДИМОЙ set-theoretic типизацией, ловящей часть ошибок на компиляции"
check: exact
hint: Типы выводятся, не пишутся; страховки меньше, чем у статики Go.
```

```drill
type: free-form
prompt: "Назови четыре сдвига в мышлении при переходе с Go на Elixir."
answer: "1) Функциональный и неизменяемый — нет мутации на месте, операции возвращают новые данные. 2) `=` это сопоставление с образцом, а не присваивание. 3) Рекурсия и Enum/comprehensions вместо циклов for. 4) Динамика с выводимой set-theoretic типизацией вместо статики Go."
check: manual
```

```drill
type: free-form
prompt: "В каком порядке ставить Erlang и Elixir и почему? Как проверить установку?"
answer: "Сначала Erlang/OTP, потом Elixir — Elixir компилируется в байткод BEAM и работает поверх Erlang/OTP, поэтому без него не запустится. Удобно через менеджер версий (asdf/mise), который ставит совместимую пару. Проверка: `elixir --version` — покажет версию Elixir (нужно 1.19+) и Erlang/OTP (27+)."
check: manual
```

## Рантайм на пальцах

```drill
type: multiple-choice
prompt: "Процесс ушёл в бесконечный цикл без вызовов ввода-вывода. Что произойдёт на BEAM?"
options: ["Узел зависнет", "Планировщик вытеснит его по исчерпании бюджета редукций, остальные процессы продолжат работать", "Процесс будет убит автоматически", "Все планировщики встанут"]
answer: "Планировщик вытеснит его по исчерпании бюджета редукций, остальные процессы продолжат работать"
check: exact
hint: "Вытеснение по редукциям, а не по доброй воле процесса."
```

```drill
type: free-form
prompt: "Коллега говорит: «упал процесс — упал узел». В чём он путается?"
answer: "Узел — это вся виртуальная машина BEAM (один процесс ОС) со всеми планировщиками и процессами. Процесс BEAM — лёгкая изолированная сущность внутри узла; его падение штатно и локально (умирает только его состояние), а супервизор перезапустит. Узел падает только от чего-то системного (например, исчерпание памяти или таблицы атомов)."
check: manual
```
