# Функции, модули, guards и пайп

## Модули и функции

Код живёт в **модулях** (`defmodule`), логика — в **функциях** (`def` — публичная, `defp` —
приватная). Возвращается последнее выражение; `return` нет вообще.

```elixir
defmodule Math do
  def square(x) do          # публичная
    x * x
  end

  def cube(x), do: x * square(x)   # однострочная форма: do:

  defp helper(x), do: x + 1        # приватная: видна только внутри Math
end

Math.square(5)   # => 25
Math.helper(5)   # ❌ (UndefinedFunctionError) — defp наружу не торчит
```

> **Go-параллель.** Модуль ≈ пакет + пространство имён в одном. `def` ≈ экспортируемая
> функция (с большой буквы в Go), `defp` ≈ функция со строчной буквы (пакетно-приватная).
> Но имя файла и имя модуля не обязаны совпадать, и в одном файле может быть несколько
> модулей.

### `alias`, `import`, `require` — три директивы для чужих модулей

Модули зовут по полному имени: `MyApp.Accounts.User.new()`. Чтобы не писать это каждый раз,
есть три директивы. Все они **лексические** — действуют только там, где написаны (внутри
модуля или даже внутри одной функции), и на другие файлы не влияют.

```elixir
defmodule MyApp.Report do
  alias MyApp.Accounts.User           # теперь просто User.new()
  alias MyApp.Accounts.{User, Team}   # сразу несколько
  alias MyApp.Accounts.User, as: U    # под своим коротким именем

  import Enum, only: [map: 2]         # втянуть функции: можно звать map(list, f) без Enum.
  require Logger                      # подготовить модуль, у которого есть МАКРОСЫ

  def build(users) do
    Logger.info("строю отчёт")        # Logger.info — макрос, поэтому нужен require
    map(users, &User.name/1)          # без префикса Enum. — благодаря import
  end
end
```

- **`alias`** — сократить имя. Это 95% случаев, используй смело.
- **`import`** — втянуть функции модуля, чтобы звать без префикса. Дозируй и всегда указывай
  `only:`: иначе получается каша, в которой непонятно, откуда взялась функция.
- **`require`** — нужен только для **макросов** модуля (компилятор должен раскрыть их в этом
  файле). Для обычных функций `require` не требуется.

Есть и четвёртая директива — **`use`**, но она про другое: не «сократить имя», а «внедри в мой
модуль вот этот код». Познакомимся с ней в модуле 06, когда дойдём до behaviours
(`use GenServer`).

> **Go-параллель.** `alias` ≈ импорт пакета под локальным именем; `import ..., only:` ≈
> точечный импорт (`import . "pkg"`), которого в Go справедливо избегают; `require` аналога не
> имеет вовсе — в Go нет макросов. Главное отличие: в Elixir всё это лексическое, а не
> файловое, и написать `alias` можно даже внутри функции.

## Арность: `name/2` — это часть идентичности функции

Функцию в Elixir однозначно задаёт **имя + количество аргументов (арность)**, записывается
`square/1`, `Enum.map/2`. `foo/1` и `foo/2` — **две разные функции**, не перегрузка одной.
В доках, ошибках и `&`-захвате всегда указывают арность.

```elixir
String.split/1    # split(string) — по пробелам
String.split/2    # split(string, pattern)
String.split/3    # split(string, pattern, opts)
```

> **Go-контраст.** В Go нет перегрузки по числу аргументов и нет понятия «арность в имени».
> В Elixir арность — первоклассная: она различает функции и пишется явно повсюду.

## Multi-clause: сопоставление как диспетчер

Вместо `if`/`switch` внутри тела пиши несколько **clause** (голов) одной функции с разными
образцами в аргументах. Рантайм пробует их **сверху вниз** и выполняет первую совпавшую.

```elixir
defmodule Http do
  def status(200), do: "OK"
  def status(404), do: "Not Found"
  def status(code) when code >= 500, do: "Server Error (#{code})"
  def status(_other), do: "Unknown"
end
```

```elixir
defmodule Resp do
  def render({:ok, data}),      do: "Данные: #{data}"
  def render({:error, reason}), do: "Сбой: #{reason}"
end
```

Если ни одна clause не подошла — `FunctionClauseError` (тоже штатный fail-fast). Это
центральная идиома: разбор тегированных кортежей, рекурсия, обработка сообщений — всё на
multi-clause.

> **Go-контраст.** В Go это был бы `switch` по значению или `switch v := x.(type)`. В Elixir
> диспетч встроен в саму функцию, читается как таблица «вход → ветка», и опирается на тот же
> pattern matching из модуля 02. Порядок clause **важен**: специфичные — выше, общий
> `_other` — последним.

## Guards: когда образца мало

Образец проверяет *форму*. Когда нужно условие на *значение* (диапазон, тип, сравнение) —
добавляй `when`-guard:

```elixir
def classify(n) when is_integer(n) and n > 0, do: :positive
def classify(n) when is_integer(n) and n < 0, do: :negative
def classify(0), do: :zero
def classify(_), do: :not_a_number
```

В guards разрешён только **ограниченный** набор конструкций (чистые, без побочных эффектов):
сравнения, булева логика, арифметика, type-checks (`is_integer`, `is_binary`, `is_map`...),
`in`, и т.п. Нельзя звать произвольные свои функции — guard должен быть безопасно
вычислимым и быстрым. Свой переиспользуемый guard оформляется через `defguard`.

> **Go-параллель.** Guard ≈ `case x > 0:` в `switch` или условие в `if`, но привязанное к
> clause функции. Ограничение «только чистые конструкции» — особенность: компилятор должен
> гарантировать, что guard не имеет эффектов.

## Дефолтные аргументы `\\`

```elixir
def greet(name, greeting \\ "Привет") do
  "#{greeting}, #{name}!"
end

greet("Сэм")             # => "Привет, Сэм!"
greet("Сэм", "Здорово")  # => "Здорово, Сэм!"
```

`\\` задаёт значение по умолчанию. Технически это порождает несколько арностей (`greet/1` и
`greet/2`). С multi-clause дефолты пишут в отдельной «заголовочной» clause без тела, чтобы не
повторять `\\` в каждой.

Как это выглядит на практике:

```elixir
def join(list, sep \\ ", ")             # ← заголовок: только сигнатура с дефолтом, без тела
def join([], _sep), do: ""
def join(list, sep), do: Enum.join(list, sep)
```

Если написать `\\` в каждой clause, компилятор ругнётся: «def join/2 defines defaults multiple
times». Правило простое: **дефолты объявляются один раз, в заголовочной clause**.

## Пайп `|>`: конвейер вместо матрёшки

Пайп берёт значение слева и подставляет его **первым аргументом** функции справа:

```elixir
"  Hello, World  " |> String.trim() |> String.downcase() |> String.split(", ")
# эквивалент: String.split(String.downcase(String.trim("  Hello, World  ")), ", ")
# => ["hello", "world"]
```

Без пайпа читается изнутри наружу (как в Go: `f(g(h(x)))`), с пайпом — сверху вниз, как
конвейер данных. Именно поэтому стандартная библиотека спроектирована так, что **главный
аргумент (данные) идёт первым**: `Enum.map(list, f)`, `String.split(str, p)`. Это «data-first»
дизайн под пайп.

```elixir
list
|> Enum.filter(&(&1 > 0))
|> Enum.map(&(&1 * 2))
|> Enum.sum()
```

> **Go-контраст.** В Go нет пайпа; ты пишешь промежуточные переменные или вложенные вызовы.
> Пайп — не магия, а синтаксический сахар над «подставь первым аргументом», но он
> радикально меняет читаемость и поощряет писать функции в стиле «данные первым параметром».

### Когда пайп не ложится: `then/2` и `tap/2`

Пайп подставляет значение только **первым** аргументом. Два штатных выхода, когда нужно иначе:

```elixir
# then/2 — «примени к значению вот эту функцию»: значение попадает куда угодно
"42"
|> String.trim()
|> then(fn s -> Map.get(%{"42" => :answer}, s) end)

# tap/2 — «загляни в значение и пропусти дальше без изменений» (для побочного эффекта)
users
|> tap(fn list -> IO.puts("получено #{length(list)}") end)
|> Enum.filter(& &1.active)
```

`then` заменяет неуклюжее `|> (fn x -> ... end).()`, а `tap` идеален для логирования в
середине конвейера.

### Как заглянуть внутрь пайплайна: `IO.inspect` и `dbg`

Отладчик в Elixir есть, но 90% реальной отладки — это печать значения посреди конвейера. Обе
функции **возвращают своё значение**, поэтому вставляются в пайп, ничего не ломая:

```elixir
[1, -2, 3]
|> Enum.filter(&(&1 > 0))
|> IO.inspect(label: "после filter")   # напечатает: после filter: [1, 3]
|> Enum.sum()

# dbg() — «покажи весь конвейер по шагам»
[1, -2, 3]
|> Enum.filter(&(&1 > 0))
|> Enum.sum()
|> dbg()
```

`dbg()` печатает каждый шаг пайпа вместе с промежуточным результатом и указанием файла и
строки — то, ради чего в Go расставляют десяток `fmt.Printf`. В `iex` он умеет ещё и пошаговый
режим. Гигиена та же, что в Go: отладочные `IO.inspect`/`dbg` в коммит не попадают (Credo из
модуля 09 об этом напомнит).

## Анонимные функции и capture `&`

```elixir
square = fn x -> x * x end
square.(5)               # => 25  — ВЫЗОВ анонимной функции через точку: f.(args)

double = &(&1 * 2)       # capture-синтаксис: &1 — первый аргумент
double.(10)              # => 20

Enum.map([1, 2, 3], fn x -> x * x end)
Enum.map([1, 2, 3], &(&1 * &1))         # то же короче
Enum.map(["a", "b"], &String.upcase/1)  # захват именованной функции по имени/арности
```

Две вещи легко перепутать: именованную функцию зовут `Mod.fun(args)`, а анонимную — через
**точку**: `f.(args)`. Точка обязательна и отличает «вызвать функцию-значение» от «обратиться
к полю». `&Mod.fun/1` захватывает существующую функцию как значение (передать в `Enum.map`).

## Рекурсия вместо циклов

В Elixir **нет** `for i := 0; i < n; i++`. Перебор — это рекурсия (часто спрятанная внутри
`Enum`). Каноничный приём — **аккумулятор**:

```elixir
defmodule Sum do
  def total(list), do: total(list, 0)         # публичный вход, заводит аккумулятор
  defp total([], acc), do: acc                 # база: список кончился — вернуть acc
  defp total([h | t], acc), do: total(t, acc + h)  # шаг: добавили голову, идём по хвосту
end

Sum.total([1, 2, 3, 4])   # => 10
```

Последняя clause делает **хвостовой вызов** (рекурсивный вызов — последнее действие), и BEAM
выполняет его без роста стека (tail-call optimization). Поэтому рекурсия с аккумулятором не
переполнит стек даже на длинных списках. На практике 90% циклов ты напишешь через `Enum`/
`Stream` (модуль 05), но понимать рекурсию под ними — обязательно.

> **Go-контраст.** Цикл `for` с мутируемым счётчиком заменяется на рекурсию с неизменяемым
> аккумулятором, который передаётся в следующий вызов. Никакой мутации — каждый шаг это новый
> вызов с новым значением acc. Tail-call optimization играет роль «цикла без стека».

## Глоссарий модуля

- **Модуль (`defmodule`)** — пространство имён и контейнер функций.
- **`def` / `defp`** — публичная / приватная функция модуля.
- **Арность** — число аргументов; часть идентичности функции (`split/2` ≠ `split/3`).
- **Clause** — одна «голова» функции с собственным образцом аргументов.
- **Multi-clause** — несколько clause одной функции; выбирается первая совпавшая сверху вниз.
- **`FunctionClauseError`** — ни одна clause не подошла к аргументам.
- **Guard (`when`)** — условие на значения поверх образца; допускает только чистые
  безопасные конструкции; свой guard объявляют через `defguard`.
- **Заголовочная clause** — сигнатура с дефолтами (`\\`) без тела; дефолты объявляются в ней
  один раз.
- **Пайп (`|>`)** — подставляет левое значение первым аргументом правой функции.
- **Data-first** — соглашение «главные данные первым аргументом», под которое спроектирована
  стандартная библиотека.
- **`then/2` / `tap/2`** — вставки в пайп: применить произвольную функцию / заглянуть в
  значение и пропустить дальше.
- **Анонимная функция** — `fn x -> ... end`, вызывается через точку: `f.(x)`.
- **Capture (`&`)** — короткая запись `&(&1 * 2)` и захват именованной функции `&String.upcase/1`.
- **Аккумулятор** — неизменяемое значение, передаваемое в следующий виток рекурсии вместо
  мутируемой переменной цикла.
- **Хвостовой вызов (TCO)** — рекурсивный вызов последним действием; стек не растёт.
- **`alias` / `import` / `require`** — сократить имя модуля / втянуть функции / подготовить
  макросы (`use` — модуль 06).
- **`IO.inspect` / `dbg`** — печать значения в конвейере; обе возвращают своё значение.

## Типичные ошибки и заблуждения

- **Искать `return`.** Его нет. Возвращается последнее выражение clause. «Ранний возврат»
  выражается через multi-clause или `case`/`cond`, а не `return`.
- **Звать анонимную функцию без точки.** `f(x)` для `f = fn ...` не работает — нужно `f.(x)`.
  Точка отличает вызов значения-функции от вызова именованной.
- **Игнорировать арность.** `foo/1` и `foo/2` — разные функции. В `&`-захвате и доках
  арность обязательна: `&String.split/2`, не `&String.split`.
- **Пихать сложную логику в guard.** Guards ограничены чистыми конструкциями; нельзя звать
  произвольные функции. Не помещается в guard — выноси в тело через `case`/`cond`.
- **Порядок clause наоборот.** Общий образец `_` сверху перехватит всё, специфичные снизу
  не сработают. Специфичное — выше, общее — ниже.
- **Писать функции «данные последним аргументом».** Тогда пайп некрасив. Идиома Elixir —
  главные данные **первым** параметром, опции — последним (keyword list).
- **Глубокая нерекурсивная рекурсия.** Рекурсия без аккумулятора (`h + sum(t)`) копит стек;
  с аккумулятором и хвостовым вызовом — нет. Для больших данных — аккумулятор или `Enum`.
- **Дефолты `\\` в каждой clause.** Ошибка компиляции «defines defaults multiple times».
  Дефолты объявляются один раз — в заголовочной clause без тела.
- **`import` без `only:`.** Втянутые «всё подряд» функции превращают чтение кода в угадайку.
  По умолчанию бери `alias`, а `import` — точечно и с `only:`.
- **Ждать, что `require` нужен для обычных функций.** Он нужен только для макросов
  (`require Logger`); функции доступны и так, максимум им нужен `alias`.
- **Оставлять `IO.inspect`/`dbg` в коммите.** Это отладочная печать, а не логирование; для
  логов есть `Logger` (модуль 09).
