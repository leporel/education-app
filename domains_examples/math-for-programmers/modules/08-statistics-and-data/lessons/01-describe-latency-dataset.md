# Урок 01 — Описываем датасет латентности руками и кодом

## Разогрев

- Медиана считается по **отсортированному** ряду; при чётном n — полусумма двух центральных.
- Перцентиль методом ближайшего ранга: `i = ⌈p/100 · n⌉`, нумерация с 1.
- Среднее заметно больше медианы — признак правого хвоста.

Формулы — в [первой части теории](../theory.md). Здесь мы один раз проходим весь путь.

## Датасет

Двадцать замеров латентности эндпоинта (мс), в порядке поступления:

```text
23, 19, 25, 21, 30, 18, 22, 26, 20, 24,
27, 19, 21, 35, 22, 480, 20, 23, 61, 24
```

Первым делом сортируем — без этого не посчитать ни медиану, ни перцентили:

```text
18, 19, 19, 20, 20, 21, 21, 22, 22, 23,
23, 24, 24, 25, 26, 27, 30, 35, 61, 480
```

## Шаг 1. Центр

```text
сумма = 960                     — складываем все 20 значений
среднее = 960 / 20 = 48 мс
медиана: n = 20 чётное, берём 10-й и 11-й элементы
         (23 + 23) / 2 = 23 мс
мода = 19, 20, 21, 22, 23, 24   — по два раза каждое, моды фактически нет
```

Среднее больше медианы более чем вдвое. Уже на этом шаге понятно: данные скошены вправо, и
одно значение (480) тянет среднее на себя. Проверим: без него среднее равно `480/19 ≈ 25.3`
мс — почти совпадает с медианой.

## Шаг 2. Разброс

```text
размах = 480 − 18 = 462 мс                  — бесполезен, определён одним замером
Q1: i = ⌈0.25·20⌉ = 5   → 20 мс
Q3: i = ⌈0.75·20⌉ = 15  → 26 мс
IQR = 26 − 20 = 6 мс                        — вот это уже информативно
граница выбросов: Q3 + 1.5·IQR = 26 + 9 = 35
выбросы: 61 и 480 (35 ровно на границе — не выброс)
```

Половина всех запросов укладывается в диапазон 20–26 мс. Именно это число (IQR = 6) стоит
называть, когда спрашивают «насколько стабилен эндпоинт», а не размах в 462 мс.

## Шаг 3. Перцентили

```text
p50: i = ⌈0.50·20⌉ = 10  → 23 мс
p90: i = ⌈0.90·20⌉ = 18  → 35 мс
p95: i = ⌈0.95·20⌉ = 19  → 61 мс
p99: i = ⌈0.99·20⌉ = 20  → 480 мс
```

Обратите внимание на p99: при n = 20 он равен максимуму, то есть определяется **одним**
замером. Такое число нельзя ставить в SLO и нельзя сравнивать между окнами — оно будет
скакать как угодно. Для устойчивого p99 нужны сотни, а лучше тысячи наблюдений.

## Шаг 4. Картинка

Числа полезны, но форму данных видно только на графике.

```text
корзина      количество
≤ 20 мс      █████ 5
≤ 25 мс      █████████ 9
≤ 30 мс      ███ 3
≤ 40 мс      █ 1
≤ 100 мс     █ 1
≤ 1000 мс    █ 1
```

Классический «тонкий пик + длинный хвост». Box plot того же датасета:

```text
   18   20      26   35            61                         480
    ├────█████████────┤             °                           °
        Q1  med  Q3
```

## Шаг 5. То же самое кодом

```go
package main

import (
	"fmt"
	"math"
	"slices"
)

func percentile(sorted []float64, p float64) float64 {
	i := int(math.Ceil(p/100*float64(len(sorted)))) - 1
	return sorted[max(i, 0)]
}

func main() {
	data := []float64{23, 19, 25, 21, 30, 18, 22, 26, 20, 24,
		27, 19, 21, 35, 22, 480, 20, 23, 61, 24}
	slices.Sort(data)

	var sum float64
	for _, x := range data {
		sum += x
	}
	mean := sum / float64(len(data))
	q1, q3 := percentile(data, 25), percentile(data, 75)

	fmt.Printf("mean=%.1f p50=%.0f p90=%.0f p95=%.0f p99=%.0f IQR=%.0f\n",
		mean, percentile(data, 50), percentile(data, 90),
		percentile(data, 95), percentile(data, 99), q3-q1)
}
// mean=48.0 p50=23 p90=35 p95=61 p99=480 IQR=6
```

Совпало с ручным расчётом — а значит, оба сделаны верно. Это привычка, которую стоит
завести: считать руками на маленьком примере и сверять с кодом.

## Шаг 6. Что докладывать

Плохой отчёт: «средняя латентность 48 мс».
Хороший отчёт: «p50 = 23 мс, p90 = 35 мс, половина запросов в диапазоне 20–26 мс; за окно
два выброса — 61 мс и 480 мс, оба требуют разбора; выборка мала (20 замеров), p99 по ней не
считается».

```drill

prompt: "Объясните, почему в этом датасете размах (462 мс) и IQR (6 мс) настолько различаются, и какое из этих чисел честнее описывает работу эндпоинта."
answer: "Размах определяется двумя крайними значениями, поэтому единственный аномальный замер в 480 мс задаёт его целиком и никак не отражает поведение остальных девятнадцати запросов. IQR описывает, где живёт средняя половина данных, и к выбросам нечувствителен: 6 мс означает, что типичный разброс эндпоинта невелик. Честнее IQR — но при этом выбросы нельзя выбрасывать из отчёта: их надо назвать отдельно, потому что 480 мс это чей-то реальный запрос, и он может быть симптомом проблемы."
check: manual
```

## Итог

Порядок описания любого набора чисел один и тот же: отсортировать, посчитать центр
(среднее и медиану — обязательно оба, чтобы увидеть скос), разброс (IQR надёжнее размаха и
σ), перцентили и наконец нарисовать. Ключевой урок этого датасета: среднее 48 мс не
описывает ни один из двадцати запросов, а p99 на выборке в 20 замеров — это максимум, а не
статистика. Дальше — [урок 02](./02-correlation-and-paradoxes.md), где мы перейдём от
описания одной величины к связям между двумя.
