# Урок 03 — Разбор A/B-теста и доверительного интервала

## Разогрев

- `SE = √(p(1−p)/n)` — стандартная ошибка доли; для среднего это `s/√n`.
- 95%-интервал ≈ `оценка ± 1.96·SE`; для разницы `SE = √(SE₁² + SE₂²)`.
- Размер выборки считается **до** запуска: `n ≈ 16·p(1−p)/MDE²` на группу.

Формулы и оговорки — во [второй части теории](../theory-2-inference-and-traps.md).

## Постановка

Гипотеза: новая форма оплаты повысит конверсию. Текущая конверсия — 4%. Продукт готов
внедрять изменение, если рост составит хотя бы **0.4 процентного пункта** (с 4.0% до 4.4%) —
это и есть MDE, минимальный значимый эффект.

## Шаг 1. Сколько данных нужно

Считаем **до** запуска. Иначе тест либо ничего не покажет, либо покажет случайность.

```text
p = 0.04, MDE = 0.004
n ≈ 16 · p(1−p) / MDE²          — формула для 95% значимости и 80% мощности
  = 16 · 0.04 · 0.96 / 0.000016
  = 16 · 0.0384 / 0.000016
  = 0.6144 / 0.000016
  = 38 400 на группу
всего: 76 800 посетителей
при 6 000 посетителей в день: 76 800 / 6 000 = 12.8 → 13 дней
```

Тринадцать дней — это и есть настоящая цена эксперимента. Если продукт не готов ждать,
разговор должен идти не про статистику, а про MDE: чтобы ловить рост в 1 п.п. вместо
0.4 п.п., нужно всего `16·0.0384/0.0001 = 6 144` на группу — два дня.

Обратите внимание на квадрат в знаменателе: **уменьшение MDE вдвое умножает выборку на 4**.

## Шаг 2. Запуск без подглядывания

Правила, которые надо зафиксировать письменно до старта:

1. **Метрика одна** (первичная). Остальные — вспомогательные, по ним решений не принимаем.
2. **Срок фиксирован** — 13 дней, целые недели лучше (день недели влияет на поведение).
3. **Не смотрим на p-value каждый день.** Проверка «до первой значимости» раздувает
   ложные срабатывания с 5% до 20–30%: вы даёте себе тринадцать попыток поймать случайность.
4. **Разделение случайное и стабильное** — по хешу от user id, а не по времени и не по
   региону, иначе группы будут различаться составом (привет, парадокс Симпсона).

Мониторить в процессе можно и нужно — но техническое здоровье (ошибки, латентность, доля
трафика в группах), а не целевую метрику.

## Шаг 3. Считаем результат

Прошло 13 дней.

```text
группа A (контроль): 38 500 посетителей, 1 540 покупок
группа B (новая):    38 700 посетителей, 1 703 покупки
```

Конверсии и их ошибки:

```text
p_A = 1540 / 38500 = 0.0400
p_B = 1703 / 38700 = 0.0440

SE_A = √(0.0400·0.9600 / 38500) = √(0.00000099740) ≈ 0.000999
SE_B = √(0.0440·0.9560 / 38700) = √(0.00000108682) ≈ 0.001043
```

Разница и её интервал:

```text
Δ = 0.0440 − 0.0400 = 0.0040                   — 0.4 п.п.
SE_Δ = √(SE_A² + SE_B²)                        — дисперсии независимых складываются
     = √(0.000999² + 0.001043²)
     = √(0.000000998 + 0.000001088)
     = √0.000002086 ≈ 0.001444
95%-интервал: 0.0040 ± 1.96·0.001444
            = 0.0040 ± 0.00283
            = [0.00117, 0.00683]  то есть [+0.12 п.п., +0.68 п.п.]
```

Ноль в интервал **не** попал — эффект статистически значим. Но интерпретировать надо не
только знак:

```text
точечная оценка эффекта:   +0.40 п.п. (относительный рост +10%)
пессимистичный сценарий:   +0.12 п.п. (относительный рост +3%)
оптимистичный сценарий:    +0.68 п.п. (относительный рост +17%)
```

Решение принимается по **нижней границе**: если +0.12 п.п. окупает стоимость поддержки
новой формы — внедряем. Если нет, значимость сама по себе ничего не даёт.

## Шаг 4. Проверка симуляцией

Не доверять формуле — здоровая привычка. Перестановочный тест не требует ни нормальности,
ни таблиц: он честно моделирует мир, где эффекта нет.

```go
import "math/rand/v2"

// Доля случайных перетасовок, в которых разница конверсий не меньше наблюдённой.
func permutationTest(nA, kA, nB, kB, iters int) float64 {
	pool := make([]bool, 0, nA+nB)
	for i := 0; i < kA+kB; i++ {
		pool = append(pool, true) // покупка
	}
	for i := 0; i < nA+nB-kA-kB; i++ {
		pool = append(pool, false)
	}
	observed := float64(kB)/float64(nB) - float64(kA)/float64(nA)

	ge := 0
	for range iters {
		rand.Shuffle(len(pool), func(i, j int) { pool[i], pool[j] = pool[j], pool[i] })
		a, b := 0, 0
		for i, v := range pool {
			if v && i < nA {
				a++
			} else if v {
				b++
			}
		}
		if float64(b)/float64(nB)-float64(a)/float64(nA) >= observed {
			ge++
		}
	}
	return float64(ge) / float64(iters)
}
// permutationTest(38500, 1540, 38700, 1703, 10_000) ≈ 0.003
```

Оценка p-value около 0.003 — согласуется с тем, что интервал не содержит ноль. Формула и
симуляция сошлись, значит ошибки в выкладке нет.

## Шаг 5. Что могло пойти не так

```text
подглядывание             → ложное срабатывание вместо эффекта
несбалансированные группы → парадокс Симпсона (проверить состав по устройствам, регионам)
новизна (novelty effect)  → рост в первые дни, затухание потом; смотреть динамику
несколько метрик          → одна из 20 «значима» случайно; фиксировать первичную заранее
утечка между группами     → один пользователь видел оба варианта; проверить стабильность
                            разделения по хешу
```

```drill
type: free-form

answer: "Значимость получена, но полезный эффект не доказан: при базе 4% нижняя граница +0.02 п.п. — это относительный рост в 0.5%, который почти наверняка не окупит разработку и поддержку. Продукту стоит сказать: «мы уверены, что изменение не вредит, и весьма вероятно, что оно немного помогает, но гарантированный минимум выигрыша ниже порога окупаемости». Дальше есть три пути: внедрить, если стоимость поддержки близка к нулю; продлить тест, чтобы сузить интервал (учитывая, что для сужения вдвое нужно вчетверо больше данных); или отказаться и искать изменение с большим ожидаемым эффектом."
check: manual
```

```drill

prompt: "Объясните своими словами, почему подглядывание в промежуточные результаты A/B-теста увеличивает долю ложных выводов, и как этого избежать."

Избежать можно тремя способами: зафиксировать срок и смотреть результат один раз; применить последовательный тест с alpha spending, который распределяет допустимую ошибку по проверкам; или использовать байесовский подход, где промежуточные обновления убеждений корректны по построению."
check: manual
```

## Итог

A/B-тест — это четыре шага в строгом порядке: задать MDE и посчитать размер выборки,
случайно разделить трафик, дождаться срока без подглядывания, посчитать разницу и её
доверительный интервал. Решение принимается по нижней границе интервала, а не по факту
«p < 0.05»: значимость говорит лишь о том, что эффект вряд ли нулевой, а окупаемость
определяется его размером. И главное правило урока, которое дороже всех формул: размер
выборки считается до старта, потому что после старта любая арифметика превращается в
подгонку.
