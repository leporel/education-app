# Урок 01 — Таблица роста и big-O на живом коде

## Разогрев

- **Наклон прямой**: `k = (y₂ − y₁)/(x₂ − x₁)` — «на сколько поднялись делить на сколько прошли».
- **Два правила big-O**: выбрасываем константные множители и младшие слагаемые.
- **Иерархия**: `1 < log n < √n < n < n log n < n² < n³ < 2ⁿ < n!`.

Если что-то из этого не откликается — вернитесь в [`theory.md`](../theory.md), раздел
«Простыми словами».

## Новая тема: читаем сложность глазами

Практический навык звучит так: **посмотреть на функцию и за 10 секунд назвать её
сложность**. Он держится на трёх наблюдениях.

1. **Цикл по входу — это множитель `n`.** Один цикл `for i := 0; i < n; i++` даёт `n`.
2. **Вложенность умножает, последовательность складывает.** Цикл в цикле — `n·m`;
   два цикла подряд — `n + m`, что сворачивается в `max(n, m)`.
3. **Каждая операция внутри цикла имеет свою цену.** `map` lookup — `O(1)`, поиск в
   отсортированном срезе — `O(log n)`, `append` в срез — амортизированно `O(1)`, а вот
   `strings.Contains` по строке длины `m` — `O(m)`.

Третий пункт — самый частый источник сюрпризов: код выглядит как один цикл, но внутри
спрятан ещё один.

## Разобранные примеры

### Пример 1. Спрятанный квадрат

```go
func hasCommonTag(users []User, tags []string) []User {
	var out []User
	for _, u := range users { // n итераций
		for _, t := range tags { // m итераций
			if slices.Contains(u.Tags, t) { // ещё k — длина u.Tags
				out = append(out, u)
				break
			}
		}
	}
	return out
}
```

```text
внешний цикл: n                      — по пользователям
внутренний:   m                      — по искомым тегам
slices.Contains: k                   — линейный поиск по тегам пользователя
итого: O(n · m · k)                  — вложенность перемножается
```

При `n = 50 000`, `m = 20`, `k = 10` это 10 миллионов операций — ещё терпимо. При
`m = 2000` (кто-то передал весь справочник тегов) — уже миллиард, и ручка «увеличить
таймаут» не поможет. Лечение: сложить `tags` в `map[string]struct{}` — тогда внутренняя
проверка станет `O(1)`, а вся функция — `O(n·k + m)`.

### Пример 2. Сортировка не проблема

```go
func topN(items []Item, n int) []Item {
	sort.Slice(items, func(i, j int) bool { // O(N log N)
		return items[i].Score > items[j].Score
	})
	return items[:n] // O(1) — просто срез
}
```

```text
sort.Slice: N log N                  — pdqsort в стандартной библиотеке
срез items[:n]: 1                    — не копирует данные
итого: O(N log N)                    — доминирует сортировка
```

Сколько это на миллионе? `10⁶ · 20 = 2·10⁷` операций — около 20–100 мс на реальных
данных. Ровно поэтому в инженерных спорах «а не дорого ли сортировать» почти всегда
ответ «нет»: `n log n` практически неотличим от `n`.

### Пример 3. Строка, растущая в цикле

```go
func join(parts []string) string {
	s := ""
	for _, p := range parts {
		s += p // каждый += копирует всю накопленную строку
	}
	return s
}
```

```text
итерация 1: копируем 0 символов
итерация 2: копируем len(p₁)
итерация 3: копируем len(p₁) + len(p₂)
...
сумма: 1 + 2 + ... + n ≈ n²/2        — формула суммы арифметической прогрессии
итого: O(n²) по суммарной длине
```

Это классика: код выглядит как один цикл, а работает как квадрат, потому что строки в
Go неизменяемы. Правильный вариант — `strings.Builder` и `O(n)`.

### Пример 4. Оцениваем «доживёт ли до прода»

Задача: перебрать все подмножества из `n` включённых фич, чтобы найти лучшую комбинацию.

```text
число подмножеств: 2ⁿ                — по одному биту на фичу (модуль 06)
n = 20:  2²⁰ ≈ 10⁶      → 1 мс       — мгновенно
n = 30:  2³⁰ ≈ 10⁹      → 1 с        — терпимо
n = 40:  2⁴⁰ ≈ 10¹²     → 18 минут   — уже нет
n = 50:  2⁵⁰ ≈ 10¹⁵     → 13 дней    — точно нет
```

Каждая новая фича **удваивает** время. Это и есть разговор про «экспонента ломается на
ровном месте»: между «работает за секунду» и «не работает никогда» — десять фич.

## Итог

Сложность читается по структуре кода, а не по ощущениям: циклы дают множители,
вложенность перемножается, последовательность складывается, а «невинные» операции
внутри цикла (линейный поиск, конкатенация строк, запрос в базу) добавляют свой
множитель. Дальше работает таблица: `n log n` на миллионе — это десятки миллисекунд,
`n²` — семнадцать минут, `2ⁿ` при `n = 50` — тринадцать дней. Разница между
приемлемым и невозможным почти всегда лежит на одном уровне иерархии роста.
