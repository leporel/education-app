# Урок 02 — Производная и градиентный спуск руками и в Go

## Разогрев

- **Производная** — наклон касательной, мгновенная скорость изменения.
- **Правило степени**: `(xⁿ)′ = n·x^(n−1)`. Константа даёт `0`, сумма дифференцируется почленно.
- **Цепное правило**: `(f(g(x)))′ = f′(g(x)) · g′(x)`.
- **Минимум** ищем из `f′(x) = 0`.

Теория — в [`theory-2-calculus.md`](../theory-2-calculus.md).

## Новая тема: обучение как спуск с горы

Представьте туман и склон. Видно только землю под ногами — значит, известен **локальный
наклон**. Хотите вниз? Сделайте шаг в сторону наибольшего спуска, посмотрите снова,
повторите. Это буквально весь градиентный спуск:

```text
w ← w − α·∇f(w)
```

где `f` — «насколько модель ошибается», `w` — настраиваемые параметры, `α` — длина шага.

Разберём на самой честной задаче, какую только можно взять: подберём прямую
`y = w·x + b` под четыре точки. Это линейная регрессия, и она же — простейшая
«нейросеть» из одного нейрона без активации.

**Функция ошибки** — средний квадрат отклонения (MSE):

```text
f(w, b) = (1/N)·Σ(i=1..N) (w·xᵢ + b − yᵢ)²
```

Читается: «для каждой точки берём разницу между предсказанием и правдой, возводим в
квадрат (чтобы знак не мешал и большие промахи били сильнее), усредняем».

**Градиент** считаем цепным правилом. Внешняя функция — квадрат, внутренняя — линейная:

```text
∂f/∂w = (1/N)·Σ 2·(w·xᵢ + b − yᵢ)·xᵢ     — производная квадрата, умноженная на ∂(w·xᵢ+b)/∂w = xᵢ
∂f/∂b = (1/N)·Σ 2·(w·xᵢ + b − yᵢ)·1      — ∂(w·xᵢ+b)/∂b = 1
```

Обозначим ошибку на точке `eᵢ = w·xᵢ + b − yᵢ`, тогда всё сжимается до

```text
∂f/∂w = (2/N)·Σ eᵢ·xᵢ
∂f/∂b = (2/N)·Σ eᵢ
```

## Разобранные примеры

### Пример 1. Один шаг спуска вручную

Данные: `(1, 3), (2, 5), (3, 7), (4, 9)` — идеально ложатся на `y = 2x + 1`, но модель
этого не знает. Старт: `w = 0`, `b = 0`, `α = 0.1`.

```text
предсказания при w=0, b=0:  0, 0, 0, 0
ошибки eᵢ = pred − y:       −3, −5, −7, −9
Σ eᵢ·xᵢ = −3·1 + (−5)·2 + (−7)·3 + (−9)·4 = −3 − 10 − 21 − 36 = −70
Σ eᵢ     = −3 − 5 − 7 − 9 = −24
∂f/∂w = (2/4)·(−70) = −35        — N = 4
∂f/∂b = (2/4)·(−24) = −12
w ← 0 − 0.1·(−35) = 3.5          — шаг против градиента
b ← 0 − 0.1·(−12) = 1.2
```

Обратите внимание: градиент отрицательный, значит функция ошибки убывает при росте `w`,
значит шаг делается **вверх** по `w`. Знак минус в формуле как раз это и обеспечивает.

### Пример 2. Второй шаг — и первое подозрение

```text
предсказания при w=3.5, b=1.2:  4.7, 8.2, 11.7, 15.2
ошибки:                          1.7, 3.2, 4.7, 6.2
Σ eᵢ·xᵢ = 1.7 + 6.4 + 14.1 + 24.8 = 47.0
Σ eᵢ    = 15.8
∂f/∂w = 0.5·47.0 = 23.5
∂f/∂b = 0.5·15.8 = 7.9
w ← 3.5 − 0.1·23.5 = 1.15
b ← 1.2 − 0.1·7.9  = 0.41
```

Мы перелетели цель (`w = 2`) в первую сторону и перелетели обратно. Так выглядит
слишком большой `α`: значения колеблются вокруг ответа. Здесь колебания затухают и мы
всё же сойдёмся, но при `α = 0.2` этот же процесс разойдётся в бесконечность. Именно
поэтому «уменьшить learning rate» — первое действие, когда модель «не учится».

### Пример 3. Тот же спуск в Go

```go
func fit(xs, ys []float64, alpha float64, steps int) (w, b float64) {
	n := float64(len(xs))
	for s := 0; s < steps; s++ {
		var gw, gb float64
		for i := range xs {
			e := w*xs[i] + b - ys[i] // ошибка на точке
			gw += e * xs[i]          // накапливаем Σ eᵢ·xᵢ
			gb += e                  // накапливаем Σ eᵢ
		}
		w -= alpha * 2 / n * gw // шаг против градиента по w
		b -= alpha * 2 / n * gb // шаг против градиента по b
	}
	return w, b
}

// fit([]float64{1,2,3,4}, []float64{3,5,7,9}, 0.02, 5000) → w ≈ 2.0000, b ≈ 1.0000
```

Двенадцать строк — и это принципиально тот же алгоритм, что крутится в обучении больших
моделей. Разница только в том, что там `w` — не два числа, а миллиарды, а градиент
считается автоматическим дифференцированием по тому же цепному правилу.

### Пример 4. Проверяем производную численно

Аналитической формуле стоит доверять, но проверять. Численная производная —
универсальный способ поймать ошибку в выводе градиента:

```go
func numGrad(f func(float64) float64, x float64) float64 {
	const h = 1e-6
	return (f(x+h) - f(x-h)) / (2 * h) // центральная разность
}

// f(w) = MSE при фиксированном b; numGrad должен совпасть с формулой (2/N)·Σ eᵢ·xᵢ
```

Если численный и аналитический градиенты расходятся больше чем на 1e-4 — ошибка в
выводе, а не в данных. Этот приём называется gradient checking и экономит часы.

## Итог

Производная — это наклон, градиент — набор наклонов по каждому параметру, а
градиентный спуск — цикл из трёх строк: посчитать ошибку, посчитать градиент, шагнуть
против него. Всё «обучение» линейной регрессии, логистической регрессии и нейросети
устроено одинаково; отличаются только формула ошибки и способ посчитать производную.
Два практических вывода: `α` подбирается экспериментально и уменьшается первым при
расходимости, а аналитический градиент всегда стоит сверить с численным.
