# Карточки

## Базовые правила

```card
front: Правило суммы — формулировка и словесный триггер
back: "Если наборы не пересекаются, число вариантов складывается: m + n. Словесный триггер — «или». Важно: только для непересекающихся наборов."
tags: [правила]
```

```card
front: Правило произведения — формулировка и словесный триггер
back: "Независимые шаги перемножаются: m·n. Словесный триггер — «и». В коде это два вложенных цикла."
tags: [правила]
```

```card
front: Два вопроса, определяющие формулу счёта
back: "1) Важен ли порядок? 2) Разрешены ли повторения? Ответы дают четыре клетки: nᵏ, A(n,k), C(n+k−1,k), C(n,k)."
tags: [правила]
```

```card
front: Чему равно 0! и почему?
back: "0! = 1. Пустую последовательность можно упорядочить ровно одним способом; при этом формулы вроде C(n,n) = n!/(n!·0!) = 1 остаются верными."
tags: [факториал]
```

## Формулы выбора

```card
front: "Порядок важен, повторения разрешены — сколько вариантов?"
back: "nᵏ. Это строка длины k над алфавитом из n символов: пароли, коды, IP-адреса."
tags: [формулы]
```

```card
front: "Размещения A(n,k) — формула и когда применять"
back: "A(n,k) = n!/(n−k)! = n·(n−1)·…·(n−k+1). Порядок важен, повторений нет: призовые места, топ-k с позициями."
tags: [формулы]
```

```card
front: "Сочетания C(n,k) — формула и когда применять"
back: "C(n,k) = n!/(k!(n−k)!) = A(n,k)/k!. Порядок не важен, повторений нет: состав команды, подмножество."
tags: [формулы]
```

```card
front: Почему C(n,k) получается делением A(n,k) на k!
back: "Каждое неупорядоченное подмножество из k элементов посчитано в A(n,k) ровно k! раз — по одному на каждый свой порядок. Приём «посчитать с избытком и поделить на кратность»."
tags: [формулы]
```

```card
front: Симметрия биномиального коэффициента
back: "C(n,k) = C(n, n−k). Выбрать k элементов — то же самое, что выбрать, какие n−k отбросить. В коде используют для сокращения числа итераций."
tags: [формулы]
```

```card
front: Правило Паскаля и его словесное объяснение
back: "C(n,k) = C(n−1,k−1) + C(n−1,k). Фиксируем один элемент: либо он в подмножестве (добираем k−1 из n−1), либо нет (берём k из n−1). Классы не пересекаются — правило суммы."
tags: [паскаль]
```

```card
front: Чему равна сумма строки треугольника Паскаля?
back: "Σ по k от 0 до n от C(n,k) = 2ⁿ — это все подмножества n-элементного множества. Следует из бинома при a = b = 1."
tags: [паскаль]
```

```card
front: Бином Ньютона
back: "(a + b)ⁿ = Σ по k от 0 до n от C(n,k)·a^(n−k)·b^k. Коэффициенты — строка n треугольника Паскаля, потому что a^(n−k)b^k возникает столькими способами, сколькими можно выбрать k скобок, где взяли b."
tags: [паскаль]
```

```card
front: "Как быстро растёт n!? Ориентиры и оценка."
back: "10! ≈ 3.6·10⁶, 20! ≈ 2.4·10¹⁸ (почти предел int64), 70! > 10¹⁰⁰. Формула Стирлинга n! ≈ √(2πn)·(n/e)ⁿ; отсюда log₂(n!) ≈ n·log₂(n/e) и граница Θ(n log n) для сортировки сравнениями."
tags: [факториал]
```

## Продвинутый счёт

```card
front: Перестановки мультимножества
back: "n! / (n₁!·n₂!·…·n_k!), где nᵢ — кратности повторяющихся элементов. Для MISSISSIPPI это 11!/(1!·4!·4!·2!) = 34 650."
tags: [мультимножества]
```

```card
front: "Шары и перегородки — задача и формула"
back: "Разложить k одинаковых предметов по n различимым ящикам: C(n + k − 1, k). Если каждый ящик обязан быть непустым: C(k − 1, n − 1)."
tags: [мультимножества]
```

```card
front: Формула включения-исключения для двух и трёх множеств
back: "Для двух: размер объединения = сумма размеров − размер пересечения. Для трёх: сумма одиночных − сумма всех трёх парных пересечений + тройное пересечение. Знаки чередуются."
tags: [включение-исключение]
```

```card
front: Как правильно считать «хотя бы один»?
back: "Через дополнение: «хотя бы один» = всего − «ни одного». Прямой подсчёт по слагаемым «ровно один», «ровно два» и так далее верен, но длиннее и ошибочнее."
tags: [дополнение]
```

```card
front: "Принцип Дирихле — базовая и усиленная форма"
back: "Базовая: если n объектов разложить по m ящикам и n > m, какой-то ящик содержит ≥ 2 объекта. Усиленная: найдётся ящик с не менее чем ⌈n/m⌉ объектами."
tags: [дирихле]
```

```card
front: Что принцип Дирихле говорит про хеш-функции и что не говорит?
back: "Говорит: при числе входов больше числа возможных хешей коллизия существует гарантированно. Не говорит, когда коллизия станет вероятной — это парадокс дней рождения, и ответ там √N, а не N."
tags: [дирихле]
```

```card
front: Рекуррентность задачи о лестнице (шаги 1 или 2)
back: "F(n) = F(n−1) + F(n−2), база F(0) = 1, F(1) = 1. Приём — классификация по последнему шагу: классы не пересекаются и покрывают всё."
tags: [рекуррентности]
```

```card
front: Числа Каталана — формула и что считают
back: "Cat(n) = C(2n,n)/(n+1). Считают правильные скобочные последовательности, бинарные деревья с n узлами, триангуляции многоугольника."
tags: [рекуррентности]
```

## Прикладное

```card
front: Сколько существует паролей длины 8 из 62 символов и что это значит?
back: "62⁸ ≈ 2.2·10¹⁴. При переборе 10¹⁰ вариантов в секунду это около 6 часов. Каждый дополнительный символ умножает время на 62 — длина сильнее алфавита."
tags: [приложения]
```

```card
front: Сколько конфигураций даёт n булевых feature-флагов?
back: "2ⁿ. Для 12 флагов это 4096 — полностью протестировать невозможно, отсюда pairwise-тестирование и ограничения на сочетания флагов."
tags: [приложения]
```

```card
front: Чем отличается счёт «10 одинаковых задач по 4 воркерам» от «10 различных задач по 4 воркерам»?
back: "Одинаковые — шары и перегородки, C(13,3) = 286. Различные — каждая задача независимо выбирает воркера, 4¹⁰ = 1 048 576."
tags: [приложения]
```

```card
front: Сколько комбинаций даёт матрица тестовых параметров 4 × 3 × 3 × 5?
back: "180 по правилу произведения. Добавление пятого параметра из 4 значений даёт 720 — рост мультипликативный, поэтому полное покрытие быстро становится нереальным."
tags: [приложения]
```

```card
front: Сколько строк длины 5 над алфавитом из 3 букв содержат хотя бы одну букву «a»?
back: "3⁵ − 2⁵ = 243 − 32 = 211. Считаем через дополнение: всего минус те, где «a» не встречается."
tags: [дополнение]
```

```card
front: Почему C(n,k) в коде не считают через факториалы?
back: "Числитель n! переполняется задолго до того, как переполнится сам ответ: C(21,2) = 210, но 21! не помещается в int64. Используют мультипликативную формулу res = res·(n−k+i)/i или динамику по правилу Паскаля."
tags: [код]
```

```card
front: Как перебрать все подмножества n-элементного множества в коде?
back: "Циклом по маске от 0 до 2ⁿ−1: бит i означает «элемент i входит». Это же основа кода для формулы включения-исключения, где знак определяется чётностью bits.OnesCount(mask)."
tags: [код]
```

```card
front: Что даёт math/big для комбинаторики в Go?
back: "big.Int.Binomial(n, k) считает C(n,k) без переполнения (например, C(100,50) ≈ 1.0·10²⁹), а big.Int.MulRange(1, n) даёт n!."
tags: [код, go]
```
