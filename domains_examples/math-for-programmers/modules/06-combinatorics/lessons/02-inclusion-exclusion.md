# Урок 02 — Включения-исключения и «хотя бы один»

## Разогрев

Два приёма, оба про то, что считать «в лоб» не надо:

- **Включение-исключение.** Складываем одиночные, вычитаем парные пересечения, прибавляем
  тройные, и так далее с чередующимися знаками.
- **Дополнение.** «Хотя бы один» = «всего» − «ни одного».

Подробности — во [второй части теории](../theory-2-advanced-counting.md).

## Задача 1. Два множества, наивно и правильно

В базе 10 000 заказов. 3 000 оплачены картой, 2 500 имеют промокод, 800 — и то, и другое.
Сколько заказов «интересны маркетингу», то есть попадают хотя бы в одну категорию?

```text
наивно:  3000 + 2500 = 5500          — заказы с картой И промокодом посчитаны дважды
правильно: 3000 + 2500 − 800 = 4700
```

Проверка структурой: разложим на три непересекающиеся части.

```text
только карта:     3000 − 800 = 2200
только промокод:  2500 − 800 = 1700
и то и другое:                  800
сумма:            2200 + 1700 + 800 = 4700 ✓
```

Второй способ длиннее, но нагляднее, и им полезно перепроверять себя, пока формула не стала
рефлексом. Именно этот счёт делает планировщик БД, оценивая, сколько строк вернёт
`WHERE paid_by_card OR has_promo`.

## Задача 2. Три множества

Сервис за месяц: 600 пользователей открывали приложение (A), 400 совершили покупку (B),
300 обращались в поддержку (C). Пересечения: A∩B = 250, A∩C = 150, B∩C = 100, A∩B∩C = 50.

```text
шаг 1: сложили одиночные        600 + 400 + 300 = 1300
шаг 2: вычли парные             1300 − 250 − 150 − 100 = 800
шаг 3: вернули тройное          800 + 50 = 850
```

Почему тройное возвращается: пользователь из A∩B∩C был посчитан 3 раза на шаге 1 и вычтен
3 раза на шаге 2 (он входит во все три парных пересечения), то есть обнулился. Его нужно
вернуть ровно один раз.

```text
пользователь из ровно 1 множества:  +1                 = 1  ✓
пользователь из ровно 2 множеств:   +1+1 −1            = 1  ✓
пользователь из ровно 3 множеств:   +1+1+1 −1−1−1 +1   = 1  ✓
```

Каждый учтён ровно один раз — формула корректна.

```drill
answer: "4"

```

## Задача 3. «Хотя бы один» в чистом виде

Сколько шестизначных PIN-кодов (цифры 0–9) содержат хотя бы одну цифру 7?

```text
всего кодов:      10⁶ = 1 000 000
без семёрок:      9⁶  = 531 441        — на каждой позиции 9 вариантов
хотя бы одна 7:   1 000 000 − 531 441 = 468 559
```

Прямой подсчёт потребовал бы шести слагаемых вида `C(6,k)·9^(6−k)`. Сравните трудозатраты.

Тот же приём в вероятностной постановке (модуль
[`07-probability`](../../07-probability/index.md)) звучит так: «вероятность хотя бы одного
отказа среди 5 узлов = 1 − (вероятность, что все 5 живы)». Это буквально та же строка.

```drill
type: fill-in
prompt: "Сколько строк длины 4 над алфавитом из 5 символов содержат хотя бы один символ «x»? Считайте через дополнение."
answer: "369"
check: exact
hint: "5⁴ − 4⁴"
```

## Задача 4. Задача о беспорядках (лёгкая версия)

Классика включения-исключения: n писем разложили по n конвертам случайно. Сколько
раскладов, где **ни одно** письмо не попало в свой конверт?

Для n = 4 посчитаем через дополнение и включение-исключение. Пусть Aᵢ — «письмо i попало в
свой конверт».

```text
всего раскладов:                    4! = 24
|Aᵢ| = 3! = 6, таких множеств 4:    4·6 = 24
|Aᵢ∩Aⱼ| = 2! = 2, пар C(4,2) = 6:   6·2 = 12
тройных: C(4,3) = 4, каждое 1! = 1: 4·1 = 4
четверное: 1 расклад:                     1
|A₁∪A₂∪A₃∪A₄| = 24 − 12 + 4 − 1 = 15
ни одного совпадения: 24 − 15 = 9
```

Девять — это правильный ответ (число беспорядков D(4) = 9). Забавный факт: доля таких
раскладов быстро стремится к 1/e ≈ 0.368 и уже при n = 4 равна 9/24 = 0.375.

## Задача 5. Когда формула становится кодом

Для k множеств включение-исключение — это перебор всех непустых подмножеств, то есть цикл
по битовым маскам:

```go
// size(mask) должна возвращать размер пересечения множеств, отмеченных в mask
func unionSize(k int, size func(mask int) int) int {
	total := 0
	for mask := 1; mask < 1<<k; mask++ {
		if bits.OnesCount(uint(mask))%2 == 1 {
			total += size(mask)
		} else {
			total -= size(mask)
		}
	}
	return total
}
```

Обратите внимание на цену: 2ᵏ слагаемых. Для 3–4 множеств это бесплатно, для 20 — уже
миллион вызовов, и именно поэтому в СУБД точную кардинальность объединения не считают, а
оценивают статистикой.

```drill
type: free-form
prompt: "Объясните, почему в формуле включения-исключения знаки обязаны чередоваться. Достаточно рассуждения про элемент, лежащий ровно в t множествах."
answer: "Такой элемент попадает в C(t,1) одиночных слагаемых со знаком «+», в C(t,2) парных со знаком «−», в C(t,3) тройных со знаком «+» и так далее. Итоговый вклад равен C(t,1) − C(t,2) + C(t,3) − …, а по биному Ньютона при a = 1, b = −1 сумма всех C(t,k)·(−1)^k равна нулю, поэтому знакопеременная сумма без нулевого члена равна ровно 1. Значит каждый элемент объединения учтён один раз — но только при чередующихся знаках."
check: manual
```

## Итог

Складывать пересекающиеся множества нельзя — нужно вычитать пересечения, и знаки в формуле
чередуются, потому что элемент из t множеств должен быть учтён ровно один раз. Формулировка
«хотя бы один» — почти всегда сигнал считать дополнение: «всего» минус «ни одного». В коде
включение-исключение превращается в перебор битовых масок ценой 2ᵏ слагаемых, что задаёт
естественную границу применимости. Дальше — [урок 03](./03-counting-in-engineering.md),
где мы применим весь арсенал к инженерным оценкам.
