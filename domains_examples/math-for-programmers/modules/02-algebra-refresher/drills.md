# Упражнения

Считайте на бумаге, а ответ проверяйте подстановкой — это часть навыка, а не
формальность. Задания с `check: manual` проверяет сам решающий: там нужен рассказ или
короткий кусок кода, а не одно число.

## Упрощение и разложение на множители

```drill
type: fill-in
prompt: "Упростите выражение: 5 − (x + 2)"
answer: "3 − x | 3-x | −x + 3 | -x+3"
check: fuzzy
hint: "минус перед скобкой меняет знак каждого слагаемого внутри"
```

```drill
type: fill-in
prompt: "Раскройте скобки: (3x + 2)²"
answer: "9x² + 12x + 4 | 9x^2 + 12x + 4 | 9x2+12x+4"
check: fuzzy
hint: "квадрат суммы: первое в квадрате, плюс удвоенное произведение, плюс второе в квадрате"
```

```drill
type: multiple-choice
prompt: "Чему равно a³ − b³?"
options: ["(a − b)(a² + ab + b²)", "(a − b)(a² − ab + b²)", "(a − b)³", "(a − b)(a + b)(a² + b²)"]
answer: "(a − b)(a² + ab + b²)"
check: exact
hint: "во втором множителе знак середины противоположен знаку первого множителя"
```

```drill
type: fill-in
prompt: "Разложите на множители: x² − 49"
answer: "(x − 7)(x + 7) | (x-7)(x+7) | (x + 7)(x − 7)"
check: fuzzy
hint: "разность квадратов"
```

```drill
type: free-form
prompt: "Проверьте кодом тождество (a − b)³ = a³ − 3a²b + 3ab² − b³: напишите короткий цикл на Go или Python, который перебирает a и b от −20 до 20 и печатает первое расхождение (или сообщение, что расхождений нет)."
answer: "Двойной цикл по a и b с проверкой (a-b)*(a-b)*(a-b) == a*a*a - 3*a*a*b + 3*a*b*b - b*b*b. Расхождений быть не должно: это тождество, оно верно при любых целых a и b."
check: manual
```

## Неравенства

```drill
type: multiple-choice
prompt: "Решите неравенство: −3x ≥ 12"
options: ["x ≥ −4", "x ≤ −4", "x ≥ 4", "x ≤ 4"]
answer: "x ≤ −4"
check: exact
hint: "делим на −3 — отрицательное число"
```

```drill
type: free-form
prompt: "Объясните своими словами, почему при умножении обеих частей неравенства на отрицательное число знак переворачивается. Приведите числовой пример и картинку числовой прямой."
answer: "Умножение на отрицательное число зеркально отражает числовую прямую относительно нуля: то, что было левее, становится правее. Пример: 3 < 5, умножаем на −2, получаем −6 и −10, и −6 > −10. Порядок сохранился бы только при умножении на положительное число."
check: manual
```

## Функции и графики

```drill
type: multiple-choice
prompt: "Какова область определения функции f(x) = √(x − 3)/(x − 5)?"
options: ["все числа", "x ≥ 3", "x ≥ 3 и x ≠ 5", "x > 5"]
answer: "x ≥ 3 и x ≠ 5"
check: exact
hint: "под корнем неотрицательное, знаменатель не ноль"
```

```drill
type: free-form
prompt: "Не пользуясь калькулятором, нарисуйте от руки графики y = 2x − 1, y = x², y = 1/x и y = abs(x) на одном листе. Отметьте у каждого точку пересечения с осями, асимптоты (если есть) и скажите, где функция растёт, а где убывает."
answer: "Прямая: пересекает оси в (0.5, 0) и (0, −1), растёт всюду. Парабола: вершина (0, 0), убывает при x < 0, растёт при x > 0. Гипербола: асимптоты x = 0 и y = 0, убывает на каждой из двух ветвей, в нуле не определена. Модуль: излом в (0, 0), убывает при x < 0, растёт при x > 0, значения всегда неотрицательны."
check: manual
```

## Экспонента и логарифм

```drill
type: fill-in

answer: "3"

hint: "разность логарифмов — это логарифм частного"
```

```drill
type: fill-in
prompt: "Сколько бит нужно, чтобы закодировать 50 000 различных значений? В ответе только число."
answer: "16"
check: exact
hint: "нужно наименьшее b, при котором 2ᵇ ≥ 50000; 2¹⁵ = 32768"
```

```drill
type: free-form
prompt: "Объясните, почему в записи сложности бинарного поиска O(log n) не указывают основание логарифма. Приведите формулу, из которой это следует, и посчитайте, во сколько раз log₂ n больше, чем ln n."
answer: "Из формулы перехода к другому основанию log_a n = log_b n / log_b a: логарифмы по разным основаниям отличаются множителем 1/log_b a, который не зависит от n. Значит это одна и та же скорость роста с точностью до константы. log₂ n = ln n / ln 2 ≈ 1.4427 · ln n."
check: manual
```
