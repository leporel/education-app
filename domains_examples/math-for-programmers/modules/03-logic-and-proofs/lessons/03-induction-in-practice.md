# Урок 03 — Индукция на практике: формула и инвариант цикла

## Разогрев

Из [`theory-2-proof-techniques.md`](../theory-2-proof-techniques.md):

- Индукция доказывает `∀n ≥ n₀ P(n)` двумя шагами: **база** `P(n₀)` и **переход**
  `P(k) ⇒ P(k+1)`.
- Переход — это импликация, поэтому «предположение индукции» ничего не предполагает
  о реальности: оно условное.
- База ↔ состояние до цикла, переход ↔ тело цикла, вывод ↔ инвариант после цикла.

Сегодня прогоняем это два раза: сначала на формуле, потом на настоящем коде.

## Новая тема

### Шаг 1. Сначала проверить, потом доказывать

Возьмём утверждение `P(n)`: `1 + 2 + … + n = n(n+1)/2` для всех `n ≥ 1`.

Прежде чем что-то доказывать, полезно убедиться, что доказывать есть что. Тридцать
секунд работы:

```go
for n := 1; n <= 10000; n++ {
	sum := 0
	for i := 1; i <= n; i++ {
		sum += i
	}
	if sum != n*(n+1)/2 {
		fmt.Println("counterexample at n =", n)
		return
	}
}
fmt.Println("holds for n = 1..10000")
```

Если бы в формуле была опечатка — например, `n(n-1)/2` — код нашёл бы это на первом же
`n`. Перебор не доказывает утверждение (мы это разбирали на примере `n² + n + 41`), но
он мгновенно ловит ошибки в самой формулировке. Доказывать заведомо ложное — обидная
трата вечера.

### Шаг 2. Доказательство индукцией

```text
База, n = 1:
  левая часть  = 1
  правая часть = 1·(1 + 1)/2 = 2/2 = 1
  совпало ⇒ P(1) верно

Переход. Предположим P(k): 1 + 2 + … + k = k(k+1)/2. Цель — P(k+1),
то есть 1 + 2 + … + (k+1) = (k+1)(k+2)/2.

  1 + 2 + … + k + (k+1)
  = k(k+1)/2 + (k+1)          — подставили предположение индукции
  = k(k+1)/2 + 2(k+1)/2       — привели (k+1) к знаменателю 2
  = (k(k+1) + 2(k+1))/2       — сложили дроби
  = (k+1)(k + 2)/2            — вынесли общий множитель (k+1)
  = (k+1)((k+1) + 1)/2        — переписали k+2 как (k+1)+1

Это ровно P(k+1). База и переход доказаны ⇒ P(n) верно для всех n ≥ 1.
```

Стоит на секунду задержаться на строке «подставили предположение индукции». Это
единственное место, где база и переход соединяются в цепочку: мы взяли доказанное для
`k` и втащили его внутрь выражения для `k+1`. Всё остальное — обычная школьная алгебра
из модуля [`02-algebra-refresher`](../../02-algebra-refresher/index.md): общий
знаменатель, сложение дробей, вынесение множителя.

Два приёма, которые делают переход механическим:

1. **Выпишите цель заранее.** Прежде чем преобразовывать, напишите, как должна выглядеть
   `P(k+1)`. Тогда вы преобразуете *к чему-то*, а не *куда-нибудь*.
2. **Найдите место, где подставлено предположение.** Если во всей цепочке нет строки
   «подставили предположение индукции» — вы доказали что-то другое, но не переход.

### Шаг 3. Тот же приём на цикле

Теперь настоящий код — линейный поиск:

```go
func contains(xs []int, target int) bool {
	for i := 0; i < len(xs); i++ {
		if xs[i] == target {
			return true
		}
	}
	return false
}
```

Функция выглядит правильной, но «выглядит» — не аргумент на код-ревью.
Сформулируем **инвариант** — утверждение, истинное перед каждой итерацией:

```text
I(i): target не встречается среди xs[0], …, xs[i-1]
```

При `i = 0` отрезок пустой, и `I(0)` — это `∀x ∈ ∅ (x ≠ target)`, то есть истина
впустую (то самое `∀` по пустому множеству из [`theory.md`](../theory.md)).

Доказываем индукцией по числу выполненных итераций:

```text
База, i = 0:
  отрезок xs[0..-1] пуст, target в нём не встречается ⇒ I(0) верно

Переход. Пусть I(i) верно и цикл выполняет итерацию с индексом i:
  Случай A: xs[i] == target
    цикл возвращает true. Это корректно: свидетель предъявлен,
    ∃j xs[j] == target истинно. Инвариант дальше не нужен.
  Случай B: xs[i] != target
    по предположению target нет среди xs[0..i-1];
    только что проверили, что его нет и на позиции i;
    значит, его нет среди xs[0..i] ⇒ I(i+1) верно
  Других случаев нет: сравнение либо истинно, либо ложно.

Выход из цикла при i = len(xs):
  I(len(xs)) означает: target нет среди xs[0..len(xs)-1], то есть нигде.
  Функция возвращает false — корректно.
```

Вот и всё доказательство корректности. Обратите внимание, что оно состоит из тех же
кусков, что и доказательство формулы: база, переход, разбор случаев внутри перехода
и отдельный вывод в конце.

Практическая ценность этой процедуры не в самом доказательстве — в поиске места, где
рассуждение не сходится. Попробуйте прогнать те же три шага для кода с `i <= len(xs)`
вместо `i < len(xs)`: база и переход пройдут без единой заминки, а вот на последней
итерации вы упрётесь в обращение к `xs[len(xs)]`, которого не существует. Off-by-one
всегда всплывает на границе — либо в базе, либо в выходе из цикла, — и аккуратно
выписанный инвариант приводит вас туда за минуту, без отладчика и без запуска тестов.

И ещё один кусочек, о котором в коде забывают чаще всего — **завершаемость**. Индукция
доказала, что *если* цикл закончится, ответ будет правильным. Что он закончится, нужно
показать отдельно: величина `len(xs) - i` — целая, неотрицательная и строго убывает на
каждой итерации, а строго убывающая последовательность неотрицательных целых не может
быть бесконечной. Ровно этот же аргумент вы приводите (обычно неформально), когда
объясняете в PR, почему цикл не зациклится.

## Итог

Индукция состоит из двух обязательных частей: база (подстановка стартового значения) и
переход (`P(k) ⇒ P(k+1)`, где предположение обязано быть реально использовано). Порядок
работы на практике: сначала проверить формулу перебором на маленьких значениях, потом
выписать цель `P(k+1)`, потом преобразовывать к ней. Инвариант цикла — та же индукция,
только записанная про состояние программы: база — состояние перед входом, переход —
одна итерация, вывод — то, что верно после выхода. И отдельно доказывается
завершаемость: должна быть неотрицательная целая величина, строго убывающая на каждой
итерации.
