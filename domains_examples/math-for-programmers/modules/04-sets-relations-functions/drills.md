# Упражнения

Считать можно на бумаге, но каждый численный ответ полезно перепроверить кодом —
`set` в Python или `map[T]struct{}` в Go занимают три строки.



## Объясните и проверьте кодом

```drill
type: free-form
prompt: "Объясните своими словами, почему |P(A)| = 2ⁿ, где n = |A|. Используйте аналогию с битовой маской и покажите разбор для A = {a, b, c}."
answer: "Подмножество однозначно кодируется битовой маской длины n: по каждому элементу независимое решение «взять / не взять». Независимых двоичных решений n штук, значит комбинаций 2ⁿ. Для A = {a, b, c} маски 000..111 дают 8 подмножеств: ∅, {a}, {b}, {c}, {a,b}, {a,c}, {b,c}, {a,b,c}."
check: manual
```

```drill
type: free-form
prompt: "Проверьте кодом формулу |A ∪ B| = |A| + |B| − |A ∩ B| хотя бы на трёх разных парах множеств, включая случай непересекающихся множеств и случай A ⊆ B. Приведите код и вывод."
answer: "Например, на Python: A, B = {1,2,3}, {3,4}; len(A|B) == len(A) + len(B) - len(A&B). Для непересекающихся пересечение пустое и формула вырождается в сумму. Для A ⊆ B пересечение равно A, и результат равен |B|."
check: manual
hint: "в Python множества встроены: | это ∪, & это ∩, - это разность"
```

```drill
type: free-form
prompt: "Объясните, почему хеш-функция принципиально не может быть инъективной, и почему из этого НЕ следует, что она плохая."
answer: "Входов бесконечно много (строки любой длины), а выходов конечное число (например, 2⁶⁴). Инъекция из бесконечного множества в конечное невозможна, поэтому коллизии неизбежны. От хеша требуется не инъективность, а равномерность и дешевизна: чтобы коллизии были редкими и непредсказуемыми."
check: manual
hint: "сравните мощности области определения и области прибытия"
```

```drill
type: free-form
prompt: "Компаратор сортировки задан как less(x, y) = x.Priority < y.Priority. Объясните, какой порядок он на самом деле задаёт, почему результат сортировки становится невоспроизводимым и какие есть два способа это починить."
answer: "Элементы с равным Priority несравнимы ни в одну сторону, значит это частичный, а не линейный порядок. Их взаимное расположение алгоритм выбирает произвольно, поэтому один и тот же вход может дать разный вывод. Починка: либо добавить вторичный ключ (например, ID) и сделать порядок линейным, либо использовать стабильную сортировку, которая сохраняет исходный порядок «равных»."
check: manual
```

```drill
type: free-form
prompt: "У пользователя текущий набор прав C, у новой роли — набор N. Запишите через операции над множествами: что выдать, что отобрать, что не трогать и как одной операцией получить полный список изменений. Приведите Go-код на map[string]struct{}."
answer: "Выдать: N \\ C. Отобрать: C \\ N. Не трогать: C ∩ N. Полный список изменений: C △ N = (C \\ N) ∪ (N \\ C). В коде — три цикла по мапам с проверкой наличия ключа во второй мапе."
check: manual
hint: "разность несимметрична, и в этом весь смысл задачи"
```
