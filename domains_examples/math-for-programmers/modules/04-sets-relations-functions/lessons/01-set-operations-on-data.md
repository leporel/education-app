# Урок 01 — Операции над множествами на живых данных

## Разогрев

Три вещи из [`theory.md`](../theory.md), без которых урок не поедет:

- `x ∈ A` — «x лежит в A». В Go это `_, ok := m[x]`.
- `A \ B` — «то, что есть в A и чего нет в B». Несимметрично.
- `A △ B` — «то, что ровно в одном из двух». Это XOR, он же «что изменилось».

## Новая тема: права как множества

Возьмём задачу, которая в том или ином виде есть в каждом бэкенде. У пользователя
сейчас есть набор прав. Ему назначают новую роль со своим набором прав. Нужно
понять, какие права **выдать**, какие **отобрать**, а какие оставить в покое —
и не сделать при этом лишних запросов в базу.

Первый импульс — написать цикл в цикле и три флага. Второй, более здоровый —
заметить, что и то, и другое здесь множества, и вопрос уже решён математикой.

```text
C = текущие права пользователя          (Current)
N = права новой роли                    (New)

выдать    = N \ C     — нужны, но их ещё нет
отобрать  = C \ N     — есть, но больше не нужны
оставить  = C ∩ N     — есть и нужны, трогать не надо
изменения = C △ N     — полный diff одной операцией
```

Обратите внимание на симметрию задачи и несимметрию операции: «выдать» и
«отобрать» — это одна и та же разность, просто с переставленными аргументами.
Перепутать местами `C` и `N` здесь — не опечатка, а инцидент безопасности: вместо
выдачи прав вы их снимете (или наоборот). Проговорите вслух: *разность идёт от того,
что у нас есть, к тому, чего у нас нет*.

## Разобранные примеры

### Пример 1. Смена роли

```text
C = {read, write, deploy}
N = {read, write, review}

выдать   = N \ C:
   read   ∈ C → пропускаем
   write  ∈ C → пропускаем
   review ∉ C → берём
   = {review}

отобрать = C \ N:
   read   ∈ N → пропускаем
   write  ∈ N → пропускаем
   deploy ∉ N → берём
   = {deploy}

оставить = C ∩ N = {read, write}
изменения = C △ N = {deploy} ∪ {review} = {deploy, review}
```

Проверка мощностей — заодно тренировка формулы включения-исключения:

```text
|C| = 3, |N| = 3, |C ∩ N| = 2
|C ∪ N| = |C| + |N| − |C ∩ N|
        = 3 + 3 − 2                  — подставили
        = 4                          — всего различных прав фигурирует четыре
|C △ N| = |C ∪ N| − |C ∩ N| = 4 − 2 = 2   — ровно две операции изменения
```

Две операции изменения — значит, ровно два запроса на запись, а не шесть.

### Пример 2. Кто есть кто среди пользователей

Пусть `A` — множество id пользователей с ролью `admin`, `B` — с ролью `billing`.

```text
A = {u1, u2, u3, u5}
B = {u2, u5, u7}

A ∩ B = {u2, u5}       — есть обе роли
A \ B = {u1, u3}       — админы без биллинга
B \ A = {u7}           — биллинг без админки
A ∪ B = {u1,u2,u3,u5,u7}
|A ∪ B| = 4 + 3 − 2 = 5    — сходится с перечислением
```

Формулировки задач переводятся почти дословно: «у кого есть роль A, но нет B» —
`A \ B`; «у кого есть обе» — `A ∩ B`; «у кого хотя бы одна» — `A ∪ B`;
«у кого ровно одна» — `A △ B`.


## В коде: Go-множество и три операции

Множество в Go — это `map[T]struct{}`: `struct{}` не занимает памяти, поэтому платим
только за ключи.

```go
type Set map[string]struct{}

func NewSet(items ...string) Set {
    s := make(Set, len(items))
    for _, it := range items {
        s[it] = struct{}{}
    }
    return s
}

func (s Set) Has(x string) bool { _, ok := s[x]; return ok } // x ∈ s

func (s Set) Diff(o Set) Set { // s \ o
    r := make(Set)
    for x := range s {
        if !o.Has(x) {
            r[x] = struct{}{}
        }
    }
    return r
}
```

Сама задача про роли после этого умещается в четыре строки — и читается как
исходная формулировка:

```go
current := NewSet("read", "write", "deploy")
next := NewSet("read", "write", "review")

toGrant := next.Diff(current)  // N \ C — выдать
toRevoke := current.Diff(next) // C \ N — отобрать
fmt.Println(len(toGrant), len(toRevoke)) // 1 1
```

Две детали, на которых спотыкаются:

1. **`nil`-мапа.** `var s Set` читается нормально, но при записи паникует. Пустое
   множество — это `make(Set)`, а не объявление переменной.
2. **Порядок обхода.** `for x := range m` в Go намеренно рандомизирован. Это честное
   отражение того, что у множества нет порядка. Нужен стабильный вывод в лог или
   в API — соберите ключи в слайс и отсортируйте.

```drill
type: free-form
prompt: "Напишите на Go функцию SymDiff(a, b Set) Set через уже готовые Diff и Union и объясните, почему её результат — это ровно «список изменений» при смене роли."
answer: "func (s Set) SymDiff(o Set) Set { return s.Diff(o).Union(o.Diff(s)) }. C △ N = (C \\ N) ∪ (N \\ C) — это объединение того, что надо отобрать, и того, что надо выдать, то есть полный набор прав, состояние которых меняется."
check: manual
```

## Почему не слайсы

Соблазн держать права слайсом велик: их мало, порядок «вроде бы» нужен для вывода.
Но операция «есть ли `x` в слайсе» — это линейный поиск, и любая из наших четырёх
операций превращается во вложенный цикл. Сравните:

```text
слайсы:    для каждого из |C| прав пробегаем весь N   → порядка |C| · |N| сравнений
множества: для каждого из |C| прав одна проверка Has  → порядка |C| + |N| операций
```

На десяти правах разницы не заметно, на десяти тысячах пользователей в цикле —
заметно очень. Плюс слайс не защищает от дублей: `[]string{"read", "read"}` — валидный
слайс и невалидное множество, и такой дубль спокойно доедет до запроса в базу.
Правило простое: если единственный вопрос к коллекции — «есть ли здесь x», это
множество, и хранить его надо как множество.

Отдельно про универсум. Иногда нужен вопрос «какие права вообще никому не выданы» —
это дополнение: `U \ (объединение всех наборов)`, где `U` — список всех известных
системе прав. Без явного `U` вопрос не имеет смысла, и это хороший повод завести
такой список константой рядом с определением прав, а не собирать его из данных.

```drill
type: free-form
prompt: "Проверьте кодом, что для ваших C и N выполняется |C ∪ N| = |C| + |N| − |C ∩ N|, и объясните, почему без вычитания пересечения ответ был бы завышен."
answer: "Элементы из C ∩ N входят и в |C|, и в |N|, поэтому при простом сложении считаются дважды. Вычитание |C ∩ N| убирает ровно один лишний подсчёт каждого общего элемента."
check: manual
```

## Итог

Задачи «кто есть, кого нет, что выдать, что отобрать» — это не задачи на циклы,
а задачи на четыре операции: `∪`, `∩`, `\`, `△`. Разность несимметрична, и именно
её направление кодирует смысл: `N \ C` — выдать, `C \ N` — отобрать. Симметрическая
разность `C △ N` даёт полный список изменений одной операцией. В Go всё это —
`map[T]struct{}` и три коротких метода; помните про `make` вместо `nil` и про то, что
порядок обхода множества не определён. Мощности считайте по включению-исключению:
`|A ∪ B| = |A| + |B| − |A ∩ B|` — это и оценка числа записей в базу, и способ
проверить себя.
