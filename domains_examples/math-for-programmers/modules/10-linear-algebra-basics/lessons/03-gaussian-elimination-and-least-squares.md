# Урок 03 — Метод Гаусса и прямая по методу наименьших квадратов

## Разогрев

- Система записывается как `A·x = b`.
- Элементарные операции: поменять строки, умножить строку на число ≠ 0, прибавить к
  строке другую, умноженную на число.
- Цель прямого хода — треугольный вид; дальше обратный ход снизу вверх.
- Переопределённая система (уравнений больше, чем неизвестных) решается через
  `AᵀA·x = Aᵀb`.

Теория — [`theory-2-matrices.md`](../theory-2-matrices.md).

## Новая тема: две очень похожие задачи

Первая задача — **точная**: есть ровно столько уравнений, сколько неизвестных, решение
существует и единственно. Это метод Гаусса.

Вторая — **приближённая**: измерений много, они шумные, точного решения нет, и нужно
«как можно ближе». Это метод наименьших квадратов. И вот что приятно: вторая задача
сводится к первой одним умножением на `Aᵀ`.

Практический пример, где обе встречаются в одном тикете: «по трём замерам подобрать
коэффициенты формулы стоимости запроса» (точная система) и «по сотне замеров построить
тренд роста базы» (наименьшие квадраты).

## Разобранные примеры

### Пример 1. Метод Гаусса на системе 3×3

Задача: латентность запроса складывается из фиксированной части, части на строку и
части на джойн. Три замера дали систему

```text
 x + 2y +  z = 8
2x +  y −  z = 1
3x −  y + 2z = 7
```

Пишем расширенную матрицу и убираем `x` из второй и третьей строк.

```text
[ 1   2   1 |  8 ]
[ 2   1  −1 |  1 ]
[ 3  −1   2 |  7 ]

R2 ← R2 − 2·R1        — коэффициент 2, потому что в R2 стоит 2x, а в R1 стоит 1x
[ 1   2   1 |   8 ]
[ 0  −3  −3 | −15 ]
[ 3  −1   2 |   7 ]

R3 ← R3 − 3·R1        — в R3 стоит 3x
[ 1   2   1 |   8 ]
[ 0  −3  −3 | −15 ]
[ 0  −7  −1 | −17 ]

R2 ← R2 / (−3)        — приводим ведущий элемент к единице, числа становятся приятнее
[ 1   2   1 |   8 ]
[ 0   1   1 |   5 ]
[ 0  −7  −1 | −17 ]

R3 ← R3 + 7·R2        — убираем y из третьей строки
[ 1   2   1 |  8 ]
[ 0   1   1 |  5 ]
[ 0   0   6 | 18 ]    — треугольный вид готов
```

Обратный ход:

```text
6z = 18        ⇒ z = 3
y + z = 5      ⇒ y = 5 − 3 = 2
x + 2y + z = 8 ⇒ x = 8 − 2·2 − 3 = 1

проверка в исходном втором уравнении: 2·1 + 2 − 3 = 1 ✓
проверка в третьем: 3·1 − 2 + 2·3 = 3 − 2 + 6 = 7 ✓
```

Ответ: `(x, y, z) = (1, 2, 3)`.

### Пример 2. Что если решения нет или их бесконечно много

Возьмём систему, где второе уравнение — удвоенное первое:

```text
 x + y = 3
2x + 2y = 7

[ 1  1 | 3 ]
[ 2  2 | 7 ]

R2 ← R2 − 2·R1
[ 1  1 | 3 ]
[ 0  0 | 1 ]          — «0 = 1», противоречие
```

Решений нет: прямые параллельны. Если бы правая часть была `6`, последняя строка стала
бы `0 0 | 0` — прямые совпали бы, и решений было бы бесконечно много (`y` свободна,
`x = 3 − y`). Три случая из школьной геометрии никуда не делись, просто теперь их видно
по виду матрицы.

### Пример 3. Прямая по методу наименьших квадратов

Данные роста таблицы: `(1, 2), (2, 3), (3, 5)` — месяц и размер в ГБ. Ищем `y = kx + b`.

```text
A = [ 1  1 ]      x = [ k ]      b = [ 2 ]
    [ 2  1 ]          [ b ]          [ 3 ]
    [ 3  1 ]                         [ 5 ]
```

Три уравнения, две неизвестные — точки не лежат на одной прямой, точного решения нет.
Умножаем обе части на `Aᵀ`:

```text
AᵀA = [ 1  2  3 ]·[ 1  1 ] = [ 1+4+9   1+2+3 ] = [ 14   6 ]
      [ 1  1  1 ] [ 2  1 ]   [ 1+2+3   1+1+1 ]   [  6   3 ]
                  [ 3  1 ]

Aᵀb = [ 1  2  3 ]·[ 2 ] = [ 1·2 + 2·3 + 3·5 ] = [ 23 ]
      [ 1  1  1 ] [ 3 ]   [ 1·2 + 1·3 + 1·5 ]   [ 10 ]
                  [ 5 ]
```

Получили обычную систему 2×2, решаем тем же Гауссом:

```text
14k + 6b = 23
 6k + 3b = 10

R2 ← R2 · 2            — уравниваем коэффициент при b
12k + 6b = 20
R1 ← R1 − R2
 2k = 3       ⇒ k = 1.5
6·1.5 + 3b = 10 ⇒ 9 + 3b = 10 ⇒ b = 1/3 ≈ 0.3333

прямая: y = 1.5x + 0.3333
```

Проверим качество подгонки:

```text
x=1: 1.5 + 0.333 = 1.833   против 2   — отклонение −0.167
x=2: 3.0 + 0.333 = 3.333   против 3   — отклонение +0.333
x=3: 4.5 + 0.333 = 4.833   против 5   — отклонение −0.167
сумма отклонений = −0.167 + 0.333 − 0.167 = 0   — так и должно быть у МНК-прямой
сумма квадратов = 0.0278 + 0.1111 + 0.0278 = 0.1667 — минимально возможная
```

Нулевая сумма отклонений — не совпадение: она следует из второго нормального уравнения
(строки `Aᵀ`, состоящей из единиц). Хорошая быстрая проверка, что вы не ошиблись в
арифметике.

### Пример 4. То же самое в Go

```go
// Прямая y = kx + b по методу наименьших квадратов, замкнутая формула для 2 неизвестных.
func fitLine(xs, ys []float64) (k, b float64, err error) {
	if len(xs) != len(ys) || len(xs) < 2 {
		return 0, 0, fmt.Errorf("fitLine: need equal slices of length >= 2")
	}
	n := float64(len(xs))
	var sx, sy, sxx, sxy float64
	for i := range xs {
		sx += xs[i]          // Σx
		sy += ys[i]          // Σy
		sxx += xs[i] * xs[i] // Σx²  — это элемент AᵀA
		sxy += xs[i] * ys[i] // Σxy  — это элемент Aᵀb
	}
	den := n*sxx - sx*sx // определитель AᵀA
	if den == 0 {
		return 0, 0, fmt.Errorf("fitLine: degenerate data, all x are equal")
	}
	k = (n*sxy - sx*sy) / den
	b = (sy - k*sx) / n
	return k, b, nil
}

// fitLine([]float64{1,2,3}, []float64{2,3,5}) → k = 1.5, b = 0.3333
```

Обратите внимание на `den == 0`: это ровно `det(AᵀA) = 0` из теории. Если все `x`
одинаковы, прямую провести нельзя, и честная ошибка лучше, чем `NaN` в отчёте.

Для больших систем не пишите Гаусса руками — берите `gonum`:
`mat.Solve(&x, a, b)` решает `A·x = b` устойчиво и быстро, а `mat.NewDense` строит матрицы
из плоских срезов.

## Итог

Метод Гаусса — это школьный метод сложения, записанный по шагам: обнуляем под
диагональю, получаем треугольник, идём обратным ходом снизу вверх. Вид итоговой матрицы
сразу говорит, сколько решений: противоречивая строка — ноль, лишний нулевой ряд —
бесконечность, полный треугольник — одно. Метод наименьших квадратов — та же задача
после умножения на `Aᵀ`: `AᵀA·x = Aᵀb` превращает сотню шумных измерений в маленькую
систему, а её решение минимизирует сумму квадратов отклонений. Именно так строится любая
линия тренда — и в отчёте по росту базы, и в линейной регрессии.
