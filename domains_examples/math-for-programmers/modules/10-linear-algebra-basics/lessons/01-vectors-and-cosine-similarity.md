# Урок 01 — Векторы, скалярное произведение и косинусная близость на игрушечных embeddings

## Разогрев

- `‖v‖₂ = √(Σ vᵢ²)` — длина; `d(v, w) = ‖v − w‖` — расстояние.
- `v · w = Σ vᵢwᵢ` — скалярное произведение, число.
- `v · w = 0` ⇔ ортогональны.
- `cos(v, w) = (v · w)/(‖v‖·‖w‖)` — из `[−1, 1]`.

Теория — [`theory.md`](../theory.md).

## Новая тема: строим мини-поиск по смыслу

Задача урока — собрать руками то, что внутри любой векторной базы. Возьмём четыре
«документа» и опишем каждый пятью признаками. Настоящий энкодер выдал бы 768 чисел и
никто бы не знал, что они значат; мы возьмём пять и назовём их честно:

```text
признаки: (база данных, производительность, сеть, фронтенд, безопасность)

d₁ = (0.9, 0.6, 0.1, 0.0, 0.1)   — «Как читать план EXPLAIN в Postgres»
d₂ = (0.2, 0.7, 0.9, 0.0, 0.2)   — «Настройка TCP keepalive под нагрузкой»
d₃ = (0.0, 0.3, 0.1, 0.9, 0.1)   — «CSS Grid за 10 минут»
d₄ = (0.7, 0.2, 0.1, 0.0, 0.8)   — «Права доступа в PostgreSQL»
```

И запрос: «почему запрос к базе выполняется медленно».

```text
q = (0.8, 0.9, 0.1, 0.0, 0.0)
```

По-человечески ожидаем: `d₁` — точное попадание, `d₄` — «тоже про базу, но про другое»,
`d₂` — «тоже про производительность, но про сеть», `d₃` — мимо. Посмотрим, выдаст ли
математика то же самое.

## Разобранные примеры

### Пример 1. Скалярные произведения

```text
q · d₁ = 0.8·0.9 + 0.9·0.6 + 0.1·0.1 + 0 + 0
       = 0.72 + 0.54 + 0.01 = 1.27
q · d₂ = 0.8·0.2 + 0.9·0.7 + 0.1·0.9 + 0 + 0
       = 0.16 + 0.63 + 0.09 = 0.88
q · d₃ = 0.8·0.0 + 0.9·0.3 + 0.1·0.1 + 0 + 0
       = 0 + 0.27 + 0.01 = 0.28
q · d₄ = 0.8·0.7 + 0.9·0.2 + 0.1·0.1 + 0 + 0
       = 0.56 + 0.18 + 0.01 = 0.75
```

Порядок по «сырому» произведению: `d₁ (1.27) > d₂ (0.88) > d₄ (0.75) > d₃ (0.28)`.

### Пример 2. Нормируем — и порядок меняется

Длины документов разные, а это влияет на сырое произведение. Посчитаем нормы:

```text
‖q‖  = √(0.64 + 0.81 + 0.01) = √1.46 ≈ 1.2083
‖d₁‖ = √(0.81 + 0.36 + 0.01 + 0 + 0.01) = √1.19 ≈ 1.0909
‖d₂‖ = √(0.04 + 0.49 + 0.81 + 0 + 0.04) = √1.38 ≈ 1.1747
‖d₃‖ = √(0 + 0.09 + 0.01 + 0.81 + 0.01) = √0.92 ≈ 0.9592
‖d₄‖ = √(0.49 + 0.04 + 0.01 + 0 + 0.64) = √1.18 ≈ 1.0863
```

```text
cos(q, d₁) = 1.27 / (1.2083 · 1.0909) = 1.27 / 1.3182 ≈ 0.963
cos(q, d₂) = 0.88 / (1.2083 · 1.1747) = 0.88 / 1.4194 ≈ 0.620
cos(q, d₃) = 0.28 / (1.2083 · 0.9592) = 0.28 / 1.1590 ≈ 0.242
cos(q, d₄) = 0.75 / (1.2083 · 1.0863) = 0.75 / 1.3126 ≈ 0.571
```

Итог: `d₁ (0.963) > d₂ (0.620) > d₄ (0.571) > d₃ (0.242)`.

Здесь порядок совпал с сырым произведением, но обратите внимание на разрыв: `d₂` и `d₄`
почти сравнялись, потому что `d₂` — «длинный» вектор и косинус срезал его преимущество.
На реальных данных, где длина вектора отражает объём текста, такие перестановки
происходят постоянно. Косинус спрашивает «про то же самое?», а сырое произведение —
«про то же самое и как много об этом сказано?».

### Пример 3. Ортогональность как «разные темы»

Возьмём два искусственных документа:

```text
a = (1, 0, 0, 0, 0)   — чистая «база данных»
b = (0, 0, 0, 1, 0)   — чистый «фронтенд»
a · b = 0             — ни одна компонента не перекрывается
cos(a, b) = 0         — угол ровно 90°
```

Ортогональность в пространстве смыслов означает «эти документы не пересекаются вообще».
Именно поэтому базисные оси удобно интерпретировать как независимые темы.

### Пример 4. Реализация и проверка в Go

```go
func dot(a, b []float64) (float64, error) {
	if len(a) != len(b) {
		return 0, fmt.Errorf("dot: dimension mismatch %d vs %d", len(a), len(b))
	}
	sum := 0.0
	for i := range a {
		sum += a[i] * b[i]
	}
	return sum, nil
}

func cosine(a, b []float64) (float64, error) {
	ab, err := dot(a, b)
	if err != nil {
		return 0, err
	}
	aa, _ := dot(a, a) // ошибка невозможна: длины совпадают по построению
	bb, _ := dot(b, b)
	den := math.Sqrt(aa) * math.Sqrt(bb)
	if den == 0 {
		return 0, nil // нулевой вектор не имеет направления
	}
	return ab / den, nil
}

func topK(q [][]float64, docs [][]float64, k int) []int { /* сортировка по cosine */ }
```

Проверка размерностей — не педантизм: несовпадение длин здесь означает, что в индекс
попал вектор от другой версии модели, и без явной ошибки вы получите тихо неправильную
выдачу.

## Итог

Вектор — это список чисел, скалярное произведение — один цикл, косинусная близость —
то же произведение, поделённое на длины. На этих трёх строчках держится весь
семантический поиск: превратить объект в вектор, нормализовать, отсортировать по
скалярному произведению. Главный практический вывод урока — понимать, **что именно
измеряет ваша метрика**: сырое произведение учитывает и направление, и длину; косинус —
только направление. Выбор между ними определяет, что вылезет в топ.
