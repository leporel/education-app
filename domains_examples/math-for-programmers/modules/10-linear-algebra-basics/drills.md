## Блок 4. Объяснить своими словами

```drill
type: free-form
prompt: "Объясните коллеге, почему умножение матриц некоммутативно, приведя пример из графики, где перепутанный порядок даёт видимый баг."
answer: "A·B значит «сначала B, потом A», как композиция функций. Пример: поворот на 90° и растяжение по x вдвое. R·S = [[0,−1],[2,0]], S·R = [[0,−2],[1,0]] — разные матрицы. В графике «повернуть, потом перенести» и «перенести, потом повернуть» отличаются: во втором случае объект уезжает по дуге вокруг начала координат."
check: manual
```

```drill
type: free-form
prompt: "Вы строите поиск по embeddings. Объясните, зачем нормализовать векторы при вставке в индекс и что это даёт по производительности."
answer: "После нормализации ‖v‖ = 1, поэтому косинусная близость сводится к скалярному произведению: не нужно на каждом запросе считать две нормы и делить. Кроме того, ‖v − w‖² = 2 − 2·(v·w), значит порядок по косинусу и по евклидову расстоянию совпадает и индекс может использовать любую из метрик. Нормализация делается один раз при вставке вместо каждого сравнения."
check: manual
```

```drill
type: free-form
prompt: "Объясните смысл определителя человеку, который никогда его не считал: что он измеряет, что означают значения 1, 3, −2 и 0."
answer: "Определитель — коэффициент изменения площади (в 3D — объёма) при преобразовании. det = 1 — площадь сохранилась (поворот); det = 3 — фигуры раздулись втрое; det = −2 — раздулись вдвое и пространство вывернулось (отражение); det = 0 — площадь схлопнулась в ноль, информация потеряна, обратного преобразования не существует."
check: manual
```

```drill
type: free-form
prompt: "Опишите идею PageRank через собственные векторы: что за матрица, что за вектор, почему λ = 1 и как это считают на практике."
answer: "M — матрица переходов, Mᵢⱼ есть вероятность перейти со страницы j на страницу i. Вектор p — распределение «где сейчас случайный сёрфер». Устойчивое распределение не меняется после шага, то есть M·p = p — собственный вектор с собственным значением 1. На практике считают степенным методом: стартуют с равномерного p и повторяют p ← M·p с нормализацией до сходимости."
check: manual
```

```drill
type: free-form
prompt: "Реализуйте на Go умножение матрицы на вектор с проверкой размерностей и объясните, почему в горячем коде матрицу лучше хранить плоским срезом, а не [][]float64."
answer: "Функция должна возвращать ошибку при m.cols != len(v), а не паниковать. Плоский срез с индексацией i*cols+j — это одна аллокация и непрерывная память, поэтому строки читаются последовательно и попадают в кеш процессора. [][]float64 — это срез указателей на отдельно аллоцированные строки: лишние аллокации, разброс по памяти и промахи кеша."
check: manual
```
