## Графы

```card
front: Определение графа и базовые обозначения
back: "G = (V, E) — множество вершин V и множество рёбер E. n — число вершин, m — число рёбер. deg(v) — степень вершины."
tags: [graphs]
```

```card
front: Чем ориентированный граф отличается от неориентированного
back: "В ориентированном ребро это упорядоченная пара (u, v), и (u, v) ≠ (v, u) — подписка. В неориентированном пара неупорядоченная — дружба."
tags: [graphs]
```

```card
front: Максимальное число рёбер в простом неориентированном графе
back: "m ≤ C(n, 2) = n(n − 1)/2. Отсюда перебор всех пар вершин — это O(n²)."
tags: [graphs]
```

```card
front: Лемма о рукопожатиях
back: "Σ deg(v) = 2m — каждое ребро добавляет по единице к степеням обоих концов. Следствие: число вершин нечётной степени всегда чётно."
tags: [graphs]
```

```card
front: Как лемма о рукопожатиях помогает в отладке данных
back: "Если сумма степеней в построенном неориентированном графе нечётная, значит какое-то ребро записано только с одной стороны — данные повреждены."
tags: [graphs]
```

```card
front: Три эквивалентных определения дерева
back: "1) связный и без циклов; 2) связный и ровно n − 1 ребро; 3) между любыми двумя вершинами ровно один простой путь."
tags: [trees]
```

```card
front: Высота сбалансированного и вырожденного дерева из n узлов
back: "Сбалансированное двоичное — около log₂ n; вырожденное («цепочка») — n − 1. Именно поэтому несбалансированное BST деградирует до O(n)."
tags: [trees]
```

```card
front: Что такое DAG и когда для него существует топологический порядок
back: "Directed acyclic graph — ориентированный граф без циклов. Топологический порядок существует тогда и только тогда, когда циклов нет."
tags: [dag]
```

```card
front: Единственен ли топологический порядок
back: "Нет. Независимые вершины можно расставить по-разному — и это полезно: такие задачи можно выполнять параллельно."
tags: [dag]
```

```card
front: Критерий двудольности графа
back: "Граф двудольный ⇔ в нём нет циклов нечётной длины ⇔ вершины можно раскрасить в два цвета так, чтобы соседи различались."
tags: [graphs]
```

```card
front: Матрица смежности против списков смежности
back: "Матрица — O(n²) памяти, проверка ребра O(1). Списки — O(n + m) памяти, проверка O(deg v). Для разреженных графов почти всегда списки."
tags: [graphs, representation]
```

```card

tags: [graphs, matrices]
```

```card
front: Когда BFS, а когда DFS

tags: [traversal]
```

```card

tags: [traversal]
```

## Рекуррентности

```card
front: Как из рекурсивной функции получить T(n)
back: "Число рекурсивных вызовов даёт a, во сколько раз уменьшается вход — b, работа вне вызовов — f(n). Итого T(n) = a·T(n/b) + f(n) плюс база."
tags: [recurrence]
```

```card
front: Метод подстановки для T(n) = 2T(n/2) + n
back: "T(n) = 2ᵏ·T(n/2ᵏ) + k·n; при 2ᵏ = n получаем k = log₂ n и T(n) = n + n log₂ n = Θ(n log n)."
tags: [recurrence]
```

```card
front: Что показывает дерево рекурсии
back: "Сколько работы на каждом уровне и где она сосредоточена: равномерно по уровням, в корне или в листьях. Сумма по всем уровням и есть ответ."
tags: [recurrence]
```

```card
front: Общий вид и критическая функция master theorem
back: "T(n) = a·T(n/b) + f(n); сравниваем f(n) с критической функцией n^(log_b a) — это работа в листьях."
tags: [master-theorem]
```

```card
front: Три случая master theorem
back: "1) f растёт медленнее критической → Θ(n^(log_b a)), правят листья. 2) f равна ей → Θ(n^(log_b a)·log n), все уровни равны. 3) f растёт быстрее (плюс условие регулярности) → Θ(f(n)), правит корень."
tags: [master-theorem]
```

```card
front: Разберите по master theorem T(n) = 2T(n/2) + n²
back: "a = 2, b = 2, критическая n^(log₂2) = n. f(n) = n² растёт быстрее → случай 3 → Θ(n²)."
tags: [master-theorem]
```

```card
front: Чем отличаются T(n) = T(n/2) + 1 и T(n) = 2T(n/2) + 1
back: "Первое — Θ(log n) (бинарный поиск), второе — Θ(n). Один рекурсивный вызов против двух меняет ответ принципиально."
tags: [recurrence]
```

```card
front: Сложность наивного рекурсивного Фибоначчи и что с ней делать
back: "Θ(φⁿ), φ = (1+√5)/2 ≈ 1.618 — при n = 50 это 10¹⁰ вызовов. Мемоизация схлопывает дерево рекурсии в DAG и даёт Θ(n)."
tags: [recurrence]
```

```card
front: Формула Бине
back: "F(n) = (φⁿ − ψⁿ)/√5, где φ = (1+√5)/2, ψ = (1−√5)/2. Так как abs(ψ) < 1, при больших n F(n) ≈ φⁿ/√5."
tags: [recurrence]
```

```card
front: Когда master theorem неприменима
back: "Когда рекуррентность не имеет вида a·T(n/b) + f(n) с одинаковыми подзадачами. Например T(n) = T(n−1) + n (это Θ(n²)) или T(n) = 2T(n/2) + n log n. Тогда рисуют дерево рекурсии."
tags: [master-theorem]
```

```card
front: Как связаны рекурсия и индукция
back: "Это одно и то же с двух сторон: рекурсия сводит задачу к меньшей, индукция доказывает P(n) через P(n−1). База рекурсии — база индукции, рекурсивный вызов — предположение индукции."
tags: [induction]
```

```card
front: Что такое инвариант цикла и как им доказывают корректность
back: "Утверждение, истинное перед каждой итерацией. Схема: инвариант верен до цикла, сохраняется каждой итерацией, и после выхода вместе с условием выхода даёт нужный результат."
tags: [induction]
```

## Автоматы

```card
front: Из чего состоит DFA
back: "M = (Q, Σ, δ, q₀, F): множество состояний Q, алфавит Σ, функция переходов δ(состояние, символ), начальное состояние q₀, множество принимающих состояний F."
tags: [automata]
```

```card
front: Главное свойство конечного автомата
back: Конечная память при входе любой длины — состояние одно, работа за один проход, O(длины входа) времени и O(1) памяти.
tags: [automata]
```

```card
front: Чем NFA отличается от DFA и что это меняет
back: "В NFA из состояния по символу может вести несколько стрелок или ни одной, бывают ε-переходы; строка принята, если существует хотя бы один успешный путь. Класс распознаваемых языков тот же: NFA переводится в DFA, но число состояний может вырасти с k до 2ᵏ."
tags: [automata]
```

```card
front: Почему регулярное выражение не может распознать сбалансированные скобки
back: "Нужно помнить текущую глубину вложенности — это бесконечно много состояний. У DFA их конечное число k, поэтому две разные глубины неизбежно попадут в одно состояние и перестанут различаться. Для вложенных структур нужен парсер со стеком."
tags: [automata, regex]
```

```card
front: Что такое ReDoS и почему в Go его нет
back: "Экспоненциальный backtracking в NFA-движках (PCRE, Java, JS) на шаблонах вроде (a+)+b подвешивает процесс. Go использует RE2 с гарантией линейного времени — ценой отсутствия обратных ссылок."
tags: [regex]
```

```card
front: Как автомат делимости на 3 хранит остаток
back: "Состояние — текущий остаток от деления на 3. При чтении бита b переход остаток ← (2·остаток + b) mod 3. Три состояния достаточно для строки любой длины."
tags: [automata]
```

```card
front: Зачем описывать статусы заказа как автомат, а не набором if
back: "Явная таблица переходов делает запрещённые переходы невозможными по построению, даёт единый источник правды и отвечает на вопросы аудита («как заказ мог стать shipped минуя paid» — такого ребра нет)."
tags: [automata, backend]
```

```card
front: Промышленные примеры конечных автоматов
back: "Состояния TCP из RFC 793 (LISTEN, SYN_SENT, ESTABLISHED, FIN_WAIT_1, TIME_WAIT, CLOSED), circuit breaker (closed → open → half-open), статусы заказа, лексеры и парсеры."
tags: [automata, backend]
```
