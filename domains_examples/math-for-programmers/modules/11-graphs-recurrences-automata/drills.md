формулой.

## Блок 2. Рекуррентности

```drill
type: fill-in
prompt: "Решите T(n) = 2T(n/2) + n методом подстановки. Ответ в виде Θ(...)."
answer: "Θ(n log n) | Theta(n log n)"
check: fuzzy
hint: "T(n) = 2ᵏ·T(n/2ᵏ) + k·n, остановка при 2ᵏ = n"
```

```drill
type: multiple-choice
prompt: "Функция делит вход на 4 части размера n/4, рекурсивно обрабатывает каждую и тратит n на склейку: T(n) = 4T(n/4) + n. Что даёт master theorem?"
options: ["Θ(n)", "Θ(n log n)", "Θ(n²)", "Θ(log n)"]
answer: "Θ(n log n)"
check: exact
hint: "Критическая функция n^(log₄4) = n, она совпадает с f(n) — случай 2."
```

```drill
type: fill-in
prompt: "Для T(n) = 8T(n/2) + n² чему равна критическая функция n^(log_b a)? Ответ в виде n^k."
answer: "n³ | n^3"
check: fuzzy
hint: "log₂ 8 = 3"
```

```drill
type: multiple-choice

answer: "Потому что вход уменьшается вычитанием, а не делением на b"
```

## Блок 4. Объяснить своими словами

```drill
type: free-form
prompt: "Коллега предлагает регуляркой проверять, что в строке сбалансированы скобки любой вложенности. Объясните, почему это принципиально невозможно, и что предложить вместо."
answer: "Регулярное выражение эквивалентно конечному автомату, у которого фиксированное число состояний k. Чтобы различать вложенность произвольной глубины, надо помнить счётчик глубины — то есть бесконечно много состояний. При достаточно глубокой вложенности две разные глубины попадут в одно состояние и автомат перестанет их различать. Нужен парсер со стеком (или счётчик глубины в обычном цикле) — это уже контекстно-свободный язык, а не регулярный."
check: manual
```

```drill
type: free-form
prompt: "Опишите, как по коду рекурсивной функции получить T(n), и продемонстрируйте на функции, которая делает два рекурсивных вызова на половине входа и один линейный проход."
answer: "Число рекурсивных вызовов даёт a, во сколько раз уменьшается вход — b, вся работа вне вызовов — f(n). Для описанной функции a = 2, b = 2, f(n) = n, то есть T(n) = 2T(n/2) + n с базой T(1) = 1. Критическая функция n^(log₂2) = n совпадает с f(n) — случай 2 master theorem, ответ Θ(n log n). Тот же результат даёт дерево рекурсии: на каждом из log n уровней ровно n работы."
check: manual
```

```drill
type: free-form
prompt: "Докажите индукцией, что рекурсивная функция вычисления факториала (fact(0) = 1, fact(n) = n·fact(n−1)) возвращает n! для всех n ≥ 0. Выпишите базу и шаг."
answer: "База: n = 0, функция возвращает 1, и по определению 0! = 1 — совпало. Шаг: пусть fact(k) = k! для некоторого k ≥ 0. Тогда fact(k+1) = (k+1)·fact(k) по коду = (k+1)·k! по предположению индукции = (k+1)! по определению факториала. По принципу индукции утверждение верно для всех n ≥ 0. Отдельно стоит отметить наличие базы и то, что аргумент строго убывает — иначе рекурсия не завершится."
check: manual
```

```drill
type: free-form
prompt: "Постройте граф для задачи «кто может одобрить отпуск сотруднику»: сотрудники, руководители, роли. Укажите, ориентированный ли граф, что является вершиной и ребром, какое представление выбрать и как выглядит проверка права."
answer: "Вершины — сотрудники и роли; ребро «подчиняется» ориентировано от сотрудника к руководителю, ребро «имеет роль» соединяет сотрудника с ролью (это двудольная часть). Граф ориентированный для иерархии и разреженный, поэтому списки смежности. Проверка «может ли A одобрить отпуск B» — поиск пути от B вверх по рёбрам подчинения до A с ограничением на длину плюс проверка наличия нужной роли у A. Обязательна защита от циклов в иерархии (посещённые вершины), иначе обход зациклится."
check: manual
```

```drill
type: free-form
prompt: "Спроектируйте автомат для парсинга строки вида «ключ=значение» с необязательными пробелами вокруг «=». Перечислите состояния, переходы и принимающие состояния, объясните, почему пустой ключ должен отвергаться."
answer: "Состояния: start, key, spaceBeforeEq, eq, spaceAfterEq, value. Переходы: start + буква → key; key + буква → key; key + пробел → spaceBeforeEq; key/spaceBeforeEq + '=' → eq; eq + пробел → spaceAfterEq; eq/spaceAfterEq + символ значения → value; value + символ значения → value. Принимающее только value (и, если пустое значение допустимо, eq). Пустой ключ отвергается тем, что start не принимающее и из него нет перехода по '=' — значит строка «=5» упирается в отсутствующий переход и отвергается."
check: manual
```
