## Объяснить своими словами

```drill
type: free-form
prompt: "Объясните, почему алгоритм Евклида даёт правильный ответ. Достаточно рассуждения про множества общих делителей — формул не требуется."
answer: "Любой общий делитель a и b делит и остаток r = a − b·q; обратно, любой общий делитель b и r делит a. Значит множества общих делителей пар (a, b) и (b, r) совпадают, а вместе с ними совпадают и наибольшие элементы этих множеств."
check: manual
```

```drill
type: free-form
prompt: "Хеш-таблица использует hash & (size−1) при size = 2ᵏ. Какой риск это несёт и как его обычно снимают?"
answer: "Используются только младшие биты хеша. Если они предсказуемы (например, ключи — указатели, кратные 8), все элементы попадут в малое число бакетов. Снимают либо размешиванием хеша перед взятием остатка (например, h ^= h >> 16), либо выбором простого размера таблицы, при котором остаток зависит от всех битов."
check: manual
```

```drill
type: free-form
prompt: "Объясните на пальцах, почему RSA считается стойким, и какой именно шаг стал бы лёгким, если бы кто-то научился быстро раскладывать числа на множители."
answer: "Публичны n и e. Приватная экспонента d — обратный элемент к e по модулю φ(n), а φ(n) = (p−1)(q−1) вычисляется только при известных p и q. Быстрое разложение n на p и q сразу даёт φ(n), из него d, а значит и полный приватный ключ."
check: manual
```

```drill
type: free-form
prompt: "Почему шардинг по id % n болезненно переживает изменение числа шардов? Приведите оценку доли ключей, которые переедут при переходе с 4 шардов на 5."
answer: "Остаток по новому модулю почти не связан с остатком по старому, поэтому переезжает почти всё: на месте останется примерно 1/5 ключей, то есть переедет около 80%. Именно поэтому применяют consistent hashing или rendezvous hashing, где при добавлении шарда переезжает лишь доля 1/n ключей."
check: manual
```
