# Урок 01 — Евклид, НОД/НОК и остатки в реальных задачах

## Разогрев

Три факта из [теории](../theory.md), без которых дальше не поедем:

- Деление с остатком: `a = b·q + r`, где `0 ≤ r < b`, и такая пара единственна.
- `gcd(a, b) = gcd(b, a mod b)`, база — `gcd(a, 0) = a`.
- Остаток можно брать в любой момент: `(a·b) mod m = ((a mod m)·(b mod m)) mod m`.

## Задача 1. Кольцевой буфер

У нас буфер на 8 слотов и указатель записи `w`. После каждой записи `w = (w + 1) % 8`.
Пока всё просто. Ломается на чтении «назад»: хотим взять элемент, записанный k шагов назад.

```text
w = 2, k = 5
i = w − k = 2 − 5 = −3            — вышли за левый край
в Go: (-3) % 8 == -3              — знак от делимого, индекс невалиден
математически: −3 mod 8 = 5       — потому что −3 = 8·(−1) + 5
рабочая формула: ((i % n) + n) % n = ((−3) + 8) % 8 = 5
```

Почему `+ n` достаточно ровно один раз: после `i % n` результат уже лежит в интервале
`(−n, n)`, поэтому одно прибавление n гарантированно выводит в неотрицательную зону, а
второй `% n` срезает лишнее, если мы и так были неотрицательны.

```go
func ringIndex(i, n int) int { return ((i % n) + n) % n }
```

## Задача 2. Часовые пояса

Сервер в UTC, пользователь в UTC−5. Локальное время события: `(h + offset) mod 24`.

```text
h = 3, offset = −5
3 − 5 = −2                        — «за полночь назад»
−2 mod 24 = 22                    — вчерашние 22:00
```

Та же формула, другой модуль. Именно поэтому в теории мы называли модульную арифметику
«арифметикой часов» — здесь это буквально.

```drill
type: fill-in
prompt: "Сервер в UTC показывает 2 часа. Пользователь в UTC−7. Который час у пользователя (0..23)?"
answer: "19"
check: exact
hint: "((2 − 7) % 24 + 24) % 24"
```

## Задача 3. Совпадение периодов

Два фоновых задания: одно раз в 12 минут, другое раз в 18. Запустились вместе. Когда
следующий «двойной» запуск и сколько раз за сутки они столкнутся?

```text
lcm(12, 18) = 12·18 / gcd(12, 18)
gcd(12, 18): 18 mod 12 = 6; 12 mod 6 = 0 → gcd = 6
lcm = 216 / 6 = 36                 — каждые 36 минут
24 ч = 1440 мин
1440 / 36 = 40                     — 40 совпадений в сутки (считая старт)
```

Это не «просто задачка»: именно так оценивают, как часто два периодических джоба сойдутся
и создадут пик нагрузки. Лечение — сделать периоды взаимно простыми или добавить джиттер.

```drill
type: fill-in
prompt: "Джобы с периодами 10 и 14 минут стартовали одновременно. Через сколько минут они совпадут снова?"
answer: "70"
check: exact
hint: "gcd(10, 14) = 2"
```

## Задача 4. Шардинг по ключу

Пусть 4 шарда и ключ — строка. Наивный вариант — `id % 4`, но id часто последовательный, и
если он же используется как ключ ещё где-то, шардирование коррелирует с другими решениями.
Правильнее — хешировать ключ, а потом брать остаток:

```go
import "hash/fnv"

func shard(key string, n uint32) uint32 {
	h := fnv.New32a()
	h.Write([]byte(key)) // Write у hash.Hash никогда не возвращает ошибку
	return h.Sum32() % n
}
```

Что здесь математически важно:

1. `% n` равномерно распределяет только если сам хеш распределён равномерно. Остаток не
   умеет чинить плохой хеш — он умеет его сохранять.
2. При `n = 2ᵏ` можно писать `h & (n−1)` — быстрее, но используются только младшие биты.
3. При смене n с 4 на 5 остаток меняется почти у всех ключей: на месте останется примерно
   1/5 ключей. Это и есть боль решардинга.

```drill
type: multiple-choice
prompt: "Почему шардирование через hash(key) % n предпочтительнее, чем id % n?"
options:
  - "hash считается быстрее"
  - "хеш убирает корреляцию с порядком и структурой id"
  - "остаток от хеша всегда меньше"
  - "id может быть отрицательным"
answer: "хеш убирает корреляцию с порядком и структурой id"
check: exact
```

## Задача 5. Проверка Ферма кодом

Соберём всё вместе: посчитаем обратные элементы по модулю 11 через `a^(p−2) mod p` и
убедимся, что `a · a⁻¹ ≡ 1`.

```go
const p = 11
for a := 1; a < p; a++ {
	inv := powMod(a, p-2, p) // powMod — из «В коде» теории
	fmt.Printf("%d⁻¹ = %d, проверка: %d\n", a, inv, a*inv%p)
}
```

Последний столбец должен быть сплошными единицами. Если попробовать то же самое с
составным модулем (скажем, 12), формула сломается: у 2, 3, 4, 6, 8, 9, 10 обратных по
модулю 12 просто не существует, потому что `gcd(a, 12) ≠ 1`.

```drill
type: free-form
prompt: "Почему у числа 6 нет обратного элемента по модулю 12? Ответьте через общий делитель."
answer: "gcd(6, 12) = 6 ≠ 1. Любое произведение 6·x кратно 6, значит его остаток по модулю 12 может быть только 0 или 6, но никогда 1. Обратный элемент существует лишь при взаимной простоте a и m."
check: manual
```

## Итог

Все пять задач — одна и та же операция «взять остаток», надетая на разные предметные
области. Запомнить стоит три вещи. Первая: `((x % n) + n) % n` — это не костыль, а
корректный математический mod, и в Go он нужен всегда, когда аргумент может быть
отрицательным. Вторая: НОК считается через НОД, а НОД — Евклидом за логарифм шагов, и
совпадение периодов — это про НОК. Третья: остаток равномерен ровно настолько, насколько
равномерен вход, поэтому шардируют по хешу, а не по id.
