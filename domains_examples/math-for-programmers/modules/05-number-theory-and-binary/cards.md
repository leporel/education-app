# Карточки

## Делимость и простые

```card
front: "Запись b | a — как читается и что означает?"
back: "«b делит a»: a делится на b нацело, остаток равен нулю. Вертикальная черта здесь не «или»."
tags: [делимость]
```

```card
front: Деление с остатком — точная формулировка
back: "Для целых a и b > 0 существует единственная пара q и r, что a = b·q + r и 0 ≤ r < b."
hint: Ключевое слово — единственная
tags: [делимость]
```

```card
front: Определение простого числа. Почему 1 не простое?
back: "Простое — натуральное число с ровно двумя делителями (1 и оно само). Единицу исключают, иначе разложение на множители перестало бы быть единственным."
tags: [простые]
```

```card
front: Основная теорема арифметики
back: "Любое целое n > 1 раскладывается в произведение простых единственным способом с точностью до порядка множителей. Пример 360 = 2³·3²·5."
tags: [простые]
```

```card
front: До какого числа достаточно перебирать делители, проверяя n на простоту?
back: "До √n включительно. Если n = a·b, то меньший из множителей не превосходит √n."
tags: [простые]
```

```card
front: Признак делимости на 3 и почему он работает
back: "Сумма цифр делится на 3. Работает потому, что 10 ≡ 1 (mod 3), значит и 10ᵏ ≡ 1, и число сворачивается в сумму цифр."
tags: [делимость]
```

```card
front: Сколько примерно простых чисел не превосходит n?
back: "π(n) ≈ n / ln n. Среди 64-битных чисел примерно каждое 44-е простое — поэтому случайный поиск большого простого для RSA быстр."
tags: [простые]
```

## НОД, НОК, Евклид

```card
front: Алгоритм Евклида — рекуррентность и база
back: "gcd(a, b) = gcd(b, a mod b), пока b ≠ 0; gcd(a, 0) = a."
tags: [gcd]
```

```card
front: Почему алгоритм Евклида корректен?
back: "Любой общий делитель a и b делит и остаток r = a − b·q, и наоборот. Множества общих делителей пар (a,b) и (b,r) совпадают, значит совпадают их максимумы."
tags: [gcd]
```

```card
front: Почему алгоритм Евклида быстрый?
back: "За каждые два шага уменьшаемое падает минимум вдвое, поэтому шагов O(log min(a,b)) — меньше сотни для 64-битных чисел. Худший случай — соседние числа Фибоначчи."
tags: [gcd]
```

```card
front: Связь НОД и НОК
back: "a·b = gcd(a,b) · lcm(a,b). Практически lcm считают как a / gcd(a,b) * b — делить нужно первым, чтобы не переполнить."
tags: [gcd]
```

```card
front: Что значит «взаимно простые»?
back: "gcd(a, b) = 1 — общих делителей, кроме единицы, нет. Сами числа при этом могут быть составными (8 и 9)."
tags: [gcd]
```

## Модульная арифметика

```card
front: "Как читается a ≡ b (mod m) и что означает?"
back: "«a сравнимо с b по модулю m»: a и b дают одинаковый остаток при делении на m, то есть m делит разность a − b."
tags: [mod]
```

```card
front: Два правила арифметики остатков
back: "(a + b) mod m = ((a mod m) + (b mod m)) mod m и (a · b) mod m = ((a mod m)·(b mod m)) mod m. Отсюда же работает и возведение в степень."
hint: Остаток можно брать в любой момент, не только в конце
tags: [mod]
```

```card
front: Чему равно -7 % 3 в Go и чему равен математический остаток?
back: "В Go -1 (знак берётся от делимого), математический остаток 2. Исправление — ((x % m) + m) % m."
tags: [mod, go]
```

```card
front: Можно ли сокращать сравнение по модулю на общий множитель?
back: "Нет. 6 ≡ 12 (mod 6), но 1 ≡ 2 (mod 6) ложно. Деление по модулю делают через обратный элемент."
tags: [mod]
```

```card
front: Что такое обратный элемент по модулю и когда он существует?
back: "a⁻¹ — такое число, что a·a⁻¹ ≡ 1 (mod m). Существует тогда и только тогда, когда gcd(a, m) = 1."
tags: [mod]
```

```card
front: Малая теорема Ферма
back: "Если p простое и a не делится на p, то a^(p−1) ≡ 1 (mod p). Следствие — обратный элемент равен a^(p−2) mod p."
tags: [mod, ферма]
```

```card
front: Сколько умножений нужно для a^n mod m быстрым возведением в степень?
back: "Порядка 2·log₂(n): показатель раскладывают по двоичным разрядам, каждый шаг — возведение в квадрат и, возможно, домножение."
tags: [mod]
```

## Системы счисления

```card
front: Как перевести десятичное число в двоичное вручную?
back: "Делить на 2, записывая остатки, и читать их снизу вверх. 90 → 1011010₂."
tags: [системы-счисления]
```

```card
front: Почему байты записывают в hex, а права доступа — в восьмеричной?
back: "16 = 2⁴ и 8 = 2³, поэтому одна hex-цифра — ровно 4 бита, а одна восьмеричная — 3 бита. Байт = 2 hex-цифры, права rwx = 1 восьмеричная цифра."
tags: [системы-счисления]
```

```card
front: Переведите 0x5A в двоичную и десятичную
back: "0x5A → 0101 1010₂ → 64 + 16 + 8 + 2 = 90."
hint: По 4 бита на hex-цифру
tags: [системы-счисления]
```

## Биты

```card
front: Что делают x & (x−1) и x & (−x)?
back: "Первое сбрасывает самый младший установленный бит, второе оставляет только его. Отсюда проверка степени двойки x != 0 && x&(x−1) == 0."
tags: [биты]
```

```card
front: Как заменить x % 2ᵏ и x / 2ᵏ битовыми операциями?
back: "x % 2ᵏ = x & (2ᵏ − 1) и x / 2ᵏ = x >> k. Только для неотрицательных x."
tags: [биты]
```

```card
front: "Установить, сбросить, переключить и проверить бит i"
back: "set — x |= 1<<i; clear — x &^= 1<<i (в C x &= ~(1<<i)); toggle — x ^= 1<<i; test — x & (1<<i) != 0."
tags: [биты, go]
```

```card
front: Чем в Go отличается унарный ^ от бинарного ^?
back: "Унарный ^a — побитовое НЕ (в C это ~a), бинарный a ^ b — XOR. Ещё есть a &^ b — AND NOT, «сбросить в a биты, выставленные в b»."
tags: [биты, go]
```

```card
front: Главное свойство XOR
back: "x ^ y ^ y = x — XOR обратим сам себе. Отсюда шифр Вернама, поиск непарного элемента и обмен переменных без временной."
tags: [биты]
```

```card
front: Что такое дополнительный код и почему int8 хранит −128..127?
back: "Знаковые целые кодируются как two's complement: −x представляется как 2ⁿ − x, старший бит — знаковый. Диапазон несимметричен, потому что ноль занимает одну из «положительных» комбинаций."
tags: [биты]
```

```card
front: Что происходит при переполнении uint8 на 255 + 1?
back: "Получается 0. Беззнаковые целые в Go — арифметика по модулю 2ⁿ, это специфицировано, а не ошибка."
tags: [биты, go]
```

```card
front: "math/bits — четыре самые нужные функции"
back: "OnesCount64 (popcount), LeadingZeros64 (отсюда ⌊log₂x⌋ = 63 − LeadingZeros64), TrailingZeros64, Len64. Компилируются в одну инструкцию."
tags: [go]
```

## Приложения

```card
front: Почему размер хеш-таблицы берут простым числом или степенью двойки?
back: "Степень двойки позволяет hash & (n−1) вместо hash % n, но использует только младшие биты — хеш надо предварительно размешать. Простое число заставляет остаток зависеть от всех битов."
tags: [хеширование]
```

```card
front: Чем контрольная сумма «сумма байтов» хуже CRC?
back: "Сумма не зависит от порядка байтов, поэтому не ловит перестановку. CRC — остаток от деления сообщения-многочлена на порождающий многочлен, чувствителен к позиции."
tags: [checksum]
```

```card
front: Идея RSA в четырёх строках
back: "n = p·q для больших простых; φ(n) = (p−1)(q−1); публичная экспонента e взаимно проста с φ; d = e⁻¹ mod φ(n). Шифрование c = m^e mod n, расшифровка m = c^d mod n. Стойкость — в сложности разложения n."
tags: [rsa]
```

```card
front: Сколько вариантов у UUIDv4 и как это оценить?
back: "122 случайных бита из 128. Приём 2¹⁰ ≈ 10³ даёт 2¹²² ≈ 4·10³⁶. Коллизия с вероятностью ~50% ожидается примерно после 2⁶¹ ≈ 2.3·10¹⁸ генераций."
tags: [uuid]
```

```card
front: Приём быстрой оценки степеней двойки в десятичных порядках
back: "2¹⁰ = 1024 ≈ 10³. Значит 2²⁰ ≈ 10⁶, 2³⁰ ≈ 10⁹, 2⁶⁴ ≈ 1.8·10¹⁹. В общем виде 2ⁿ ≈ 10^(0.301·n)."
tags: [оценки]
```
