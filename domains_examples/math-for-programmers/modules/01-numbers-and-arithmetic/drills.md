# Упражнения — числа и арифметика

Считайте руками, записывая шаги, и только потом сверяйтесь. Там, где ответ дробный,
принимается и обыкновенная дробь, и десятичная. Задания с пометкой «проверь кодом»
разбираются самостоятельно — их проверяет не автомат, а запущенный вами код.

## Объясни и проверь

```drill
type: free-form
prompt: "Объясни своими словами, почему 0.1 + 0.2 != 0.3 в float64, и почему это не ошибка реализации языка. В объяснении обязательно должно прозвучать, на каком шаге впервые появляется погрешность."
answer: "Погрешность появляется уже при записи литералов: 1/10 и 2/10 не представимы конечной двоичной дробью, потому что знаменатель 10 содержит множитель 5. В памяти оказываются ближайшие узлы сетки float64. Их точная сумма округляется к ещё одному узлу, а литерал 0.3 округляется к соседнему — это два разных числа."
check: manual
```

```drill
type: free-form
prompt: "Объясни, почему определение a⁰ = 1 не является произвольным соглашением. Приведи вывод из правила действий со степенями."
answer: "Из правила aᵐ / aⁿ = aᵐ⁻ⁿ при m = n получаем aⁿ / aⁿ = a⁰. Но слева стоит частное одинаковых чисел, то есть 1. Значит, чтобы правило продолжало работать, a⁰ обязано равняться 1 (при a ≠ 0)."
check: manual
```

```drill
type: free-form
prompt: "Проверь кодом: напиши функцию mod(a, n int) int, дающую математический остаток в диапазоне [0, n), и убедись, что она отличается от оператора % на отрицательных значениях. Объясни, где такая функция нужна в реальном коде."
answer: "return ((a % n) + n) % n. На a = -7, n = 3 оператор % даёт -1, функция даёт 2. Нужна везде, где остаток используется как индекс: шардирование по hash % n, кольцевые буферы, циклический выбор элемента — отрицательный индекс там означает панику или порчу данных."
check: manual
```

```drill
type: free-form
prompt: "Проверь кодом: с помощью math.Nextafter измерь шаг сетки float64 рядом со значениями 1, 1e6, 1e15. Объясни, почему из этих чисел следует, что фиксированный допуск eps = 1e-9 не годится как универсальный способ сравнения."
answer: "Шаг растёт вместе с величиной числа: около 1 он порядка 2.2e-16, около 1e15 уже 0.125. Значит, при больших значениях фиксированный допуск 1e-9 меньше расстояния между соседними представимыми числами, и сравнение с ним превращается в обычное ==. Нужен относительный допуск: |a − b| ≤ eps · max(|a|, |b|)."
check: manual
```
