# Урок 02 — Степени, корни и оценка порядков

Цель урока — научиться отвечать на вопросы вида «сколько это примерно?» за десять
секунд и без калькулятора. Инструменты: правила степеней из [`theory.md`](../theory.md),
научная запись и первое, очень практичное знакомство с логарифмом.

## Разминка: степени двойки, которые стоит знать

Их не нужно зубрить таблицей — достаточно помнить опорные точки и удваивать:

| n | 2ⁿ | Чем удобно |
|---|---|---|
| 8 | 256 | один байт |
| 10 | 1024 | «килограмм» ≈ 10³ |
| 16 | 65 536 | uint16, порты |
| 20 | ≈ 10⁶ | «мегабайт» |
| 30 | ≈ 10⁹ | «гигабайт» |
| 32 | ≈ 4.3·10⁹ | uint32, IPv4 |
| 53 | ≈ 9·10¹⁵ | предел точных целых в float64 |
| 64 | ≈ 1.8·10¹⁹ | uint64 |

Опорный трюк: **2¹⁰ ≈ 10³**. Отсюда 2²⁰ ≈ 10⁶, 2³⁰ ≈ 10⁹, и любую степень двойки
можно оценить в уме:

```text
2⁴⁵ = 2⁴⁰ · 2⁵           — разбили показатель на удобные куски
   ≈ (10³)⁴ · 32         — 2¹⁰ ≈ 10³, значит 2⁴⁰ ≈ 10¹²
   ≈ 32 · 10¹²
   ≈ 3.2 · 10¹³
```

Точное значение 2⁴⁵ = 35 184 372 088 832 ≈ 3.5·10¹³. Ошиблись на 10% — для оценки
на салфетке этого более чем достаточно.

## Логарифм с чёрного хода

Строго логарифм разбирается в [модуле 02](../../02-algebra-refresher/index.md).
Здесь достаточно рабочей формулировки:

> **log₂(n) — это сколько раз нужно поделить n пополам, чтобы дойти до единицы.**

Из этого сразу следуют два вопроса, которые программист задаёт постоянно.

**Сколько бит нужно, чтобы закодировать N разных значений?** n бит дают 2ⁿ комбинаций,
значит нужно наименьшее n с условием 2ⁿ ≥ N, то есть n = ⌈log₂ N⌉.

```text
N = 1000 различных статусов
2⁹  = 512  < 1000     — девяти бит мало
2¹⁰ = 1024 ≥ 1000     — десяти хватает
n = ⌈log₂ 1000⌉ = 10
```

**Сколько шагов сделает двоичный поиск в массиве из n элементов?** Каждый шаг делит
диапазон пополам, значит примерно ⌈log₂ n⌉ шагов. Для миллиона элементов это 20
шагов, для миллиарда — 30. Ровно поэтому «поиск по отсортированному» в разговоре
считают бесплатным.

```go
package main

import "fmt"

func main() {
	n := 1_000_000
	steps := 0
	for n > 1 {
		n /= 2
		steps++
	}
	fmt.Println(steps) // 19 = ⌊log₂ 1000000⌋
}
```

Цикл делит нацело, поэтому он считает ⌊log₂ n⌋ = 19. Двоичному поиску нужно на шаг
больше, ⌈log₂ (n+1)⌉ = 20: последний шаг проверяет оставшийся единственный элемент.
Для оценок разница между 19 и 20 роли не играет — важно, что это два десятка, а не
миллион.

## Корни как обратная операция

√x — это «какое число, умноженное само на себя, даёт x». Оно же x^(1/2), и это не
просто другая запись, а рабочий инструмент: правила степеней применимы к корням
напрямую.

```text
√(a·b) = (a·b)^(1/2) = a^(1/2) · b^(1/2) = √a · √b     — степень произведения
√(2·10⁸) = √2 · √(10⁸) = 1.414 · 10⁴ ≈ 1.4·10⁴          — вот и оценка в уме
```

Полезный частный случай: √(10ᵏ) = 10^(k/2). Для чётного k это ровно степень десятки,
для нечётного — умножаем на √10 ≈ 3.16.

```text
√(10⁹) = 10^(9/2) = 10⁴·⁵ = 10⁴ · 10⁰·⁵ ≈ 10⁴ · 3.16 ≈ 3.2·10⁴
```

Проверка: 31623² ≈ 1.0000·10⁹. Сходится.

## Оценка на салфетке: полный проход

Задача. Сервис пишет лог доступа: 12 000 RPS в пике, средняя строка 400 байт, храним
30 суток. Сколько места нужно и влезет ли это на один диск в 10 ТБ?

```text
секунд в сутках = 86400 ≈ 8.64·10⁴
строк в сутки   = 1.2·10⁴ · 8.64·10⁴
                = (1.2 · 8.64) · 10⁴⁺⁴        — множители отдельно, степени отдельно
                ≈ 10.4 · 10⁸ ≈ 1.04·10⁹        — примерно миллиард строк в сутки
байт в сутки    = 1.04·10⁹ · 4·10²
                ≈ 4.2·10¹¹ байт ≈ 420 ГБ
за 30 суток     = 4.2·10¹¹ · 3·10¹
                ≈ 1.26·10¹³ байт ≈ 12.6 ТБ
```

Ответ: не влезет, и не «немного не влезет», а с превышением на четверть. При этом мы
считали по пиковому RPS — реальная средняя нагрузка ниже, так что вывод скорее
«впритык, нужна ротация или сжатие». Важно другое: весь расчёт занял полминуты и
не потребовал ни одной точной цифры.

Для порядка величины это по-прежнему приемлемо, но выдавать такой результат за точное значение уже нельзя."


## Итог

- 2¹⁰ ≈ 10³ — главный опорный факт для оценок; из него выводятся все остальные
  степени двойки.
- В научной записи множители считаются отдельно, показатели складываются: это и
  делает оценку в уме возможной.
- log₂(n) читается как «сколько раз делим пополам»; ⌈log₂ N⌉ — число бит для N значений
  и число шагов двоичного поиска.
- Корень — это степень 1/2, и к нему применимы все правила степеней; √(10ᵏ) = 10^(k/2).
- Оценка порядка не обязана быть точной. Она обязана быть быстрой и правильной по
  порядку — этого достаточно, чтобы отсеять заведомо плохие решения.
