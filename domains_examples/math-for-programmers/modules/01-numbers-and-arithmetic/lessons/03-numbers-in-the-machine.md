# Урок 03 — Числа в машине: переполнение, float, остаток

Практика к [`theory-2-numbers-in-machine.md`](../theory-2-numbers-in-machine.md).
Разбираем три бага, которые выглядят как мистика, пока не знаешь арифметику за ними.
Каждый из них реально встречается в продакшене.

## Баг 1. Счётчик ушёл в минус

Ситуация: метрика «просмотров» хранится в `int32`, и однажды на дашборде появилось
`-2 147 483 000`. Никто ничего не удалял.

Разберём на маленьком масштабе, где всё видно глазами. Возьмём `int8` (диапазон
−128 … 127):

```text
127 = 0111 1111                 — максимум, все младшие биты заняты
+1                              — прибавляем единицу
    = 1000 0000                 — перенос дошёл до старшего бита
старший бит в дополнительном коде весит −128
    = −128                      — вот и «минус из ниоткуда»
```

С `int32` то же самое, только граница проходит по 2 147 483 647. Go при этом не
паникует: переполнение — легальная операция, результат берётся по модулю 2³².

```go
package main

import "fmt"

func main() {
	var a int8 = 127
	a++
	fmt.Println(a) // -128

	var b int32 = 2147483647
	b++
	fmt.Println(b) // -2147483648
}
```

Как чинить: брать `int64` там, где величина растёт монотонно, и не полагаться на
«столько никогда не накопится». А если тип менять нельзя — проверять перед сложением:
`if a > math.MaxInt32-delta { ... }`.

```drill

prompt: "Переменная var u uint8 = 3; u -= 5. Что окажется в u?"
options: ["254", "-2", "0", "программа паникует"]
answer: "254"
check: exact
hint: результат берётся по модулю 256
```

## Баг 2. Итог заказа отличается на копейку

Ситуация: сумма трёх позиций по 0.1 сравнивается с 0.3 — и не совпадает.

```go
package main

import "fmt"

func main() {
	sum := 0.1 + 0.1 + 0.1
	fmt.Println(sum == 0.3)   // false
	fmt.Printf("%.20f\n", sum) // 0.30000000000000004441
	fmt.Printf("%.20f\n", 0.3) // 0.29999999999999998890
}
```

Причина не в сложении, а в записи. Число 0.1 — это дробь 1/10, а в двоичной системе
конечной дробью записываются только знаменатели-степени двойки. Десятка содержит
множитель 5, значит 1/10 в двоичной — бесконечная периодическая дробь, ровно как 1/3
в десятичной. В память попадает ближайший узел сетки, и дальше вся арифметика идёт
уже с ним.

Что делать — зависит от задачи:

```text
деньги               → целые в копейках/центах, либо десятичный тип
сравнение результатов
  вычислений         → допуск: |a − b| ≤ eps · max(|a|, |b|)
точная дробь         → big.Rat из math/big
вывод пользователю   → форматирование с нужным числом знаков, а не сравнение
```

Вариант с копейками — самый скучный и самый надёжный:

```go
// Храним минимальные единицы. 0.1 + 0.1 + 0.1 == 0.3 превращается в 10+10+10 == 30.
type Kopecks int64

func (k Kopecks) String() string {
	return fmt.Sprintf("%d.%02d", k/100, k%100)
}
```

Обратите внимание: в `String()` спрятан подвох из первой части теории. Для
отрицательной суммы `k % 100` в Go даст отрицательный остаток, и вывод сломается.
Это тот самый случай, где нужен математический mod.

```drill
type: free-form
prompt: "Перепиши метод String() для типа Kopecks так, чтобы он корректно печатал отрицательные суммы. Объясни, какая именно арифметическая деталь ломает наивную версию."
answer: "Наивная версия ломается потому, что в Go знак остатка совпадает со знаком делимого: для k = -150 частное k/100 = -1, а k%100 = -50, и получается строка вида -1.-50. Нужно вынести знак отдельно: взять abs := k, если k < 0 — поменять знак и запомнить минус, затем печатать abs/100 и abs%100 с ведущим нулём. Альтернатива — использовать математический остаток ((k % 100) + 100) % 100 вместе с делением с округлением вниз."
check: manual
```

## Баг 3. Отрицательный индекс шарда

Ситуация: `shard := int(hash) % shardCount` — и раз в несколько тысяч запросов
приложение падает с выходом за границы среза.

```text
hash даёт значение, которое при приведении к int оказалось отрицательным
-1234567 % 8 = -7          — знак взят от делимого
shards[-7]                 — паника: index out of range
```

Правильный вариант — привести остаток в диапазон [0, n):

```go
// mod возвращает математический остаток: всегда в [0, n).
func mod(a, n int) int {
	return ((a % n) + n) % n
}

func shardOf(hash int64, shards int) int {
	return mod(int(hash), shards)
}
```

Ещё надёжнее — не приводить хеш к знаковому типу вовсе: `uint64(hash) % uint64(shards)`
не может дать отрицательное значение по построению. Оба способа рабочие; главное —
осознанный выбор, а не «обычно же работает».

```drill

prompt: "Чему равно -1234567 % 8 в Go?"
answer: "-7"
check: exact
```

## Проверка сетки собственными руками

Последнее упражнение урока — измерить, насколько «редкой» становится сетка float64
для больших чисел. Это лечит привычку брать `eps` наугад.

```go
package main

import (
	"fmt"
	"math"
)

func main() {
	for _, x := range []float64{1, 1e6, 1e9, 1e15, 1e18} {
		step := math.Nextafter(x, math.Inf(1)) - x
		fmt.Printf("%-8g шаг сетки %g\n", x, step)
	}
}
```

Около 1 шаг порядка 2.2·10⁻¹⁶, около 10¹⁵ — уже 0.125, около 10¹⁸ — 128. То есть для
больших величин два «разных» числа могут отличаться на сотню и всё равно быть одним
и тем же float64.

```drill
type: free-form
prompt: "Запусти код выше и объясни, почему при работе с идентификаторами больше 2⁵³ переход через JSON (где число становится double) может склеить два разных id в один. Предложи два способа этого избежать."
answer: "После 2⁵³ шаг сетки float64 становится 2 и больше, поэтому соседние целые числа перестают быть представимыми: они округляются к общему ближайшему узлу. Два разных id, отличающихся на единицу, превращаются в одно значение. Способы избежать: передавать большие id строкой (частая практика для snowflake-подобных id) либо использовать формат/парсер, сохраняющий целые как int64 без приведения к double."
check: manual
```

## Итог

- Целые в памяти живут по кольцу: переполнение в Go тихое, результат берётся по
  модулю 2ⁿ, и старший бит в дополнительном коде имеет отрицательный вес.
- Погрешность float появляется в момент записи литерала, а не при вычислении:
  1/10 не представима конечной двоичной дробью.
- Сравнивать float через `==` нельзя; допуск выбирается под масштаб задачи, и
  относительный допуск устойчивее абсолютного.
- Деньги — в целых минимальных единицах; точные дроби — `big.Rat`; произвольная
  длина — `big.Int`.
- `%` в Go не равен математическому mod для отрицательных. Там, где остаток
  используется как индекс, нужен `((a % n) + n) % n` или беззнаковый тип.
