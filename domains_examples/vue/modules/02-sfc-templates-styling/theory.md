# SFC, шаблоны и стилизация

## Откуда всё начинается: `index.html` → `main.ts` → `App.vue`

Прежде чем разбирать компонент, ответим на вопрос, который в туториалах обычно проглатывают:
**куда вообще попадает мой компонент и кто его рисует?** Проект, созданный командой
`npm create vue@latest`, выглядит так:

```
index.html            # единственная HTML-страница приложения
vite.config.ts        # конфиг сборщика (плагин Vue, алиасы)
tsconfig*.json        # настройки TypeScript
package.json          # зависимости и скрипты (dev / build / preview)
src/
  main.ts             # точка входа: создаёт приложение и монтирует его
  App.vue             # корневой компонент
  components/         # переиспользуемые компоненты
  views/              # компоненты-«страницы» (появятся с роутером, модуль 05)
  assets/             # css, картинки
```

Цепочка запуска:

```html
<!-- index.html -->
<div id="app"></div>                      <!-- пустой «якорь» для приложения -->
<script type="module" src="/src/main.ts"></script>
```

```ts
// src/main.ts
import { createApp } from "vue";
import App from "./App.vue";
import "./assets/main.css";               // глобальные стили

createApp(App).mount("#app");             // «нарисуй App внутрь элемента #app»
```

Читается так: браузер загружает `index.html`, тот подтягивает `main.ts`, тот создаёт
**экземпляр приложения** из корневого компонента `App.vue` и **монтирует** его в элемент
`#app`. С этого момента всё, что внутри `#app`, рисует и обновляет Vue. Плагины
(роутер, Pinia) подключаются здесь же цепочкой `.use(...)` — увидишь в модулях 05 и 06.

Ещё две мелочи из шаблона проекта, которые дальше будут встречаться без объяснений:

- **Алиас `@`** — это сокращение для папки `src/`, настроенное в `vite.config.ts` и
  `tsconfig`. `import Foo from "@/components/Foo.vue"` вместо `../../components/Foo.vue`.
  Никакой магии npm-пакета тут нет, просто псевдоним пути.
- **`npm run dev`** поднимает dev-сервер Vite с горячей заменой модулей (правишь файл —
  экран обновляется без перезагрузки и без потери состояния). `npm run build` собирает
  прод-бандл в `dist/`. Подробнее про тулинг — в модуле 07.

> **Простыми словами.** `index.html` — это пустая рамка с одной дыркой (`#app`). `main.ts` —
> инструкция «вставь в дырку вот это приложение». Всё остальное — уже внутри Vue.

## Анатомия Single File Component

Vue-компонент обычно живёт в файле `.vue` — это **Single File Component (SFC)**. Внутри —
до трёх блоков:

```vue
<script setup lang="ts">
// логика: состояние, computed, функции, импорты
import { ref } from "vue";
const name = ref("мир");
</script>

<template>
  <!-- разметка: HTML + директивы Vue -->
  <h1>Привет, {{ name }}!</h1>
</template>

<style scoped>
/* стили, изолированные в этот компонент */
h1 { color: teal; }
</style>
```

Почему «всё в одном файле» — это не свалка, а фича: компонент — единица, у которой логика,
разметка и оформление концептуально связаны. Держать их рядом удобнее, чем растаскивать по
трём деревьям папок (как в старом вебе: `.js` + `.html` + `.css`). Сборщик (Vite) понимает
`.vue` через плагин и компилирует его в обычный JS-модуль.

> **Параллель с Go.** SFC по духу близок к идее «пакет — это папка со связанными
> файлами», только тут наоборот: связанные *аспекты* собраны в один файл. Компилятор
> `.vue` — это как `go generate`/кодогенерация: разметка-шаблон превращается в
> render-функцию на этапе сборки, в браузер уезжает обычный JS.

### `<script setup>` — почему именно он

`<script setup>` — это синтаксический сахар, который делает Composition API лаконичным:

- Всё, что ты объявил на верхнем уровне (`const`, `function`, импорты компонентов),
  **автоматически доступно в шаблоне** — не нужно ничего «возвращать».
- `lang="ts"` включает TypeScript: типы props, emits, ref-ов работают «из коробки».
- Меньше церемоний, чем в классическом `setup()`-методе (его увидим в обзоре Options API
  в модуле 03).

Запомни как дефолт: **`<script setup lang="ts">` + Composition API** — это и есть
современный Vue.

## Язык шаблонов: директивы

Шаблон Vue — это HTML, расширенный **директивами** (атрибуты, начинающиеся с `v-`) и
**интерполяцией** (`{{ }}`). Компилятор превращает это в render-функцию; реактивные
значения, которые шаблон прочитал, автоматически подписывают рендер (механизм из модуля 01).

> **Простыми словами.** Директива — это «атрибут со смыслом»: обычный HTML-атрибут браузер
> просто кладёт в узел, а `v-`-атрибут компилятор Vue превращает в код. `:` — «подставь
> сюда значение», `@` — «на это событие вызови», `v-if`/`v-for` — «рисуй по условию/для
> каждого».

### Интерполяция текста: `{{ }}`

```vue
<p>Сумма: {{ price * qty }} ₽</p>     <!-- внутри — любое JS-выражение -->
<p>{{ isVip ? "VIP" : "обычный" }}</p>
```

Внутри `{{ }}` — **выражение** (не инструкция): можно тернарник, вызов метода, обращение к
свойству; нельзя `if`/`for`/объявления. Усложнять выражение в шаблоне не стоит — тяжёлую
логику выноси в `computed`.

### `v-bind` (`:`) — привязка атрибутов

`{{ }}` работает в тексте. Чтобы подставить значение в **атрибут**, нужен `v-bind`, у него
есть короткая форма `:`:

```vue
<img v-bind:src="avatarUrl" />
<img :src="avatarUrl" :alt="userName" />     <!-- то же короче -->
<a :href="`/users/${id}`">профиль</a>
<button :disabled="isLoading">Сохранить</button>   <!-- boolean-атрибут -->
```

`:disabled="isLoading"` — если `isLoading` истинно, атрибут проставится, иначе исчезнет. Это
заметно приятнее ручного `el.disabled = ...`.

### `v-on` (`@`) — обработка событий

```vue
<button v-on:click="count++">+1</button>
<button @click="count++">+1</button>             <!-- короткая форма @ -->
<button @click="addToCart(item)">В корзину</button>
<form @submit.prevent="onSubmit">...</form>       <!-- .prevent — модификатор -->
<input @keyup.enter="search" />                   <!-- .enter — клавиша-модификатор -->
```

**Модификаторы** (`.prevent`, `.stop`, `.enter`, `.once`…) — это встроенные «приправы» к
событию: `.prevent` вызывает `event.preventDefault()`, `.stop` — `stopPropagation()`,
`.enter` срабатывает только на Enter. Без них пришлось бы писать это руками в обработчике.

### `v-if` / `v-else` / `v-show` — условный рендеринг

```vue
<p v-if="status === 'loading'">Загрузка…</p>
<p v-else-if="status === 'error'">Ошибка</p>
<p v-else>Готово</p>

<div v-show="isOpen">Панель</div>
```

- `v-if` — **реально добавляет/убирает** элемент из DOM. Дешевле, когда условие редко
  меняется или ветка тяжёлая (её просто нет в DOM, пока не нужна).
- `v-show` — элемент **всегда в DOM**, просто переключается `display: none`. Дешевле для
  частого тогглинга (показать/скрыть тултип), потому что не пересоздаёт узлы.

Правило: редкое условие / тяжёлый блок → `v-if`; частое переключение видимости →
`v-show`.

### `v-for` — списки (и почему `:key` обязателен)

```vue
<ul>
  <li v-for="item in items" :key="item.id">{{ item.title }}</li>
</ul>

<!-- с индексом и по объекту -->
<li v-for="(item, index) in items" :key="item.id">{{ index }}: {{ item.title }}</li>
<li v-for="(value, key) in obj" :key="key">{{ key }} = {{ value }}</li>
```

**`:key` — не формальность, а обязательное условие корректности.** Vue переиспользует
существующие DOM-узлы при изменении списка; `:key` говорит ему, «какой узел соответствует
какому элементу данных». Без стабильного `key` (или с `key="index"`) при вставке/удалении
в середину Vue перепутает узлы: состояние внутри элементов (значение `input`, фокус,
анимация) «переедет» не туда. Бери в `:key` **стабильный уникальный id**, не индекс
массива.

> **Go-параллель.** `v-for` — это `for range` по слайсу/мапе, только результат —
> поддерево DOM. А `:key` — как первичный ключ строки в таблице: по нему движок понимает,
> что «это та же сущность, что и раньше», а не новая.

### `v-model` — двусторонняя привязка форм

Ввод в поле должен и читать состояние, и писать в него. Связать вручную — это
`:value="x"` + `@input="x = $event.target.value"`. `v-model` — сахар ровно над этой парой:

```vue
<input v-model="search" />            <!-- ≡ :value + @input -->
<textarea v-model="comment" />
<input type="checkbox" v-model="agree" />     <!-- boolean -->
<select v-model="city"> ... </select>
```

`v-model` — «двустороннее связывание», но без магии: это по-прежнему явные «прочитать
значение» и «записать по событию», просто записанные одним словом. На компонентах
`v-model` тоже работает — об этом в модуле 03.

## Стилизация

### `:class` — классы по состоянию

Класс часто зависит от данных. `:class` принимает объект `{ имя: условие }` или массив:

```vue
<template>
  <button
    :class="{ active: isActive, 'is-loading': loading }"
    class="btn"
  >
    Кнопка
  </button>

  <span :class="[sizeClass, isError ? 'text-red' : 'text-green']">статус</span>
</template>
```

Статический `class="btn"` и динамический `:class` **складываются** — оба попадут в DOM.
Объектная форма читается лучше всего: «класс `active`, если `isActive`».

### `:style` — инлайн-стили (по необходимости)

```vue
<div :style="{ color: textColor, width: barWidth + 'px' }">…</div>
```

Инлайн-стили оправданы для **вычисляемых** значений (ширина прогресс-бара от процента).
Для всего остального предпочитай **классы**: их проще переопределять, кэшировать и не
плодить «магические числа» в разметке (см. гайдлайны кода — scoped-классы вместо инлайна).

### `<style scoped>` — изоляция стилей компонента

```vue
<style scoped>
.btn { padding: 8px 12px; }
</style>
```

`scoped` означает: эти правила применяются **только к элементам этого компонента**, а не
протекают на всю страницу. Механика: компилятор добавляет каждому элементу компонента
уникальный атрибут (вроде `data-v-7a8f`) и дописывает его в селекторы (`.btn[data-v-7a8f]`).
Это решает вечную боль глобального CSS — случайные коллизии имён классов между компонентами.

> **Почему это важно Go-разработчику.** Глобальный CSS — это как глобальные переменные:
> один `.title` где-то переопределил твой `.title` здесь, и ищи потом. `scoped` —
> локальная область видимости для стилей, аналог неэкспортируемых имён в пакете.

### Доступность на минималках (три привычки)

Дизайн-системы вне нашей темы, но три вещи стоят одной строки внимания и отличают
работающий интерфейс от «почти работающего»:

1. **Кликабельное делай кнопкой.** `<button @click>` вместо `<div @click>`: кнопка
   доступна с клавиатуры (Tab + Enter/Space), объявляется скринридером и умеет `disabled`.
   `div` с обработчиком — ни одного из этих свойств.
2. **Поле ввода связывай с подписью.** `<label for="email">` + `<input id="email">` (или
   `<input>` внутри `<label>`, как в уроке про список дел). Клик по подписи ставит фокус в
   поле, а пользователь скринридера слышит, что вводит.
3. **Не полагайся только на цвет.** Ошибку показывай текстом рядом с полем, а не одной
   красной рамкой.

Ещё полезная привычка — `alt` у картинок (`<img :alt="user.name">`) и осмысленный текст
ссылок. Всё это ничего не стоит на этапе написания и очень дорого стоит потом.

### Интеграция Tailwind CSS

**Tailwind** — это утилитарный CSS-фреймворк: вместо своих классов ты собираешь вид из
готовых атомарных (`flex`, `gap-2`, `px-4`, `text-red-500`). Он отлично дружит с Vue, потому
что классы пишутся прямо в `:class`/`class`, а реактивность Vue ими управляет.

Подключение к проекту `npm create vue@latest` (Vite 7) на актуальном Tailwind v4:

```bash
# Команды запускает пользователь сам. Версии пинуем точно.
npm install -D =tailwindcss@4.1.0 =@tailwindcss/vite@4.1.0
```

`vite.config.ts` — подключаем официальный плагин Tailwind рядом с плагином Vue:

```ts
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [vue(), tailwindcss()],
});
```

Главный CSS-файл (например `src/assets/main.css`), импортируемый в `main.ts`:

```css
@import "tailwindcss";
```

После этого утилиты доступны везде:

```vue
<template>
  <button
    class="rounded-md px-4 py-2 font-medium text-white"
    :class="loading ? 'bg-gray-400' : 'bg-teal-600 hover:bg-teal-700'"
  >
    Сохранить
  </button>
</template>
```

Заметь: **статические** утилиты — в `class`, а то, что зависит от состояния, — в `:class`.
Vue и Tailwind делят зону ответственности без конфликтов. Когда Tailwind уместен — вопрос
вкуса команды; для учебных целей знай, что интеграция тривиальна, и не воюй с инлайн-стилями
там, где утилитарный класс читается лучше.

> Tailwind v4 настраивается через CSS (`@theme` в том же файле), а не через большой
> `tailwind.config.js`, как было в v3. Если встретишь старый проект с `tailwind.config.js`
> и `@tailwind base/components/utilities` — это v3, механика та же, синтаксис подключения
> другой.

## Типичные ошибки и заблуждения

- **«`{{ }}` работает и в атрибутах».** Нет: в тексте — `{{ }}`, в атрибутах — `v-bind`/`:`.
  `<img src="{{ url }}">` не сработает; нужно `:src="url"`.
- **«`:key` можно не ставить / поставить индекс».** `:key` обязателен в `v-for` и должен
  быть стабильным id. Индекс ломает переиспользование DOM при вставке/удалении в середину.
- **«`v-if` и `v-show` — одно и то же».** `v-if` добавляет/убирает узлы; `v-show` лишь
  переключает `display`. Разная цена для редких vs частых переключений.
- **«`v-model` — это какая-то магия двустороннего связывания».** Это сахар над
  `:value` + `@input`. Никакой магии, обычные чтение и запись.
- **«Логику можно писать прямо в `{{ }}`».** Можно выражение, но сложное лучше в
  `computed`: читаемее и кэшируется.
- **«Scoped-стили полностью изолируют всё».** Они скоупят селекторы компонента, но
  глобальные стили и наследуемые свойства (шрифт, цвет) всё ещё действуют; для
  «дотянуться» до потомка есть `:deep()` (на будущее).
- **«`@` в импортах — это npm-пакет».** Нет, это алиас на `src/`, настроенный в
  `vite.config.ts`/`tsconfig`.
- **«Кликабельный `div` — нормально».** Нет: нет фокуса с клавиатуры, нет роли для
  скринридера, нет `disabled`. Кликабельное — `<button>`.

## Глоссарий модуля

- **SFC (Single File Component)** — файл `.vue` с блоками `<script setup>`, `<template>`,
  `<style>`.
- **`<script setup>`** — сахар Composition API: всё с верхнего уровня доступно в шаблоне.
- **Монтирование (`mount`)** — вставка приложения/компонента в реальный DOM-элемент.
- **Точка входа** — `src/main.ts`: создаёт приложение (`createApp`) и монтирует его.
- **Директива** — атрибут `v-*`, который компилятор превращает в код (`v-if`, `v-for`,
  `v-model`, сокращения `:` и `@`).
- **Интерполяция** — `{{ выражение }}` в тексте.
- **Модификатор события** — `.prevent`, `.stop`, `.enter` и др.
- **`:key`** — стабильный идентификатор элемента списка для сопоставления DOM-узлов.
- **Scoped-стили** — CSS, ограниченный компонентом через атрибут `data-v-*`.
- **Алиас `@`** — псевдоним пути на `src/`.
- **HMR (hot module replacement)** — горячая замена модуля без перезагрузки страницы.
- **Утилитарный CSS** — подход Tailwind: вид собирается из атомарных классов.
