# Реактивность и ментальная модель Vue

## Нулевой шаг: что вообще происходит в браузере

Ты пришёл из мира, где программа — это процесс, который читает вход и пишет выход. Во
фронтенде декорации другие, и без них дальше будет туман. Пять минут на базу.

- **HTML** — текст с разметкой, который приходит от сервера. Браузер его разбирает и
  строит **DOM** (Document Object Model) — дерево объектов в памяти, где каждый тег стал
  узлом со свойствами и методами. Экран — это картинка, нарисованная по этому дереву.
- **DOM — это API, а не файл.** Из JavaScript можно найти узел
  (`document.querySelector`), поменять ему текст, добавить класс, повесить обработчик. Как
  только дерево изменилось, браузер перерисовывает соответствующий кусок экрана.
- **Браузер — это рантайм** (в терминах TS-домена): движок JS + DOM + сеть (`fetch`) +
  хранилища + таймеры. Твой код живёт внутри вкладки, в **одном потоке**, и делит его с
  отрисовкой. Отсюда правило, которое будет всплывать постоянно: заблокировал поток —
  заморозил интерфейс.
- **События** — способ, которым браузер сообщает о действиях пользователя (`click`,
  `input`, `submit`). Код на них подписывается, браузер вызывает подписчиков.
- **SPA (single-page application)** — приложение, где сервер отдаёт **одну** HTML-страницу
  и JS-бандл, а дальше все «страницы» рисует JavaScript, подменяя куски DOM и меняя URL без
  перезагрузки. Всё, что мы строим в этом домене, — SPA.

Vue живёт ровно в этом месте: он берёт на себя **работу с DOM**, а тебе оставляет описание
того, как данные превращаются в разметку.

> **Простыми словами.** DOM — это «дерево виджетов» страницы, живое и изменяемое. Раньше
> программисты дёргали его руками, узел за узлом. Vue — это слой, который дёргает его за
> тебя, глядя на твои данные.

## Суть: что вообще продаёт фреймворк

Представь задачу: на странице есть число и кнопка. Жмёшь кнопку — число растёт, и
надпись на экране обновляется. В «голом» вебе ты бы делал это **императивно**, руками:

```ts
let count = 0;
const label = document.querySelector("#label")!;
const button = document.querySelector("#btn")!;

button.addEventListener("click", () => {
  count++;
  label.textContent = `Счёт: ${count}`;   // <-- ты ВРУЧНУЮ синхронизируешь DOM с count
});
```

Пока поле одно — терпимо. Но в реальном UI у тебя десятки значений, и каждое влияет на
несколько кусков экрана. Императивный подход превращается в паутину «не забудь обновить
вот это, и вон то, и ещё табличку». Большинство багов интерфейса — это именно
**рассинхрон**: данные изменились, а нарисованное забыли поправить.

Vue (как и React, Svelte, Solid) продаёт одну идею: **ты описываешь, как UI выглядит
как функция от состояния, а синхронизацию берёт на себя фреймворк.** Это
**декларативный** подход:

```vue
<script setup lang="ts">
import { ref } from "vue";
const count = ref(0);
</script>

<template>
  <button @click="count++">Счёт: {{ count }}</button>
</template>
```

Здесь нет ни одной строчки «найди элемент и поменяй textContent». Ты сказал: «текст
кнопки — это `Счёт: {{ count }}`». Всё. Когда `count` меняется, Vue сам перерисовывает
ровно то, что зависит от `count`. Связь «данные → экран» теперь декларация, а не твоя
ручная работа.

> **Аналогия с Go.** В Go нет встроенной реактивности: если у тебя поменялось поле
> структуры, никто автоматически не перерисует терминал или не пошлёт новый HTML. Ты
> сам решаешь, когда и что вывести. Реактивность Vue — это как если бы у тебя был
> «наблюдаемый» тип, и любой, кто его читал, автоматически переподписывался на
> изменения. В стандартном Go ближайшее по духу — каналы (`chan`) и явная рассылка
> уведомлений, но это ты строишь руками. Vue делает это незаметно на уровне обращения
> к полю.

## Что такое реактивность технически

**Реактивность** — это система, которая:

1. **отслеживает** (track), какие данные были прочитаны во время вычисления чего-либо
   (рендера компонента, `computed`, эффекта);
2. при **изменении** этих данных **запускает заново** (trigger) ровно те вычисления,
   которые от них зависели.

То есть это автоматический граф зависимостей «значение → кто его читает». Прочитал
`count` внутри рендера — рендер подписался на `count`. Изменил `count` — Vue знает, кого
дёрнуть. Современные фреймворки называют такие отслеживаемые ячейки **сигналами**
(signals); во Vue это `ref` и `reactive`. Под капотом Vue 3 строит этот граф через
JavaScript `Proxy` и пары функций `track`/`trigger`. Тебе не нужно знать детали реализации
наизусть, но держи в голове модель: **чтение подписывает, запись уведомляет.**

## Что происходит между «данные изменились» и «экран обновился»

Реактивность отвечает на вопрос «кого перезапустить». Второй вопрос — «как именно поменять
экран», и здесь у Vue есть свой механизм, о котором полезно знать заранее, потому что
термины встретятся везде.

1. **Компиляция шаблона.** Твой `<template>` не интерпретируется в браузере построчно: на
   этапе сборки компилятор Vue превращает его в **render-функцию** — обычную JS-функцию,
   которая возвращает описание разметки. Проверить это можно в
   [SFC Playground](https://play.vuejs.org) — там есть вкладка со сгенерированным кодом.
2. **Virtual DOM.** Render-функция возвращает не настоящие DOM-узлы, а лёгкие объекты
   («виртуальные узлы»): «тег `li`, класс `done`, текст такой-то». Это и есть **Virtual
   DOM** — описание того, как экран должен выглядеть *сейчас*.
3. **Патчинг.** Vue сравнивает новое описание с предыдущим и трогает в реальном DOM
   **только различия** — меняет один текст вместо перерисовки всего списка. Настоящие
   операции с DOM дороги, а сравнение объектов в памяти дёшево; на этом и держится выигрыш.

```
состояние (ref) → render-функция → Virtual DOM → сравнение → точечные изменения DOM
     ↑                                                                    │
     └──────────────── реактивность решает, когда это запустить ──────────┘
```

> **Простыми словами.** Virtual DOM — это черновик страницы на бумажке. Vue рисует новый
> черновик, сравнивает со старым и переносит на «чистовик» (реальный DOM) только те правки,
> которые действительно изменились.

Важно: **Virtual DOM — это оптимизация, а не источник истины.** Источник истины — твоё
состояние. И, забегая вперёд, Vue сейчас учится обходиться без Virtual DOM вовсе (Vapor
Mode, врезка в конце модуля) — компилируя шаблон сразу в точечные обновления узлов. API,
который ты учишь, от этого не меняется.

## Реактивные примитивы

### `ref` — реактивная ячейка для одного значения

`ref(initial)` оборачивает значение в реактивный контейнер. Доступ — через `.value`:

```ts
import { ref } from "vue";

const count = ref(0);        // Ref<number>
console.log(count.value);    // 0   <-- читаем через .value
count.value++;               // пишем через .value, и это триггерит обновления
count.value = 10;
```

Зачем `.value`, а не просто `count`? Потому что в JavaScript нельзя перехватить чтение
и присваивание **примитива** (число, строка, boolean) — они копируются по значению, и у
них нет «места», за которым можно следить. Поэтому Vue заворачивает значение в объект с
одним свойством `value` и вешает реактивность на это свойство. `.value` — это цена,
которую платишь за реактивный примитив.

> **TS-параллель.** `ref(0)` имеет тип `Ref<number>` — это дженерик-обёртка, ровно как
> ты бы сам написал `type Ref<T> = { value: T }` в TS-домене. Vue выводит `T` из
> начального значения. Хочешь явно — `const count = ref<number>(0)` или
> `const user = ref<User | null>(null)`.

Важная поблажка: **в шаблоне `.value` писать не надо.** Vue автоматически разворачивает
ref-ы верхнего уровня в `<template>`. Поэтому в JS — `count.value`, а в шаблоне —
`{{ count }}`. Это частый источник путаницы первые пару дней.

### `reactive` — реактивный объект целиком

`reactive(obj)` делает реактивным **весь объект** (через `Proxy`). Доступ — обычный, без
`.value`:

```ts
import { reactive } from "vue";

const state = reactive({
  count: 0,
  user: { name: "Ann" },
});

state.count++;            // реактивно, без .value
state.user.name = "Bob";  // глубоко реактивно: вложенные объекты тоже отслеживаются
```

Выглядит приятнее `ref` — нет `.value`. Но у `reactive` есть жёсткие ограничения,
которые и делают `ref` рекомендуемым выбором по умолчанию:

- **Только объекты, массивы, Map/Set.** Примитив `reactive(5)` не сработает —
  оборачивать-то нечего (см. объяснение `.value` выше).
- **Нельзя переприсвоить целиком.** `state = reactive({...})` потеряет реактивность:
  ты заменил саму ссылку, а компонент держал старый proxy.
- **Разваливается при деструктуризации.** Вот главная граблина — отдельный раздел ниже.

**Практическое правило (как советует официальная документация):** по умолчанию бери
`ref` для всего — и для примитивов, и для объектов. `reactive` оставь для случаев, когда
действительно удобнее сгруппировать связанные поля в один объект и ты не собираешься его
переприсваивать. `ref(object)` внутри тоже разворачивается в `reactive`, так что глубокая
реактивность у тебя всё равно есть.

### `computed` — производное значение, которое кэшируется

Очень часто значение не хранят, а **выводят** из других. Для этого — `computed`:

```ts
import { ref, computed } from "vue";

const price = ref(100);
const qty = ref(3);

const total = computed(() => price.value * qty.value);   // ComputedRef<number>

console.log(total.value);   // 300
qty.value = 5;
console.log(total.value);   // 500 — пересчиталось само
```

`computed` сам отследил, что читает `price` и `qty`, и подписался на них. Меняешь любую
зависимость — `total` помечается «грязным» и пересчитается при следующем чтении. Ключевое
слово — **кэшируется**: если зависимости не менялись, повторное чтение `total.value`
вернёт сохранённый результат, **не вызывая функцию заново**. Это отличие от обычной
функции:

```ts
// Просто функция — считает КАЖДЫЙ раз при вызове, даже если ничего не менялось.
const totalFn = () => price.value * qty.value;

// computed — считает только когда изменились price или qty, иначе отдаёт кэш.
const totalComputed = computed(() => price.value * qty.value);
```

Поэтому в шаблоне для любых производных значений бери `computed`, а не вызов функции:
дешевле и понятнее. `computed` по умолчанию **только для чтения** — ты описываешь, *как*
значение выводится, а не присваиваешь его (записываемый computed существует, но это
редкий случай).

> **Go-параллель.** `computed` — это ленивый, кэширующий, самоинвалидирующийся
> `getter`. В Go ты бы написал метод `func (o *Order) Total() int { return o.Price *
> o.Qty }` — но он считает каждый вызов и ничего не кэширует. `computed` добавляет
> к этому кэш + автоматическую инвалидацию по зависимостям.

### `watch` и `watchEffect` — побочные эффекты на изменение

`computed` хорош, когда результат — **значение**. Но иногда на изменение данных надо
сделать **действие**: отправить запрос, записать в localStorage, залогировать. Это
**побочный эффект**, и для него есть `watch`:

```ts
import { ref, watch } from "vue";

const userId = ref(1);

watch(userId, (newId, oldId) => {
  console.log(`был ${oldId}, стал ${newId}`);
  // тут можно сходить за данными нового пользователя
});

userId.value = 2;   // watch сработает: был 1, стал 2
```

`watch` явно указывает источник (`userId`) и даёт тебе старое и новое значение. Можно
следить за несколькими источниками (`watch([a, b], ...)`) или за геттером
(`watch(() => state.count, ...)`).

`watchEffect` — её младшая сестра: ты не перечисляешь источники, она **сама** подписывается
на всё реактивное, что прочитала внутри, и запускается сразу при создании:

```ts
import { ref, watchEffect } from "vue";

const a = ref(1), b = ref(2);

watchEffect(() => {
  console.log(`сумма = ${a.value + b.value}`);   // подписалась на a и b автоматически
});
// сработает сразу: "сумма = 3", и потом на каждое изменение a или b
```

Когда что брать:

| Хочешь… | Бери |
|---|---|
| Вывести новое **значение** из других | `computed` |
| Сделать **действие** при изменении конкретного источника, нужен `old`/`new` | `watch` |
| Сделать действие, зависящее от нескольких значений, и лень их перечислять | `watchEffect` |

**Правило по умолчанию:** если можешь выразить через `computed` — выражай через
`computed`. `watch`/`watchEffect` — для эффектов (I/O, логирование, ручная синхронизация
с не-реактивным миром), а не для «посчитать B из A». Новички часто пишут `watch`, который
обновляет другой `ref`, хотя это ровно работа `computed`.

### Ещё несколько реактивных утилит (знать в лицо)

Полный список большой, но четыре встречаются регулярно:

```ts
import { shallowRef, readonly, toRef, isRef } from "vue";

const big = shallowRef({ rows: [] });   // реактивна только замена .value целиком,
                                         // изменения ВНУТРИ объекта не отслеживаются
const publicState = readonly(state);     // только для чтения (полезно отдавать наружу)
const nameRef = toRef(props, "name");    // ref, «смотрящий» на свойство объекта/props
isRef(x);                                // проверить, ref ли это
```

- **`shallowRef`** — когда в ячейке лежит что-то большое и меняется целиком (результат
  запроса, инстанс сторонней библиотеки, карта, редактор). Глубокая реактивность стоит
  памяти и времени: не отслеживай то, за чем не собираешься следить.
- **`readonly`** — «отдаю значение, но менять его снаружи нельзя». Хороший тон для
  состояния, у которого есть свои методы изменения.
- **`toRef(props, "name")`** — способ получить реактивную ссылку на конкретное поле, не
  теряя связи (та же идея, что `toRefs`, но для одного свойства).

## Обновление DOM асинхронно: `nextTick`

Ещё одна деталь, которая экономит часы отладки. **Vue не перерисовывает DOM в тот же
момент, когда ты поменял значение.** Изменения накапливаются и применяются одной пачкой в
конце текущей задачи — в микрозадаче (помнишь микро/макрозадачи из TS-домена?).

```ts
const count = ref(0);

count.value = 1;
count.value = 2;
count.value = 3;   // рендер произойдёт ОДИН раз, с итоговым значением 3
```

Это называется **батчингом** и защищает от лишних перерисовок. Плата — маленькое, но
принципиальное следствие: сразу после изменения состояния DOM ещё старый.

```ts
import { nextTick } from "vue";

showInput.value = true;
inputRef.value?.focus();          // ❌ элемента ещё нет в DOM — null

showInput.value = true;
await nextTick();                  // ждём применения изменений
inputRef.value?.focus();          // ✅ теперь элемент есть
```

`nextTick()` возвращает промис, который резолвится после того, как Vue применил
накопленные изменения к DOM. Нужен он редко — почти всегда только для работы с реальным
DOM (фокус, измерения, прокрутка) и в тестах (поэтому в Vue Test Utils столько `await`).

> **Простыми словами.** Vue — как редактор, который сохраняет файл не на каждую букву, а
> когда ты перестал печатать. `nextTick` — это «дождаться сохранения».

## Как Vue отслеживает зависимости (модель «под капотом»)

Не обязательно знать реализацию наизусть, но рабочая модель экономит часы отладки.

Каждое реактивное чтение происходит **внутри какого-то активного эффекта** — это рендер
компонента, тело `computed` или коллбэк `watchEffect`. Vue в этот момент держит ссылку на
«кто сейчас вычисляется». Когда ты читаешь `count.value`, геттер вызывает `track`:
«запиши, что текущий эффект зависит от `count`». Когда пишешь `count.value = x`, сеттер
вызывает `trigger`: «перезапусти все эффекты, которые зависели от `count`».

Два следствия, которые реально влияют на код:

1. **Отслеживается только то, что прочитано синхронно в момент вычисления.** Если ты
   прочитал значение внутри `setTimeout` или после `await`, на момент чтения активного
   эффекта уже нет — подписки не будет. (К `watch`/`watchEffect` это особенно относится:
   подписка собирается на синхронном проходе.)
2. **Реактивность живёт на свойствах объекта, а не на значениях.** Поэтому деструктуризация
   «выдёргивает» значение из-под наблюдения — об этом сразу же.

> Эта же модель «чтение подписывает / запись уведомляет» — основа **сигналов**, к которым
> индустрия пришла независимо (Solid, Svelte 5, Angular signals). Vue 3.6 с **Vapor Mode**
> доводит её до предела: компилятор генерирует код, который точечно меняет нужные узлы DOM
> вообще без Virtual DOM. API при этом тот же `ref`/`computed`, что ты учишь сейчас, —
> так что вкладываешься ты в правильное. Подробнее — врезка в конце.

## Главные грабли реактивности

### 1. Забыл `.value`

```ts
const count = ref(0);
count++;                    // ❌ "count" — это объект Ref, не число; так его не увеличишь
console.log(count + 1);     // ❌ "[object Object]1" — складываешь объект со строкой
count.value++;              // ✅
```

В JS обращение `count` (без `.value`) даёт сам объект-обёртку, а не число. TypeScript тут
твой друг: на `count++` он ругнётся, что у `Ref<number>` нет числовой семантики. В шаблоне
же — наоборот, `.value` писать **не надо** (Vue развернёт сам). Эта асимметрия «в JS с
`.value`, в шаблоне без» — нормальный источник спотыкания первые дни.

### 2. Потеря реактивности при деструктуризации `reactive`

```ts
const state = reactive({ count: 0 });

let { count } = state;      // ❌ скопировали ЗНАЧЕНИЕ 0 в обычную переменную
count++;                    // меняем локальную переменную, state.count не трогаем
// шаблон, завязанный на state.count, не обновится
```

Деструктуризация читает свойство **один раз** и кладёт его значение в новую переменную —
связь с proxy теряется. То же самое произойдёт, если передать `state.count` в функцию: уйдёт
число, не реактивная ячейка. Лечение: либо не деструктурировать (`state.count`), либо
обернуть нужные поля в `ref` через `toRefs`:

```ts
import { reactive, toRefs } from "vue";

const state = reactive({ count: 0, name: "Ann" });
const { count, name } = toRefs(state);   // теперь count: Ref<number>, name: Ref<string>
count.value++;                            // ✅ реактивно, связь со state сохранена
```

> **Почему Go-разработчику это особенно непривычно.** В Go деструктуризации в этом смысле
> нет, но интуиция «передал значение — отдал копию» как раз *правильная*: `reactive`-поле
> при копировании ведёт себя как value, а не как указатель на «живую» ячейку.
> `ref`/`toRefs` возвращают тебе именно «указатель на живое».

### 3. `watch`, который должен был быть `computed`

```ts
// ❌ так делают новички
const fullName = ref("");
watch([firstName, lastName], () => {
  fullName.value = `${firstName.value} ${lastName.value}`;
});

// ✅ это же самое — одно объявление, кэш, никакого лишнего состояния
const fullName = computed(() => `${firstName.value} ${lastName.value}`);
```

Лишний `ref` + `watch` = лишнее состояние, которое можно рассинхронить. `computed`
самодостаточен и не врёт.

### 4. Реактивность не делает асинхронность многопоточной

`watch`/эффекты — это всё ещё один поток выполнения JS. Реактивность красиво
перерисовывает UI, но если внутри эффекта ты запускаешь долгую синхронную работу, она
**заблокирует** интерфейс. Никаких goroutines: тяжёлое — в `async`/Web Worker, как
обсудим в модуле 07. Пришёл из Go — не жди, что «оно само распараллелится».

## Типичные ошибки и заблуждения

- **«Реактивность — это магия / двойное связывание как в старом Angular».** Нет, это
  явный граф «чтение → подписка, запись → уведомление». Понимаешь модель — исчезает магия.
- **«`reactive` лучше, потому что без `.value`».** Удобнее на вид, но ломается на
  деструктуризации и переприсваивании. Дефолт — `ref`.
- **«В шаблоне тоже надо `.value`».** Нет, Vue разворачивает ref-ы верхнего уровня в
  шаблоне сам. `.value` — только в `<script>`.
- **«`computed` и метод/функция — одно и то же».** `computed` кэширует и пересчитывается
  только по зависимостям; функция считает каждый вызов.
- **«`watch` — главный инструмент для производных значений».** Наоборот, производные —
  это `computed`. `watch` — для побочных эффектов.
- **«Если поменять данные внутри `setTimeout`/после `await`, оно само подпишется».**
  Подписка собирается синхронно; то, что прочитано после паузы, может не отследиться.
- **«Поменял состояние — DOM сразу обновился».** Нет, обновления батчатся и применяются в
  микрозадаче. Нужен свежий DOM — `await nextTick()`.
- **«Virtual DOM — это то, что хранит моё состояние».** Нет, это лишь описание разметки для
  сравнения. Источник истины — твои `ref`/`reactive`.
- **«Глубокая реактивность бесплатна».** Нет: для больших объектов, которые меняются
  целиком, дешевле `shallowRef`.

## Врезка: куда движется Vue (Vapor Mode)

Обещанная врезка. Vue 3.6 приносит **Vapor Mode** — альтернативный режим компиляции, в
котором шаблон превращается **не** в render-функцию с Virtual DOM, а сразу в код, который
точечно создаёт и обновляет нужные DOM-узлы. Сравнения черновиков нет вообще: «этот `ref`
меняет вот этот текстовый узел, и точка».

Что это значит практически:

- **API не меняется.** Всё, что ты учишь — `ref`, `computed`, `watch`, `<script setup>`,
  props/emits — остаётся тем же. Меняется то, во что компилируется шаблон.
- **Меньше бандл и быстрее обновления** — за счёт отсутствия рантайма Virtual DOM.
- **Это опциональный режим**, включаемый на уровне компонента/приложения, и на момент
  написания курса он молодой. Учиться на нём не нужно; знать о его существовании — да,
  потому что он объясняет, почему индустрия говорит про «сигналы» (Solid, Svelte 5, Angular
  signals) как про общий вектор.

Вывод для тебя: фундамент, который ты закладываешь сейчас (состояние → зависимости →
автоматическое обновление), — это ровно то, на чём Vapor и стоит. Вкладываешься в
правильное.

## Глоссарий модуля

- **DOM** — дерево объектов, представляющее страницу; менять его = менять экран.
- **Рантайм браузера** — движок JS плюс окружение: DOM, `fetch`, таймеры, хранилища.
- **SPA** — приложение из одной HTML-страницы, где «страницы» рисует JS.
- **Декларативный / императивный** — «опиши результат» против «опиши шаги».
- **Реактивность** — автоматическая связь «данные → зависящие от них вычисления».
- **Сигнал** — общее индустриальное название реактивной ячейки (во Vue это `ref`).
- **track / trigger** — «чтение подписывает» / «запись уведомляет».
- **Эффект** — вычисление, которое перезапускается при изменении зависимостей (рендер,
  `computed`, `watchEffect`).
- **`ref` / `reactive`** — реактивная ячейка / реактивный объект (Proxy).
- **`computed`** — кэшируемое производное значение.
- **`watch` / `watchEffect`** — побочные эффекты на изменение (с явным источником / с
  авто-подпиской).
- **Render-функция** — функция, в которую компилируется шаблон.
- **Virtual DOM** — лёгкое описание желаемой разметки; сравнивается с предыдущим.
- **Патчинг** — применение только различий к реальному DOM.
- **Батчинг / `nextTick`** — накопление изменений и точка, где DOM уже обновлён.
- **Vapor Mode** — режим компиляции без Virtual DOM (Vue 3.6+).
