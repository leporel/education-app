# Карточки

## Ментальная модель

```card
front: В одной фразе — что фреймворк вроде Vue берёт на себя, чего нет в «голом» DOM?
back: Синхронизацию «состояние → экран». Ты декларативно описываешь UI как функцию от данных, а Vue сам перерисовывает то, что зависит от изменившихся данных. Никакого ручного label.textContent = ...
tags: [vue, mental-model]
```

```card
front: Что такое реактивность технически (две операции)?
back: track (чтение реактивного значения подписывает текущий эффект/рендер на него) и trigger (запись уведомляет и перезапускает подписанные эффекты). Автоматический граф «значение → кто его читает».
tags: [vue, reactivity]
```

## ref / reactive

```card
front: Зачем у ref нужен .value, а у reactive — нет?
back: ref оборачивает значение (в т.ч. примитив) в объект { value }, потому что за примитивом нельзя следить напрямую. reactive вешает Proxy на сам объект, поэтому доступ обычный. В шаблоне .value не нужен — Vue разворачивает ref сам.
tags: [vue, ref, reactive]
```

```card
front: Почему ref рекомендуют как выбор по умолчанию, а не reactive?
back: reactive работает только с объектами, ломается при переприсваивании целиком и при деструктуризации. ref универсален (примитивы и объекты) и переживает переприсваивание (count.value = ...).
tags: [vue, ref, reactive]
```

```card
front: "const { count } = reactive({ count: 0 }) — что не так?"
back: "Деструктуризация копирует значение 0 в обычную переменную, связь с proxy теряется — реактивности нет. Решение: обращаться через state.count или взять toRefs(state)."
tags: [vue, reactive, pitfall]
```

## computed / watch

```card
front: Чем computed отличается от обычной функции, считающей то же значение?
back: computed кэшируется и пересчитывается только при изменении зависимостей; функция считает на каждый вызов. computed по умолчанию readonly и сам отслеживает, что прочитал.
tags: [vue, computed]
```

```card
front: Когда брать computed, когда watch, когда watchEffect?
back: computed — вывести значение из других. watch — сделать побочный эффект на изменение конкретного источника (есть old/new). watchEffect — эффект, зависящий от нескольких значений, с авто-подпиской на прочитанное.
tags: [vue, computed, watch]
```

```card
front: "Частый антипаттерн: watch, обновляющий другой ref. В чём ошибка?"
back: Это работа computed. Лишний ref + watch создаёт дублирующее состояние, которое можно рассинхронить. fullName = computed(() => `${a.value} ${b.value}`) — одно объявление, кэш, без лишнего стейта.
tags: [vue, watch, computed, pitfall]
```

## Под капотом / грабли

```card
front: Почему значение, прочитанное после await или внутри setTimeout, может не отследиться?
back: Подписка (track) собирается синхронно, пока активен эффект. После паузы активного эффекта уже нет, поэтому чтение не создаёт подписку.
tags: [vue, reactivity, async]
```

```card
front: Делает ли реактивность асинхронный код многопоточным (как goroutines)?
back: Нет. Это всё тот же один JS-поток. Тяжёлую синхронную работу внутри эффекта заблокирует UI. Параллелизм — отдельная история (async/Web Worker), реактивность только про синхронизацию состояния и экрана.
tags: [vue, reactivity, concurrency]
```

```card
front: Куда движется реактивность Vue (3.6 / Vapor Mode)?
back: "К компиляции без Virtual DOM: компилятор генерирует код, точечно меняющий нужные DOM-узлы (сигнальная модель, как Solid/Svelte 5). API ref/computed остаётся тем же — вкладываешься в правильное."
tags: [vue, vapor, future]
```

## Браузер, DOM, рендеринг

```card
front: Что такое DOM и почему через него «видно» изменения на экране?
back: Дерево объектов, в которое браузер разбирает HTML. Экран рисуется по этому дереву, поэтому изменение узла (текст, класс, атрибут) перерисовывает соответствующий кусок страницы. DOM — это API из JS, а не файл.
tags: [vue, dom, basics]
```

```card
front: Что такое SPA?
back: Приложение, где сервер отдаёт одну HTML-страницу и JS-бандл, а дальше «страницы» рисует JavaScript, подменяя части DOM и меняя URL без перезагрузки.
tags: [vue, spa]
```

```card
front: Во что компилируется <template> и что такое Virtual DOM?
back: Шаблон компилируется в render-функцию, возвращающую лёгкие объекты-узлы (Virtual DOM) — описание желаемой разметки. Vue сравнивает его с предыдущим и применяет к реальному DOM только различия (патчинг).
tags: [vue, vdom]
```

```card
front: Цепочка «состояние → экран» во Vue целиком?
back: состояние (ref) → render-функция → Virtual DOM → сравнение с предыдущим → точечные изменения реального DOM. Реактивность решает, КОГДА это запустить.
tags: [vue, vdom, reactivity]
```

## Батчинг и nextTick

```card
front: Обновляется ли DOM сразу после изменения ref?
back: Нет. Изменения батчатся и применяются одной пачкой в микрозадаче. Три присваивания подряд дадут один рендер с итоговым значением.
tags: [vue, nexttick]
```

```card
front: Когда нужен await nextTick()?
back: "Когда сразу после изменения состояния нужен уже обновлённый DOM: фокус на только что показанном элементе, измерение размеров, прокрутка. И в тестах (поэтому в Vue Test Utils много await)."
tags: [vue, nexttick, testing]
```

## Другие реактивные утилиты

```card
front: Когда брать shallowRef вместо ref?
back: "Когда значение большое и меняется целиком (ответ API, инстанс сторонней библиотеки): реактивна только замена .value, содержимое не отслеживается — дешевле по памяти и времени."
tags: [vue, shallowref]
```

```card
front: Зачем readonly() и toRef(props, 'name')?
back: readonly — отдать состояние наружу без права менять (менять только через свои методы). toRef — получить реактивную ссылку на одно свойство объекта/props, не теряя связи.
tags: [vue, readonly, toref]
```
