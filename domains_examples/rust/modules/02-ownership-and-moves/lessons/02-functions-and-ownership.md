# Урок 02 — Владение и функции: забрать, вернуть, одолжить

Цель: прожить, как владение пересекает границу функции, и увидеть три стратегии: забрать
владение, вернуть его обратно, либо одолжить ссылку (мостик в модуль 03).

## Разогрев

- Что станет с `String` после передачи в функцию по значению?
- Как вернуть владение обратно вызывающему?
- Почему ссылка часто лучше и того, и другого?

## Шаг 1. Функция забирает владение

```rust
fn consume(s: String) {
    println!("внутри: {s}");
}   // s дропается здесь — строка освобождена

fn main() {
    let name = String::from("Rust");
    consume(name);             // владение уехало в consume
    // println!("{name}");     // ❌ E0382: name перемещён
}
```

Передача не-`Copy` аргумента — это move. После `consume(name)` строка уже освобождена
(внутри функции `s` вышло из scope), и `name` трогать нельзя. Для `i32` было бы иначе:

```rust
fn squared(n: i32) -> i32 { n * n }

fn main() {
    let x = 4;
    let y = squared(x);        // i32 — Copy: x скопирован
    println!("{x} {y}");       // ок: 4 16
}
```

## Шаг 2. Вернуть владение обратно

Топорный, но рабочий способ продолжить пользоваться значением — вернуть его:

```rust
fn tag(mut s: String) -> String {
    s.push_str(" [done]");     // меняем (s — наш, владеем)
    s                          // возвращаем владение наружу (без return и без ;)
}

fn main() {
    let task = String::from("write Rust");
    let task = tag(task);      // отдали и получили обратно (с тем же именем — shadowing)
    println!("{task}");        // write Rust [done]
}
```

Работает, но представь функцию, которой нужно **посмотреть** на десять строк — гонять их
туда-обратно ради «почитать» абсурдно. Отсюда — ссылки.

## Шаг 3. Одолжить ссылку (превью модуля 03)

```rust
fn length(s: &String) -> usize {   // &String — заём, владение НЕ забираем
    s.len()
}

fn main() {
    let text = String::from("borrow me");
    let n = length(&text);          // &text — одолжили
    println!("{text} имеет длину {n}");   // text всё ещё наш!
}
```

Функция получила **ссылку** — почитала и вернула управление, владение всё это время
оставалось у `main`. Никакой move, никакой `clone`, ноль лишних аллокаций. Вот зачем
нужен заём: дать доступ, не отдавая собственность. В модуле 03 разберём это до правил
(`&` vs `&mut`, сколько ссылок можно сразу, и что такое lifetimes).

> **Go-параллель.** В Go ты постоянно передаёшь указатели (`*T`), чтобы не копировать
> большие структуры и/или чтобы функция могла менять оригинал. `&T`/`&mut T` в Rust — про
> то же самое, но с правилами, которые компилятор проверяет: например, нельзя одновременно
> иметь изменяемую ссылку и читать через другую. Это и убивает гонки данных.

## Шаг 4. Намеренно ошибёмся — использование после move в цикле

Частая ловушка новичка:

```rust
fn print_it(s: String) { println!("{s}"); }

fn main() {
    let label = String::from("tick");
    for _ in 0..3 {
        print_it(label);       // ❌ на второй итерации label уже перемещён
    }
}
```

```text
error[E0382]: use of moved value: `label`
  |
6 |         print_it(label);
  |                  ^^^^^ value moved here, in previous iteration of loop
```

Компилятор прямо говорит: «moved here, in previous iteration». Лечение — не отдавать
владение, а одолжить: `fn print_it(s: &str)` и `print_it(&label)`. Тогда `label` живёт
весь цикл.

## Итог

Граница функции подчиняется тем же правилам владения: не-`Copy` аргумент **перемещается**.
Три стратегии: **забрать** (функция становится владельцем и дропает), **вернуть** (отдать
и получить обратно) и — почти всегда лучшая для «почитать/посмотреть» — **одолжить ссылку**.
Последнее ведёт прямо в модуль 03, где заём обретает полные правила.
