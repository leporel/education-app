# Карточки

## Правила владения

```card
front: Три правила владения в Rust?
back: 1) У каждого значения есть владелец. 2) Владелец в каждый момент ровно один. 3) Когда владелец выходит из области видимости — значение дропается (память освобождается). Всё проверяется на компиляции.
tags: [rust, ownership]
```

```card
front: Что такое RAII и как оно освобождает память без GC?
back: Ресурс живёт ровно столько, сколько его владелец. Компилятор на компиляции знает, где владелец выходит из scope, и вставляет туда drop. Детерминированно, без сборщика мусора. Аналог автоматического defer на всё.
tags: [rust, raii, drop]
```

## Move vs Copy

```card
front: Почему let s2 = s1 для String делает move, а не копию?
back: String = заголовок на стеке (ptr/len/cap) + данные в куче. Копия заголовка дала бы два указателя на одну кучу → double free при дропе. Rust инвалидирует s1, оставляя одного владельца s2. Move двигает только заголовок, куча не трогается.
tags: [rust, move]
```

```card
front: Какие типы реализуют Copy (и потому копируются при =)?
back: "Числа (i32, u64, f64...), bool, char, и кортежи/массивы из Copy-типов. Общее: целиком лежат на стеке и ничем в куче не владеют. Как только тип владеет ресурсом (String, Vec, Box) — Copy нет, только move."
tags: [rust, copy]
```

```card
front: let x = 5; let y = x; println!("{x}"); — сработает? А для String?
back: "Для i32 — да: i32 это Copy, x остаётся валиден. Для String — нет: move, x инвалидирован, ошибка E0382 при использовании после move."
tags: [rust, copy, move]
```

## Clone и Drop

```card
front: Что делает clone() и почему его видно в коде — это плюс?
back: "clone() делает глубокую копию владеющего типа (новая аллокация + копирование байт). Видимость — фича: аллокации в Rust не прячутся, в горячем цикле .clone() заметен. В Go копии часто незаметны."
tags: [rust, clone]
```

```card
front: "Анти-паттерн: лепить .clone(), чтобы borrow checker замолчал. Почему плохо?"
back: Часто настоящий ответ — одолжить ссылку (&), а не копировать данные. Клонируй, когда реально нужна вторая независимая копия, а не просто почитать. Иначе — лишние аллокации.
tags: [rust, clone, pitfall]
```

```card
front: Когда вызывается Drop и в каком порядке для нескольких переменных?
back: При выходе владельца из области видимости. Порядок — обратный объявлению (LIFO), как defer в Go. Освобождает ресурс (куча/файл/мьютекс). Забыть нельзя — компилятор не даёт потерять владельца без drop.
tags: [rust, drop]
```

## Функции и владение

```card
front: Что происходит с не-Copy аргументом при передаче в функцию?
back: "Он перемещается (move) внутрь функции; после вызова исходная переменная невалидна. Чтобы пользоваться дальше: вернуть значение, клонировать, или (лучше) передать по ссылке &T — заём, модуль 03."
tags: [rust, ownership, functions]
```

```card
front: Чем drop в Rust лучше defer в Go по гарантиям?
back: defer надо написать руками у каждого ресурса и можно забыть. drop привязан к владению и вызывается автоматически для всего, что владеет ресурсом; компилятор гарантирует, что владелец не «потеряется» без очистки.
tags: [rust, drop, defer]
```

```card
front: Move физически копирует данные из кучи?
back: Нет. Move двигает только заголовок на стеке (ptr/len/cap). Байты в куче остаются на месте, просто меняется владелец и ответственность за их освобождение. Поэтому move дёшев.
tags: [rust, move, heap]
```

## Стек и куча

```card
front: Стек и куча — в чём разница простыми словами?
back: "Стек — блокнот, куда пишут только с конца: кадр функции создаётся при вызове и отрезается при возврате. Почти бесплатно, но размер значений должен быть известен на компиляции. Куча — склад с кладовщиком (аллокатором): просишь N байт, получаешь адрес. Любой размер и время жизни, но аллокация стоит работы, а доступ — прыжок по указателю."
tags: [rust, stack, heap]
```

```card
front: Где физически живёт String и почему это объясняет move?
back: На стеке — паспорт фиксированного размера (ptr/len/cap), в куче — сами байты. Move копирует только паспорт (3 слова) — поэтому дёшев; данные в куче не шевелятся, просто меняется владелец и ответственность за освобождение.
tags: [rust, string, move, heap]
```

```card
front: Почему Copy бывает только у «стек-онли» типов?
back: Copy — это разрешение честно скопировать значение побайтово. Если внутри есть указатель в кучу, копия дала бы двух владельцев одной аллокации (double free). Нет владения кучей → копия безвредна (i32, bool, char, кортежи из Copy-полей).
tags: [rust, copy, heap]
```

```card
front: "\"hello\" — это String?"
back: "Нет, это &'static str: ссылка на байты, вшитые в бинарник, живущие всю программу (не освобождаются, не меняются). String появляется только с аллокацией: String::from(\"hello\") или \"hello\".to_string()."
tags: [rust, str, string, literal]
```

## Частичное перемещение и drop

```card
front: Что такое частичное перемещение (partial move)?
back: "Вынос отдельного поля структуры: let name = u.name; для String-поля. Остальные поля доступны, но структуру как ЦЕЛОЕ использовать/двигать уже нельзя (error: use of partially moved value). Разобрать всё сразу можно деструктуризацией: let User { name, age } = u;"
tags: [rust, move, partial]
```

```card
front: Можно ли вызвать x.drop() вручную и как освободить значение досрочно?
back: "x.drop() запрещён компилятором (иначе получился бы двойной drop в конце scope). Досрочно освобождают функцией drop(x): она просто забирает значение себе и даёт ему умереть на месте."
tags: [rust, drop]
```
