# Карточки

## Зачем Rust

```card
front: Какую главную идею продаёт Rust по сравнению с Go?
back: Безопасность памяти и потоков БЕЗ сборщика мусора и без рантайма, проверенную на компиляции. Скорость C/C++ без его классов багов (use-after-free, double free, гонки данных). Цена — дисциплина владения (borrow checker).
tags: [rust, why]
```

```card
front: Что такое zero-cost abstractions?
back: Абстракции (итераторы, дженерики, async), которые компилируются в код не медленнее, чем написанный руками. Дженерики мономорфизируются (копия под каждый тип), а не боксируются как any в Go.
tags: [rust, zero-cost]
```

```card
front: Три кита безопасности Rust?
back: Ownership (один владелец, авто-освобождение на выходе из scope), Borrowing (много &T ИЛИ один &mut T), Lifetimes (ссылка не переживает данные). Всё проверяется на компиляции, в рантайме накладных расходов нет.
tags: [rust, ownership]
```

## Тулинг

```card
front: rustup vs cargo — кто за что отвечает?
back: rustup — менеджер тулчейнов (ставит/обновляет компилятор, переключает каналы stable/beta/nightly). cargo — сборка + зависимости + тесты + публикация (go build + go test + go mod в одном).
tags: [rust, tooling]
```

```card
front: Основные команды cargo?
back: cargo new (создать), run (собрать+запустить), build (собрать; --release для оптимизаций), test (тесты), fmt (формат), clippy (линтер), add (добавить зависимость).
tags: [rust, cargo]
```

```card
front: Cargo.toml / Cargo.lock vs go.mod / go.sum?
back: Cargo.toml — манифест (имя, версия, edition, зависимости с SemVer-диапазонами). Cargo.lock — лок точных версий (как go.sum, но про версии). Зависимости с crates.io.
tags: [rust, cargo]
```

```card
front: Чем версионирование зависимостей в Rust отличается от Go по умолчанию?
back: В Rust зависимость задаётся SemVer-диапазоном (anyhow = "1" → любая 1.x), а точные версии фиксирует Cargo.lock. В Go ты пинишь точную версию в go.mod.
tags: [rust, cargo, deps]
```

## Edition

```card
front: Что такое Edition в Rust и зачем она?
back: Набор включённых соглашений для конкретного крейта (2015/2018/2021/2024), позволяющий вводить несовместимые изменения языка без раскола экосистемы. Крейты разных редакций линкуются вместе. Это НЕ версия компилятора.
tags: [rust, edition]
```

```card
front: Edition vs версия компилятора — в чём разница?
back: Компилятор всегда последний (1.96+), и новые фичи прилетают во все редакции. Edition — лишь соглашения крейта; ломающие изменения применяются только при осознанном переходе (cargo fix --edition). Новые проекты — edition 2024.
tags: [rust, edition]
```

## Тизер ownership

```card
front: let s = String::from("hi"); let t = s; — почему потом нельзя использовать s?
back: "Владение строкой ПЕРЕМЕСТИЛОСЬ (move) в t, чтобы не было двух владельцев одной памяти. String не Copy. В Go это бы скопировало заголовок и оба остались валидны. Ошибка: error[E0382] borrow of moved value."
tags: [rust, move, ownership]
```

```card
front: println! — функция или макрос? Почему это видно?
back: Макрос — на это указывает ! в вызове. Форматная строка проверяется на компиляции. Пока можно думать о макросах как о «функциях со звёздочкой».
tags: [rust, macro]
```

## Модули и видимость

```card
front: Что такое «рантайм» языка и почему говорят, что у Rust его нет?
back: "Рантайм — код, который язык сам добавляет в программу: GC, планировщик, механизм паник. В Go он внутри каждого бинарника. Rust добавляет только крошечный запуск main — нет GC и нет планировщика, поэтому для async рантайм подключают библиотекой (Tokio)."
tags: [rust, runtime]
```

```card
front: Крейт vs модуль — что чему соответствует в Go?
back: Крейт — единица компиляции (одна библиотека или один бинарник), ближайший аналог — модуль Go целиком (go.mod). Модуль (mod) — пространство имён внутри крейта, ближе к пакету Go, но к папке не привязан.
tags: [rust, crate, module]
```

```card
front: Почему написанный файл src/utils.rs может «не существовать» для компилятора?
back: "Потому что файл становится частью крейта только когда объявлен: mod utils; в корне (src/main.rs / src/lib.rs) или в родительском модуле. В Go файл в папке автоматически часть пакета, в Rust — нет."
tags: [rust, module, pitfall]
```

```card
front: Четыре уровня видимости в Rust?
back: без pub — приватно (видно своему модулю и его потомкам); pub(super) — родительскому модулю; pub(crate) — всему своему крейту; pub — всем, кто подключит крейт. В Go гранулярность одна (пакет) и решает регистр первой буквы.
tags: [rust, visibility]
```

```card
front: "pub struct S { a: i32 } — поле a доступно снаружи модуля?"
back: "Нет. pub открывает только сам тип; каждое поле помечается pub отдельно (pub a: i32). Это позволяет держать инварианты внутри и давать доступ через методы."
tags: [rust, visibility, struct]
```

```card
front: Можно ли в Rust получить циклическую зависимость модулей — и что с крейтами?
back: Между модулями одного крейта циклы РАЗРЕШЕНЫ (компилятор видит крейт целиком) — в отличие от пакетов Go, где цикл импорта это ошибка. Между крейтами циклы запрещены.
tags: [rust, module, go]
```

```card
front: Зачем pub use?
back: "Реэкспорт: внутри крейт разложен по многим модулям, а наружу показывается плоский удобный API (pub use config::Settings; → mycrate::Settings). Внутреннюю структуру можно менять, не ломая пользователей."
tags: [rust, module, api]
```

## Тесты и повседневные команды

```card
front: "Где живут юнит-тесты в Rust и что делает #[cfg(test)]?"
back: "В том же файле, что код: #[cfg(test)] mod tests { use super::*; #[test] fn ... }. #[cfg(test)] — условная компиляция: модуль собирается только при cargo test и не попадает в релизный бинарник. Тесты видят приватные функции родителя."
tags: [rust, tests]
```

```card
front: "Чем tests/ отличается от #[cfg(test)] mod tests?"
back: "#[cfg(test)] mod tests — юнит-тесты внутри модуля, видят приватное. Папка tests/ рядом с src/ — интеграционные тесты: каждый файл собирается как отдельный крейт и видит только pub-API (чёрный ящик)."
tags: [rust, tests]
```

```card
front: Что такое doc-тест и почему это бонус против Go?
back: Примеры кода в документирующих комментариях /// компилируются и запускаются при cargo test. Поэтому примеры в документации не гниют — их ломает CI. В Go такого механизма нет (только Example-функции, которые не обязаны проверять вывод).
tags: [rust, tests, docs]
```

```card
front: cargo check vs cargo build — зачем первый?
back: "cargo check проверяет типы и заём, но НЕ генерирует бинарник — в разы быстрее. Основной цикл разработки: правка → cargo check → правка. Плюс rust-analyzer в редакторе, чтобы видеть ошибки заёма на месте."
tags: [rust, cargo, tooling]
```
