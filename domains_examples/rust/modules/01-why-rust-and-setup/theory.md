# Зачем Rust и как завести проект

## Суть: что вообще продаёт Rust

У систем-языков исторически было два лагеря.

- **C/C++**: полный контроль над памятью, никакого рантайма, максимальная скорость — но
  ты сам отвечаешь за каждый байт. Забыл `free` — утечка. Освободил дважды — крэш.
  Подержал указатель на освобождённую память — use-after-free и дыра в безопасности.
- **Go / Java / C#**: безопасно и удобно, но ценой **сборщика мусора** (GC) и рантайма.
  GC ходит по куче, решает, что живо, что мертво, и иногда останавливает мир (паузы).
  За это ты платишь латентностью и не контролируешь, когда именно освобождается память.

Rust предлагает третий путь: **безопасность памяти и потоков, как у Go, но без сборщика
мусора и без рантайма, проверенную компилятором.** Никаких пауз GC, никакого «рантайма
языка» в бинарнике — и при этом компилятор не даёт тебе сделать use-after-free, двойное
освобождение или гонку данных. Звучит как «и рыбку съесть, и…» — но цена есть, и зовут её
**borrow checker**. Ты заранее доказываешь компилятору, что с памятью у тебя всё честно;
он за это даёт скорость C без его граблей.

> **Сравнение с Go — главный водораздел.** В Go ты не думаешь, кто владеет срезом и когда
> он умрёт: GC разберётся. В Rust **владение — часть типа и часть твоего кода**. Это
> главное, что придётся уложить в голове (модули 02–03). Взамен: предсказуемая память,
> нулевая стоимость абстракций и «компилируется — значит, целый класс багов невозможен».

> **Простыми словами: что такое «рантайм» и почему его отсутствие — новость.**
> Рантайм — это код, который язык **сам добавляет в твою программу**, чтобы она вообще
> работала: сборщик мусора, планировщик горутин, механизм паник, инициализация мира до
> `main`. В Go этот код живёт внутри каждого бинарника — даже `hello world` тащит с собой
> планировщик и GC (отсюда пара мегабайт на пустом файле). Rust добавляет только крошечный
> стартовый код, который зовёт `main`: ни GC, ни планировщика. Два следствия, и оба важные:
> (1) в программе нет фоновых потоков и пауз, о которых ты не просил; (2) нет и встроенного
> планировщика задач — когда дойдём до `async` (модуль 09), рантайм придётся **подключить
> библиотекой** (Tokio). «Без рантайма» — это одновременно подарок и счёт к оплате.

### Zero-cost abstractions

Девиз Rust: *«ты не платишь за то, чем не пользуешься, а то, чем пользуешься, нельзя было
бы написать руками быстрее»*. Итераторы, дженерики, `async` — всё это компилируется в
плотный код без скрытых аллокаций и без виртуальных вызовов там, где их можно избежать.
Дженерики **мономорфизируются** (компилятор генерирует отдельную копию под каждый
конкретный тип — как шаблоны C++), а не работают через боксинг, как `any` в Go.

## Безопасность без GC: три кита

Rust держится на трёх правилах, которые мы развернём в следующих модулях. Пока — обзор:

1. **Ownership (владение).** У каждого значения ровно один владелец. Когда владелец
   выходит из области видимости — значение освобождается. Никакого GC: освобождение
   детерминировано и происходит в известной точке (модуль 02).
2. **Borrowing (заём).** Можно одолжить ссылку на значение: либо много неизменяемых
   `&T`, **либо** одну изменяемую `&mut T` — но не одновременно. Это на корню убивает
   гонки данных (модуль 03).
3. **Lifetimes (времена жизни).** Компилятор следит, чтобы ссылка не пережила данные, на
   которые смотрит. Никаких «висячих указателей» (модуль 03).

Всё это проверяется **на компиляции**. В рантайме никаких проверок владения нет —
поэтому и нет накладных расходов.

## Тулинг: rustup, cargo, и друзья

### rustup — менеджер тулчейнов

`rustup` ставит и обновляет сам компилятор и инструменты. Аналогия из Go: примерно как
если бы `go` версии управлялись отдельной утилитой.

```bash
# установка (см. rustup.rs), потом:
rustup update                 # обновить стабильный тулчейн
rustc --version               # rustc 1.96.0 (...)  — на момент написания
rustup component add clippy   # линтер (обычно уже стоит)
```

Каналы релизов: **stable** (то, против чего пишут продакшен), **beta** (предрелиз),
**nightly** (нестабильные фичи под флагами). Мы учим **stable**.

### cargo — сборка, зависимости, тесты в одном

`cargo` — это `go build` + `go test` + `go mod` + менеджер зависимостей разом. Главные команды:

```bash
cargo new hello          # создать проект (бинарный по умолчанию)
cargo run                # собрать и запустить
cargo build              # собрать (debug); --release для оптимизаций
cargo test               # прогнать тесты
cargo fmt                # форматировать (аналог gofmt)
cargo clippy             # линтер с кучей полезных подсказок
cargo add anyhow         # добавить зависимость (правит Cargo.toml)
```

Ещё три команды, которые экономят часы:

```bash
cargo check              # проверить типы и заём БЕЗ генерации бинарника — в разы быстрее build
cargo doc --open         # собрать документацию своего кода и зависимостей, открыть в браузере
cargo new mylib --lib    # создать БИБЛИОТЕЧНЫЙ крейт (по умолчанию cargo new делает бинарный)
```

И сразу поставь **rust-analyzer** в редактор (VS Code или любой LSP-клиент): он показывает
ошибки компилятора и выведенные типы прямо в коде, пока ты печатаешь. В Rust это не роскошь,
а рабочая необходимость — ошибки заёма гораздо приятнее видеть на месте, чем вычитывать из
терминала. Основной ритм разработки здесь — «правка → `cargo check` → правка»; полный
`cargo build` зовут реже, чем `go build` в Go, потому что `check` заметно быстрее.

> **Cargo vs `go mod`.** Похоже по духу, отличается в деталях:
> - Манифест — `Cargo.toml` (а не `go.mod`); лок-файл — `Cargo.lock` (как `go.sum`, но это
>   реальный лок версий, а не контрольные суммы).
> - Зависимости тянутся с **crates.io** (как pkg.go.dev, но это ещё и реестр с публикацией).
> - **Версионирование — SemVer с диапазонами** по умолчанию (`anyhow = "1"` означает «любая
>   1.x»). В Go ты пинишь точную версию; здесь по умолчанию диапазон, а точную фиксацию
>   держит `Cargo.lock`.
> - «Крейт» (crate) — единица компиляции и распространения (бинарь или библиотека).
>   «Модуль» (`mod`) — это про пространства имён внутри крейта, не путать с `go module`.

Минимальный `Cargo.toml`:

```toml
[package]
name = "hello"
version = "0.1.0"
edition = "2024"

[dependencies]
# сюда cargo add дописывает крейты, напр.:
# anyhow = "1"
```

### Edition — опциональные «несовместимые» обновления языка

Это важная и непривычная для Go идея. **Edition** (2015 / 2018 / 2021 / **2024**) — это
способ вводить изменения, которые иначе сломали бы старый код, **без раскола экосистемы**.
Крейт объявляет свою редакцию в `Cargo.toml` (`edition = "2024"`), и компилятор применяет
правила именно этой редакции. При этом крейты **разных** редакций спокойно линкуются вместе.

То есть редакция — это не «версия языка», а набор включённых соглашений для конкретного
крейта. Новые проекты бери на **2024** (текущая, стабилизирована в Rust 1.85). Сам
компилятор при этом всегда последний — новые фичи прилетают и в старые редакции, ломающие
изменения — только при переходе на новую редакцию (через `cargo fix --edition`).

> **В Go такого нет.** Go обещает обратную совместимость «навсегда» в рамках Go 1.x, и
> новые фичи просто добавляются. Rust выбрал механизм редакций, чтобы иметь возможность
> чинить ранние ошибки дизайна, не ломая чужие сборки. Цена — надо знать, на какой
> редакции ты пишешь.

## Крейты, модули и видимость: как устроен код внутри проекта

Cargo мы посмотрели снаружи. Теперь — как код организован **внутри**, потому что здесь
терминология Rust расходится с Go настолько, что путаница почти гарантирована.

- **Крейт (crate)** — единица компиляции и распространения. Один крейт = один вызов
  компилятора = одна библиотека **или** один бинарник. Ближайший аналог из Go — не пакет,
  а **модуль Go целиком** (то, что описано в `go.mod`).
- **Модуль (`mod`)** — пространство имён **внутри** крейта. Вот это уже похоже на пакет
  Go, но с важным отличием: модуль не привязан к папке.

Корень крейта — это конкретный файл: `src/main.rs` для бинарника, `src/lib.rs` для
библиотеки. Часто в проекте есть оба: вся логика в библиотечном крейте, а `main.rs` —
тонкая обёртка, которая её зовёт (так логику можно тестировать и переиспользовать).

### Файл становится модулем только если его объявить

```rust
// src/main.rs — корень бинарного крейта
mod config;          // «подключаю модуль config» → компилятор ищет src/config.rs
mod storage;         // → src/storage.rs ЛИБО src/storage/mod.rs (папка с подмодулями)

use config::Settings;   // путь внутри своего крейта
use anyhow::Result;     // путь во ВНЕШНИЙ крейт (тот, что в Cargo.toml)

fn main() -> Result<()> {
    let s = Settings::load()?;
    storage::save(&s)?;      // обращение по полному пути модуля
    Ok(())
}
```

> **Ловушка №1 для гошника.** В Go достаточно положить файл в папку — он автоматически
> часть пакета. В Rust файл, который никто не объявил через `mod`, компилятор **просто не
> увидит**: он не попадёт в сборку, и ты будешь удивляться, почему написанный код «не
> существует». Файл ≠ модуль автоматически, `mod` — это явное «пришей этот файл к дереву
> крейта».

### Видимость: всё приватно, пока не сказано иначе

```rust
// src/config.rs
pub struct Settings {        // pub — тип виден снаружи модуля
    pub path: String,        // внимание: КАЖДОЕ поле помечается pub отдельно
    secret: String,          // приватное поле: снаружи модуля не прочитать
}

impl Settings {
    pub fn load() -> anyhow::Result<Self> { todo!() }   // todo!() — «ещё не написано», паникует

    pub(crate) fn debug_dump(&self) {}   // видно только внутри ЭТОГО крейта
    fn helper(&self) {}                  // видно только внутри модуля config (и его потомков)
}
```

Четыре уровня: без `pub` — приватно (видно своему модулю и его **потомкам**);
`pub(crate)` — всему своему крейту; `pub(super)` — родительскому модулю; `pub` — всем, кто
подключит крейт.

> **Go-параллель.** В Go видимость решает **регистр первой буквы** (`Foo` экспортирован,
> `foo` — нет), и гранулярность одна — пакет. В Rust это ключевые слова и четыре уровня,
> из которых самый полезный — `pub(crate)`: «публично для моего проекта, но не часть
> публичного API». В Go для этого приходится городить папку `internal/`.

### Два приятных отличия от пакетов Go

1. **Циклы между модулями разрешены.** `config` может пользоваться `storage`, а `storage`
   — `config`: это один крейт, компилятор видит его целиком. В Go циклический импорт
   пакетов — ошибка сборки, из-за которой регулярно выделяют третий пакет «просто чтобы
   разорвать цикл». Здесь циклы запрещены только между **крейтами**.
2. **`pub use` — реэкспорт.** Внутри можно разложить код по десяти модулям, а наружу
   показать плоский удобный API:

```rust
// src/lib.rs
mod config;
mod storage;

pub use config::Settings;   // пользователю крейта видно как mycrate::Settings
pub use storage::save;
```

Пути читаются так: `crate::` — от корня своего крейта, `super::` — на уровень выше,
`self::` — текущий модуль. Если имена столкнулись — `use std::io::Result as IoResult`.

## Тесты: `#[test]` и `cargo test`

Тесты в Rust живут **в том же файле, что и код** — и это первое, что удивляет после
`_test.go`:

```rust
// src/lib.rs — сначала обычный код
pub fn add(a: i32, b: i32) -> i32 { a + b }

// а рядом — тесты, в подмодуле
#[cfg(test)]                 // «компилируй этот модуль ТОЛЬКО при cargo test»
mod tests {
    use super::*;            // втягиваем всё из родительского модуля, включая приватное

    #[test]
    fn adds_two_numbers() {
        assert_eq!(add(2, 2), 4);
    }

    #[test]
    fn result_is_positive() {
        assert!(add(2, 2) > 0);
        assert_ne!(add(2, 2), 5);
    }
}
```

- `#[cfg(test)]` — условная компиляция: в релизный бинарник тесты не попадут вообще.
- `#[test]` помечает функцию как тест, `cargo test` находит их сам
  (`cargo test adds` прогонит только те, чьё имя содержит `adds`).
- Проверки — макросы `assert!`, `assert_eq!`, `assert_ne!`. Провал теста = паника.
- Тест-модуль видит **приватные** функции родителя (он же потомок), поэтому
  юнит-тестировать внутренности можно без «экспорта ради теста».
- Тесты «снаружи», как чёрный ящик, кладут в папку `tests/` рядом с `src/`: там каждый
  файл собирается как отдельный крейт и видит только `pub`-API.

> **Go-параллель и один бонус.** Ритуал похож: `cargo test` ≈ `go test ./...`, тесты бегут
> параллельно (в Rust — по умолчанию, в Go — когда позовёшь `t.Parallel()`). А бонус,
> которого в Go нет: **doc-тесты**. Примеры кода в документирующих комментариях `///`
> реально компилируются и запускаются при `cargo test` — поэтому примеры в Rust-документации
> почти никогда не гниют.

## Первая программа и тизер ownership

```rust
fn main() {
    println!("Hello, Rust!");   // println! — это макрос (восклицательный знак), не функция
}
```

Несколько наблюдений «не как в Go»:

- `println!` с `!` — **макрос**, а не функция. Форматирование (`"{}"`) проверяется на
  компиляции. Пока воспринимай макросы как «функции со звёздочкой».
- `main` ничего не возвращает (или возвращает `Result`, увидим в модуле 05).
- Точка входа, фигурные скобки, статическая типизация — на вид знакомо по Go. А вот
  дальше начинается то, чего в Go нет:

```rust
fn main() {
    let s = String::from("hello");   // s владеет строкой в куче
    let t = s;                       // владение ПЕРЕМЕЩАЕТСЯ в t; s больше не валиден
    println!("{t}");                 // ок
    // println!("{s}");              // ❌ ошибка компиляции — см. ниже
}
```

Если раскомментировать последнюю строку, компилятор скажет примерно так:

```text
error[E0382]: borrow of moved value: `s`
 --> src/main.rs:5:16
  |
2 |     let s = String::from("hello");
  |         - move occurs because `s` has type `String`, which does not implement the `Copy` trait
3 |     let t = s;
  |             - value moved here
...
5 |     println!("{s}");
  |               ^^^ value borrowed here after move
```

В Go `t := s` для строки просто **скопировал бы** заголовок строки, и оба остались бы
валидны. В Rust присваивание **переместило владение**: чтобы не было двух владельцев,
которые оба попытаются освободить одну память. Это и есть та самая дисциплина владения —
весь модуль 02 про неё. Пока запомни ощущение: **«присваивание может забрать значение, а
не скопировать его»**.

> Заметь: компилятор не просто сказал «ошибка», он объяснил *почему* (`String` не
> реализует `Copy`) и *где* произошёл move. Привыкай читать диагностику Rust целиком — это
> буквально половина обучения. Часто там же лежит и готовый совет, как починить.

## Глоссарий модуля

- **Тулчейн (toolchain)** — комплект «компилятор + стандартная библиотека + инструменты»
  фиксированной версии; ставится и переключается через `rustup`.
- **Крейт (crate)** — единица компиляции: одна библиотека или один бинарник.
- **Модуль (`mod`)** — пространство имён внутри крейта; объявляется явно, файл сам себя не
  подключает.
- **Edition** — набор языковых соглашений конкретного крейта (2015 / 2018 / 2021 / 2024).
- **Рантайм** — код, который язык добавляет в программу (GC, планировщик). В Rust его
  практически нет; async-рантайм подключается библиотекой (Tokio).
- **Макрос** — код, который на этапе компиляции разворачивается в другой код. Зовётся с `!`
  (`println!`, `vec!`) или ставится атрибутом (`#[derive(...)]`, `#[test]`, `#[cfg(test)]`).
- **Атрибут** — аннотация в квадратных скобках, влияющая на компиляцию (`#[test]`,
  `#[derive(Debug)]`, `#[cfg(test)]`).
- **Move** — перемещение владения при присваивании или передаче вместо копирования (модуль 02).
- **RAII / drop** — освобождение ресурса в момент, когда его владелец выходит из области
  видимости (модуль 02).
- **`unwrap()`** — «дай значение или паникуй»: удобно в прототипе, опасно в проде (модуль 05).
- **Clippy** — линтер (`cargo clippy`), который знает идиомы и часто предлагает вариант лучше
  твоего.

## Типичные ошибки и заблуждения

- **«Rust — это C++ с другим синтаксисом».** Нет: ключевая идея — проверяемое владение,
  которого в C++ нет. Скорость как у C++, а класс багов с памятью — закрыт компилятором.
- **«Раз нет GC, надо вручную звать `free`».** Тоже нет. Память освобождается
  автоматически, когда владелец выходит из области видимости (RAII), но **детерминированно**
  и без отдельного сборщика. Лучшее из двух миров.
- **«Edition — это версия Rust».** Нет. Компилятор всегда последний; edition — набор
  соглашений конкретного крейта, и крейты разных редакций совместимы.
- **«`cargo` — это только сборщик».** Это сборка + зависимости + тесты + бенчи + публикация.
  Один инструмент на весь жизненный цикл.
- **«`println!` — функция».** Это макрос; `!` — часть синтаксиса вызова макроса.
- **«Присваивание копирует, как в Go».** Для типов без `Copy` оно **перемещает** владение.
  Главный сюрприз первого дня — разберём в модуле 02.
- **«Положил файл в `src/` — он собирается».** Нет: пока где-то нет `mod имя_файла;`,
  компилятор файла не видит. Самая частая «пропажа кода» у новичка.
- **«`pub struct` делает публичными и поля».** Нет: `pub` на структуре открывает только сам
  тип, каждое поле помечается `pub` отдельно. Это фича — инварианты остаются под защитой.
- **«Тесты надо складывать в отдельные файлы, как `_test.go`».** Юнит-тесты живут рядом с
  кодом в `#[cfg(test)] mod tests` и видят приватные функции; отдельная папка `tests/` — для
  тестов «снаружи», через публичный API.
