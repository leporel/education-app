# Карточки

## Ссылки и правило заёма

```card
front: Зачем нужен заём (&), если есть move и clone?
back: Чтобы дать функции доступ к данным, не передавая владение и не делая копию. Владелец остаётся прежним, функция получает ссылку на время. Дёшево (нет аллокаций) и безопасно (проверяется компилятором).
tags: [rust, borrowing]
```

```card
front: Сформулируй правило заёма.
back: В любой момент для значения существует ЛИБО любое число неизменяемых ссылок &T, ЛИБО ровно одна изменяемая &mut T — но не то и другое одновременно. «Много читателей ИЛИ один писатель».
tags: [rust, borrowing, rule]
```

```card
front: &T vs &mut T?
back: "&T — неизменяемая (shared) ссылка: только чтение, их может быть много. &mut T — изменяемая (exclusive): можно менять, должна быть единственной и без одновременных &T."
tags: [rust, references]
```

```card
front: Почему правило заёма убивает гонки данных на компиляции?
back: Гонка = одновременный доступ, где хотя бы один пишет. Правило запрещает иметь писателя (&mut) вместе с любым другим доступом. Нет одновременного «читаю+пишу» → нет гонок и use-after-free (напр. при перевыделении буфера push'ем). Аналог RWMutex, но без рантайма.
tags: [rust, borrowing, data-race]
```

```card
front: Что такое NLL (non-lexical lifetimes) и почему важно?
back: Borrow checker считает заём живым только до его ПОСЛЕДНЕГО использования, а не до конца блока. Поэтому можно взять &v, дочитать, а потом взять &mut v в том же блоке — старые ссылки уже «отжили».
tags: [rust, borrowing, nll]
```

## Слайсы

```card
front: Что такое слайс и чем &str отличается от String?
back: "Слайс — ссылка на непрерывный кусок коллекции (ptr + len), без владения: &str (срез строки), &[T] (срез массива/вектора). String владеет данными в куче; &str — заём (в т.ч. строковые литералы). Функции «почитать» берут &str."
tags: [rust, slice, str]
```

```card
front: Чем слайс Rust отличается от среза Go?
back: Слайс Rust ничем не владеет (чистый заём) и не может пережить источник; пока он жив, источник нельзя менять (активный & заём). Срез Go может пережить массив (GC) и спокойно мутироваться.
tags: [rust, slice, go]
```

## Lifetimes

```card
front: Что такое lifetime ('a) на самом деле?
back: "Не «как долго живёт значение», а аннотация СВЯЗИ: возвращаемая/хранимая ссылка живёт не дольше, чем входные данные, из которых заимствована. Длительность определяет код; 'a лишь связывает входы и выходы."
tags: [rust, lifetimes]
```

```card
front: Почему fn f() -> &String { let s = String::from(\"x\"); &s } не компилируется?
back: Возвращается ссылка на локальную переменную, которая умрёт на выходе из функции → висячая ссылка. Ошибка E0106 (missing lifetime specifier) / переменная не живёт достаточно. В Go GC удержал бы строку — в Rust так нельзя.
tags: [rust, lifetimes, dangling]
```

```card
front: Что такое lifetime elision и когда писать 'a руками?
back: "Компилятор сам расставляет lifetimes в типичных случаях (один входной заём → результат привязан к нему). Руками 'a нужен, когда ссылок на входе несколько и неясно, к какой привязан результат (напр. fn longest<'a>(x: &'a str, y: &'a str) -> &'a str). 90% кода — без явных lifetimes."
tags: [rust, lifetimes, elision]
```

## Lifetimes простыми словами

```card
front: Объясни lifetime одной фразой, без формализма.
back: "У каждой ссылки есть «срок годности» — до какого момента гарантированно живы данные. Внутри функции компилятор видит сроки сам; на границе функции он видит только типы, поэтому 'a дописывает в сигнатуру: «срок результата равен сроку вот этого аргумента»."
tags: [rust, lifetimes]
```

```card
front: Два разных смысла 'static?
back: "1) Тип &'static T — данные живут всё время работы программы (строковый литерал). 2) Ограничение T: 'static — тип НЕ содержит короткоживущих заимствований (String подходит, хотя сама строка умрёт в конце функции). Второй смысл нужен для thread::spawn / tokio::spawn (Send + 'static)."
tags: [rust, static, lifetimes]
```

```card
front: E0515 — что это и какая починка?
back: "«cannot return reference to local variable» — попытка вернуть ссылку на значение, созданное внутри функции. Починка: отдать владение (возвращать String/Vec, а не &str/&[T]). Ссылку возвращают только если она заимствована из аргумента (&s[..i], &self.field)."
tags: [rust, lifetimes, e0515]
```

## Практика заёма

```card
front: Почему v.push(4) конфликтует с живой ссылкой let r = &v, хотя в строке нет &?
back: "Потому что метод берёт заём неявно: v.push(4) — это Vec::push(&mut v, 4), а v.len() — Vec::len(&v). Читая E0502, раскрывай вызовы в Type::method(&mut receiver, ...) — сразу видно конфликт."
tags: [rust, borrowing, methods]
```

```card
front: Пять приёмов, когда borrow checker сказал «нет»?
back: "1) Переупорядочить, чтобы & отжил до &mut (NLL). 2) Сузить область явным блоком. 3) Брать нужное поле/значение, а не всю структуру (разные поля заимствуются независимо; для элементов Vec — split_at_mut). 4) clone(), если данные мелкие. 5) Сменить структуру данных: индексы/id, Rc<RefCell<T>>, каналы. И никакого unsafe."
tags: [rust, borrowing, howto]
```

```card
front: Как узнать, что значит незнакомый код ошибки, например E0597?
back: "rustc --explain E0597 — компилятор напечатает подробное объяснение с примерами. E0597 = «does not live long enough»: ссылка используется дольше, чем живут данные."
tags: [rust, errors, tooling]
```
