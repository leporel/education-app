# Карточки

## Box

```card
front: Зачем нужен Box<T> (два реальных применения)?
back: 1) Рекурсивные типы — без Box компилятор не знает размер (E0072 infinite size); Box даёт фиксированный размер указателя. 2) Trait objects Box<dyn Trait> — хранить значение неизвестного размера за указателем. Это явное «положи в кучу», единоличный владелец.
tags: [rust, box]
```

```card
front: enum List { Cons(i32, List), Nil } не компилируется. Почему и как чинить?
back: "Рекурсивный тип бесконечного размера (E0072): Cons содержит List, тот снова List... Чинится Box: Cons(i32, Box<List>) — теперь размер это i32 + указатель. Как *Node в связном списке Go."
tags: [rust, box, recursive]
```

## Rc / Arc

```card
front: Что делает Rc<T> и как работает Rc::clone?
back: "Разделённое владение в ОДНОМ потоке: данные живут, пока есть хоть один Rc (счётчик strong_count). Rc::clone копирует указатель и +1 к счётчику, данные НЕ дублирует (дёшево). Доступ только неизменяемый. Не Send (неатомарный счётчик)."
tags: [rust, rc]
```

```card
front: Rc vs Arc?
back: Rc — один поток, неатомарный счётчик, дёшево. Arc — много потоков, атомарный счётчик (чуть дороже), можно делить между потоками (Send/Sync). Компилятор не даст отправить Rc в другой поток. Для конкурентности — Arc.
tags: [rust, rc, arc]
```

```card
front: Rc::clone(&a) копирует строку внутри Rc<String>?
back: "Нет: копирует указатель и инкрементит счётчик ссылок, данные общие. Глубокая копия данных — это (*a).clone() / a.as_ref().clone(). По соглашению пишут Rc::clone(&a), чтобы было видно — это разделение, не глубокая копия."
tags: [rust, rc, clone]
```

## Внутренняя изменяемость

```card
front: Что такое внутренняя изменяемость и зачем Cell/RefCell?
back: Возможность менять данные через неизменяемую ссылку &. Cell<T> — для Copy-типов, get/set целиком. RefCell<T> — для любых, выдаёт borrow()/borrow_mut() с проверкой правила заёма В РАНТАЙМЕ. Нужны, когда статически «один писатель» не доказать, но логически он соблюдён.
tags: [rust, interior-mutability]
```

```card
front: Чем RefCell отличается от обычного заёма по проверке?
back: "Обычный заём проверяется на компиляции (бесплатно, надёжно). RefCell переносит ту же проверку «писатель ИЛИ читатели» в рантайм: нарушение (два borrow_mut сразу) — паника already borrowed: BorrowMutError, а не ошибка компиляции. Это компромисс гибкость↔безопасность, не лазейка."
tags: [rust, refcell]
```

```card
front: Что даёт паттерн Rc<RefCell<T>>?
back: Несколько владельцев (Rc) + изменяемость через & (RefCell). Рабочая лошадка для деревьев/графов/общего состояния в ОДНОМ потоке. Многопоточный аналог — Arc<Mutex<T>> (Arc вместо Rc, Mutex вместо RefCell).
tags: [rust, rc, refcell, pattern]
```

## Deref и Weak

```card
front: "Почему b.len() работает для b: Box<String> (умный указатель «прозрачен»)?"
back: "Благодаря трейту Deref (deref coercion): компилятор авто-разыменует Box до String. Box/Rc/Ref ведут себя как ссылки потому, что реализуют Deref. Это трейт, а не магия."
tags: [rust, deref]
```

```card
front: Бывают ли в безопасном Rust утечки памяти? Когда?
back: "Да: цикл Rc<->Rc (a держит Rc на b, b — Rc на a) — счётчики не дойдут до нуля, память утечёт. Безопасность памяти ≠ отсутствие утечек (утечка не считается небезопасностью). Лечится Weak."
tags: [rust, rc, leak]
```

```card
front: Что такое Weak<T> и как им разрывают цикл Rc?
back: "Слабая ссылка, которая НЕ удерживает данные живыми (не в strong-счётчике). Схема: родитель держит Rc на детей (владеет), дети — Weak на родителя (ссылаются, не владеют). Weak::upgrade() -> Option<Rc<T>> (None, если данные уже мертвы)."
tags: [rust, weak, cycle]
```

## Выбор инструмента

```card
front: Внутренняя изменяемость — объясни простыми словами.
back: "Обычно менять можно только через &mut. Тип с внутренней изменяемостью говорит: «внутри меня есть комнатка, менять её можно и через &, но за порядком следю я сам». Cell — только get/set целиком; RefCell — счётчик заёмов и паника при нарушении; Mutex — настоящий замок. Правило «писатель ИЛИ читатели» остаётся, меняется момент проверки: компиляция → рантайм."
tags: [rust, interior-mutability]
```

```card
front: "Шпаргалка выбора: от самого дешёвого к самому дорогому?"
back: значение (один владелец) → Box (фиксированный размер, рекурсия, dyn) → Rc (совладение, чтение, 1 поток) → Arc (совладение, много потоков) → Cell/RefCell (изменяемость через &) → Rc<RefCell<T>> (общий изменяемый узел) → Arc<Mutex<T>> (то же для потоков). Спускаться только когда вариант выше не подходит.
tags: [rust, smart-pointers, cheatsheet]
```

```card
front: Почему «заверну всё в Rc<RefCell<T>>, чтобы borrow checker отстал» — плохая стратегия?
back: Ошибки компиляции обменяются на паники BorrowMutError в рантайме, плюс лишние счётчики и косвенность. В нормальном Rust-коде 90% данных живут с одним владельцем; Rc<RefCell> — точечный инструмент для настоящего разделённого изменяемого состояния (графы, деревья, наблюдаемое состояние).
tags: [rust, refcell, pitfall]
```

## Глобальное состояние и DST

```card
front: Как сделать «инициализировать один раз на всю программу» без static mut?
back: "static CONFIG: OnceLock<String> = OnceLock::new(); и CONFIG.get_or_init(|| ...). Инициализатор выполнится ровно один раз, даже при гонке потоков — это замена sync.Once из Go. Для изменяемого глобального состояния — static X: Mutex<T>."
tags: [rust, oncelock, static]
```

```card
front: Что такое тип неизвестного размера (DST) и почему dyn Trait хранят за указателем?
back: "DST (dynamically sized type) — тип, размер которого неизвестен на компиляции: dyn Trait, [T], str. Такое значение нельзя положить в переменную или Vec напрямую — только за указателем (Box<dyn T>, &dyn T, &[T], &str), у которого размер фиксирован."
tags: [rust, dst, dyn]
```
