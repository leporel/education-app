# Коллекции, итераторы и замыкания

## Коллекции, владеющие данными

Три рабочие лошадки стандартной библиотеки. Все владеют данными **в куче** и
освобождают их по правилам владения (модуль 02).

### `Vec<T>` — растущий массив

```rust
let mut v: Vec<i32> = Vec::new();
v.push(1);
v.push(2);
let v2 = vec![10, 20, 30];        // макрос-литерал
println!("{}", v2[0]);            // индексация (паника при выходе за границы)
let maybe = v2.get(99);           // Option<&i32> — безопасный доступ, None вместо паники
```

> **Go-параллель.** `Vec<T>` ≈ срез Go `[]T`, но с владением: `Vec` — владелец буфера,
> срез Rust (`&[T]`) — заём. Доступ по индексу `v[i]` паникует при выходе за границы (в Go
> — тоже паника); `v.get(i)` возвращает `Option<&T>` — идиоматичный безопасный вариант.

### `HashMap<K, V>` — словарь

```rust
use std::collections::HashMap;

let mut scores = HashMap::new();
scores.insert("Ann", 10);
scores.insert("Bob", 20);

// get → Option<&V> (нет ключа → None; никакого «нулевого значения» как в Go-map)
if let Some(s) = scores.get("Ann") {
    println!("Ann: {s}");
}

// entry API — «вставить, если нет» / «обновить»
*scores.entry("Ann").or_insert(0) += 5;   // было 10 → стало 15
```

> **Тонкость против Go.** В Go `m["нет"]` молча вернёт нулевое значение, и ты используешь
> `v, ok := m[k]` для различения. В Rust `get` сразу возвращает `Option<&V>` — отсутствие
> ключа невозможно перепутать с «значение есть и оно ноль». `entry().or_insert()` —
> идиоматичный «get-or-create» без двойного поиска.

### `String` vs `&str`

- `String` — владеющая, растущая строка в куче (как `Vec<u8>` валидного UTF-8).
- `&str` — заём строки (срез), в т.ч. строковые литералы (модуль 03).

```rust
let mut s = String::from("hello");
s.push_str(" world");            // мутируем владеющую строку
let slice: &str = &s[0..5];      // заём части
fn takes_str(_: &str) {}         // принимай &str — самый общий вход
```

Строки — **UTF-8**, индексация по байтам, не по символам: `s[0]` запрещено (символ может
быть многобайтным). Перебор — через `.chars()` (по символам) или `.bytes()` (по байтам).

### Шпаргалка: `String` ↔ `&str`

Тема, на которой новички теряют больше всего времени, поэтому — таблицей.

| Что надо | Как | Аллокация? |
|---|---|---|
| `&str` → `String` | `s.to_string()`, `String::from(s)`, `s.to_owned()`, `s.into()` | да |
| `String` → `&str` | `&s`, `s.as_str()`, `&s[..]` | нет |
| собрать из частей | `format!("{a}-{b}")` | да |
| дописать в конец | `s.push_str("x")`, `s.push('c')` | иногда (когда буфер вырос) |
| число → строка | `n.to_string()`, `format!("{n}")` | да |
| строка → число | `s.trim().parse::<i32>()?` | нет |
| `Vec<String>` → одна строка | `parts.join(", ")` | да |

Три правила выбора, закрывающие 90% случаев:

- **В параметрах функции — `&str`.** Он принимает и `String` (автоматически, через deref
  coercion), и литерал, и срез. `&String` в параметре — почти всегда лишнее сужение.
- **В полях структуры — `String`.** Владеть проще, чем тащить в структуру lifetime (модуль 03).
- **В возвращаемом значении — `String`**, если строку создала функция, и `&str` только если
  она заимствована из аргумента или из `self` (иначе `E0515`, модуль 03).

И про длину: `s.len()` — это **байты**, а не символы. `"привет".len() == 12`. Символы считает
`s.chars().count()`, и это O(n): UTF-8 — кодировка переменной длины, «прыгнуть к i-му символу»
за одно действие нельзя. Если такой доступ нужен часто — тебе нужна другая структура данных
(`Vec<char>`), а не строка.

## Итераторы: ленивые, композируемые, zero-cost

Итератор — это любой тип, реализующий трейт `Iterator` (модуль 06): метод `next() ->
Option<Self::Item>`. Главные три свойства:

### 1. Ленивость

Адаптеры (`map`, `filter`, ...) **ничего не делают**, пока итератор не «прогонят»
терминальной операцией. Они лишь описывают конвейер.

```rust
let v = vec![1, 2, 3, 4, 5];

// это НИЧЕГО не вычисляет — просто строит конвейер
let pipeline = v.iter().map(|x| x * 2).filter(|x| x > &4);

// вот теперь конвейер исполняется (collect — терминальная операция)
let result: Vec<i32> = pipeline.collect();   // [6, 8, 10]
```

Забыл терминальную операцию — компилятор предупредит: `unused `Map` that must be used`
(итераторы помечены `#[must_use]`).

### 2. Композиция (адаптеры)

```rust
use std::collections::HashMap;

let nums = vec![3, 1, 4, 1, 5, 9, 2, 6];

let sum_of_evens_squared: i32 = nums.iter()
    .filter(|&&x| x % 2 == 0)     // 4, 2, 6
    .map(|&x| x * x)              // 16, 4, 36
    .sum();                       // 56

let indexed: Vec<(usize, &i32)> = nums.iter().enumerate().collect();   // [(0,&3),(1,&1),...]
```

Частые адаптеры: `map`, `filter`, `filter_map`, `enumerate`, `zip`, `take`, `skip`,
`flat_map`, `rev`, `chain`. Терминальные: `collect`, `sum`, `product`, `count`, `fold`,
`any`, `all`, `find`, `max`/`min`, `for_each`, и обычный `for x in iter`.

> **Go-параллель.** В Go (до недавних range-over-func) ты бы писал явный цикл `for` с
> аккумулятором. Конвейер итераторов читается как декларативный pipeline (ближе к LINQ/
> Stream/SQL), но — и это ключевое — он **zero-cost**: компилятор разворачивает цепочку в
> один плотный цикл без промежуточных аллокаций. `filter().map().sum()` не создаёт
> временных векторов. Абстракция, за которую не платишь.

### 3. Три способа итерировать: заём, изменяемый заём, владение

```rust
let v = vec![String::from("a"), String::from("b")];

for s in v.iter() { /* s: &String — читаем, v цел */ }
// for s in v.iter_mut() { ... }  // &mut String — меняем на месте (нужен mut v)
for s in v.into_iter() { /* s: String — забираем владение, v ПОТРАЧЕН */ }
// println!("{v:?}");  // ❌ после into_iter v перемещён
```

- `iter()` → `&T` (заём, коллекция остаётся).
- `iter_mut()` → `&mut T` (изменяемый заём, правим на месте).
- `into_iter()` → `T` (владение, коллекция израсходована).

`for x in v` без метода = `v.into_iter()` (забирает владение!). Если нужно сохранить
коллекцию — `for x in &v` (это `iter()`). Очень частая ловушка новичка.

## `collect` умеет больше, чем `Vec`

`collect()` собирает итератор в любой тип, который умеет собираться (трейт `FromIterator`), а
целевой тип берётся из аннотации:

```rust
use std::collections::{HashMap, HashSet};

let v: Vec<i32>             = (1..=3).collect();
let s: String               = vec!["a", "b"].into_iter().collect();   // "ab"
let set: HashSet<i32>       = vec![1, 1, 2].into_iter().collect();    // {1, 2}
let map: HashMap<&str, i32> = vec![("a", 1)].into_iter().collect();
```

Самый ценный трюк — **`collect` в `Result`**. Если каждый элемент может провалиться,
коллекция `Result`'ов «выворачивается наизнанку»: получается один `Result` на всю коллекцию.

```rust
let raw = vec!["1", "2", "x"];

// Result<Vec<i32>, ParseIntError>: либо ВСЕ распарсились, либо первая ошибка
let parsed: Result<Vec<i32>, _> = raw.iter().map(|s| s.parse::<i32>()).collect();
assert!(parsed.is_err());

// а если кривые элементы надо просто выбросить — filter_map + .ok()
let good: Vec<i32> = raw.iter().filter_map(|s| s.parse::<i32>().ok()).collect();   // [1, 2]
```

В Go это был бы цикл с `if err != nil { return nil, err }` внутри. Здесь — одна строка, и
решение «падать на первой ошибке или пропускать плохие» выражено выбором метода.

## Ещё немного про коллекции на каждый день

```rust
let mut v = Vec::with_capacity(1000);   // сразу выделить место — меньше перевыделений
v.extend([3, 1, 2]);                     // добавить всё из другого итератора/массива
v.sort();                                // сортировка на месте (требует Ord)
v.sort_by_key(|x| -x);                   // сортировка по вычисленному ключу
v.dedup();                               // убрать ПОДРЯД идущие дубли (обычно после sort)
v.retain(|x| *x > 1);                    // оставить подходящие, остальные удалить
let last = v.pop();                      // Option<T> — снять с конца
```

Кроме `Vec` и `HashMap` в std живут ещё три полезных типа:

- **`HashSet<T>`** — множество (в Go это `map[T]struct{}`, здесь — честный тип).
- **`BTreeMap` / `BTreeSet`** — упорядоченные по ключу: перебор идёт в порядке сортировки и
  есть запросы по диапазону. В Go для этого приходится собирать ключи и сортировать руками.
- **`VecDeque<T>`** — двусторонняя очередь: дешёвые вставки и снятия с обоих концов.

> **Про рост и `with_capacity`.** `Vec` растёт удвоением, как срез в Go: когда ёмкость
> исчерпана, выделяется новый буфер и данные копируются. Если размер известен заранее,
> `Vec::with_capacity(n)` (аналог `make([]T, 0, n)`) убирает эти перевыделения. Разница с Go
> в том, что здесь момент аллокации **видно** в коде.

> **Важно про `HashMap`:** порядок перебора не определён и меняется между запусками (как в
> Go — там это сделано намеренно). Нужен стабильный порядок — либо `BTreeMap`, либо собери
> ключи в `Vec` и отсортируй.

## Замыкания: функции, захватывающие окружение

Замыкание — анонимная функция, которая может **захватить** переменные из окружающего
кода:

```rust
let factor = 3;
let multiply = |x: i32| x * factor;     // захватил factor из окружения
println!("{}", multiply(5));            // 15
```

Это похоже на func-литералы Go (`func(x int) int { return x * factor }`), но Rust
**различает, КАК именно** замыкание трогает захваченное — это выражается тремя трейтами:

| Трейт | Как захватывает | Можно вызвать |
|---|---|---|
| `Fn` | по неизменяемой ссылке (`&`) — только читает | многократно |
| `FnMut` | по изменяемой ссылке (`&mut`) — меняет окружение | многократно |
| `FnOnce` | по значению (move) — потребляет захваченное | один раз |

```rust
let s = String::from("hi");
let print_it = || println!("{s}");      // Fn: только читает s
print_it(); print_it();                  // можно много раз

let mut count = 0;
let mut inc = || count += 1;             // FnMut: меняет count
inc(); inc();                            // count == 2

let owned = String::from("bye");
let consume = move || owned;             // FnOnce: move-захват, отдаёт owned наружу
let got = consume();                     // можно вызвать ОДИН раз
```

Компилятор сам выбирает «слабейший» подходящий трейт. Ключевое слово **`move`** заставляет
замыкание **забрать владение** захваченными переменными — это критично, когда замыкание
переживает текущую область (передаётся в поток или async-задачу; увидим в модуле 09).

> **Зачем три трейта, а Go обходится одним?** Потому что Rust следит за владением и заёмом
> даже внутри замыканий. `Fn` обещает «я только читаю — меня можно шарить и звать
> параллельно»; `FnMut` — «я меняю состояние»; `FnOnce` — «я потребляю, после меня ничего
> не осталось». Это позволяет, например, безопасно решать, можно ли отдать замыкание в
> несколько потоков. В Go таких гарантий на уровне типа нет.

Функции, принимающие замыкания, используют эти трейты как bound:

```rust
fn apply<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 { f(x) }   // принимает любой Fn(i32)->i32
println!("{}", apply(|n| n + 1, 10));   // 11
```

## Глоссарий модуля

- **Итератор** — тип с методом `next() -> Option<Item>`; всё остальное построено над ним.
- **Адаптер** — метод, возвращающий новый итератор (`map`, `filter`, `take`, `zip`); ленивый.
- **Терминальная операция** — метод, который «прогоняет» итератор и выдаёт результат
  (`collect`, `sum`, `count`, `fold`, `for_each`, `any`).
- **Ленивость** — адаптеры ничего не считают, пока не позвали терминальную операцию.
- **`FromIterator` / `collect`** — механизм сборки итератора в коллекцию; целевой тип берётся
  из аннотации.
- **`IntoIterator`** — трейт, благодаря которому работает `for x in ...`; `for x in v` берёт
  владение, `for x in &v` — заём.
- **Замыкание (closure)** — анонимная функция, захватывающая переменные из окружения.
- **Захват (capture)** — то, как замыкание берёт окружение: по `&`, по `&mut` или по значению.
- **`Fn` / `FnMut` / `FnOnce`** — трейты замыканий по способу захвата и числу вызовов.
- **`move`** — просьба захватить окружение по значению (нужно для потоков и async-задач).
- **Deref coercion** — автоматическое приведение `&String` → `&str`, `&Vec<T>` → `&[T]`.
- **Ёмкость (capacity)** — сколько элементов буфер вмещает без перевыделения; `len` ≤ `capacity`.
- **Entry API** — `map.entry(k).or_insert(v)`: get-or-create за один поиск.
- **UTF-8** — кодировка строк Rust: `len()` в байтах, символы — через `.chars()`.

## Типичные ошибки и заблуждения

- **«`for x in v` просто читает».** Нет: это `into_iter()` — **забирает владение** `v`.
  Чтобы не потерять коллекцию, пиши `for x in &v` (заём) или `&mut v`.
- **«Адаптеры выполняются сразу».** Нет, итераторы ленивы: `map`/`filter` строят конвейер,
  исполнение — на терминальной операции (`collect`/`sum`/`for`). Без неё — предупреждение.
- **«Конвейер итераторов медленнее ручного цикла».** Наоборот, zero-cost: разворачивается
  в один цикл без промежуточных аллокаций.
- **«`s[0]` даст первый символ строки».** Запрещено: строки UTF-8, индексация по байтам
  небезопасна. Используй `.chars().next()` или срез по валидным границам.
- **«В `HashMap` нет ключа → получу ноль».** Нет: `get` возвращает `Option<&V>`. Это плюс —
  не спутать «нет ключа» с «значение ноль» (в Go это требует `v, ok := m[k]`).
- **«Замыкание — это просто func-литерал».** Это ещё и выбор `Fn`/`FnMut`/`FnOnce` и
  способа захвата; `move` забирает владение — важно для потоков/async.
- **«`s.len()` — это число символов».** Это число **байтов**. `"привет".len() == 12`.
  Символы: `s.chars().count()` (и это O(n)).
- **«Если элементы могут не распарситься, придётся писать цикл».** Нет:
  `collect::<Result<Vec<_>, _>>()` даст «всё или первая ошибка», а `filter_map(|x| x.ok())` —
  «пропустить плохие».
- **«Порядок перебора `HashMap` стабилен».** Не стабилен и меняется между запусками (как в
  Go). Нужен порядок — `BTreeMap` или сортировка ключей.
- **«`Vec` растёт бесплатно».** Он растёт удвоением с копированием буфера; если размер известен
  — `Vec::with_capacity(n)`.
