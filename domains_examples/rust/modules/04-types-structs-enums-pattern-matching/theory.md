# Типы, структуры, enum и сопоставление

## Скалярные и составные типы

Числа в Rust — с явным размером и знаком: `i8/i16/i32/i64/i128/isize` (знаковые),
`u8/.../usize` (беззнаковые), `f32/f64` (дробные). По умолчанию целое — `i32`, дробное —
`f64`. `usize`/`isize` — размер под платформу (как `int` для индексов в Go, по сути).

```rust
let a = 10;          // i32 по умолчанию
let b: u64 = 10;     // явный тип
let c = 3.0;         // f64
let big = 1_000_000; // _ — просто разделитель разрядов
```

> **Не как в Go: нет неявных приведений чисел.** В Go ты тоже приводишь явно (`int64(x)`),
> и Rust здесь строг так же: `a as u64` — явный каст. Складывать `i32` и `u64` без
> приведения нельзя. Зато переполнение в debug-сборке **паникует** (а не молча
> заворачивается, как в Go/C): `255u8 + 1` в debug упадёт, в release — обернётся. Для
> явного поведения есть `wrapping_add`, `checked_add`, `saturating_add`.

Прочие скаляры: `bool`, `char` (это **скаляр Unicode**, 4 байта, не байт как в C!).
Составные: кортежи `(i32, f64, char)` и массивы фиксированного размера `[i32; 3]`.

```rust
let point = (1, 2.5, 'x');
let (i, f, ch) = point;       // деструктуризация кортежа
let arr = [0u8; 4];           // [0, 0, 0, 0]
```

## Мелочи базовой грамматики, которые легко проскочить

Большая часть синтаксиса Rust гошника не удивит, но четыре вещи стоит назвать явно — иначе
они будут мешать читать примеры дальше.

**1. Почти всё — выражение.** `if`, `match`, `loop` и просто блок `{ ... }` возвращают
значение. Точка с запятой «съедает» результат, её отсутствие — отдаёт его наружу.

```rust
let grade = if score > 90 { "A" } else { "B" };   // тернарник не нужен, его тут и нет
let x = { let a = 2; a * a };                      // блок-выражение: x == 4
```

> **Не как в Go:** там `if` — только оператор, и для такого пишут `var grade string` плюс
> присваивание в каждой ветке. Здесь «ветка возвращает значение» — норма жизни, и именно
> поэтому в Rust так мало временных `mut`-переменных.

**2. Shadowing (затенение) — это не `mut`.** Одно имя можно объявить заново, хоть с другим
типом; прежняя переменная просто перестаёт быть видимой.

```rust
let spaces = "   ";          // &str
let spaces = spaces.len();   // теперь usize — это НОВАЯ переменная, а не мутация
```

Так идиоматично «дорабатывают» значение по шагам (прочитал → распарсил → провалидировал), не
изобретая `input_raw`, `input_parsed`, `input_ok`. Отличие от `mut`: `mut` меняет **то же
самое** значение и тип менять не может, shadowing создаёт новое.

**3. `const` и `static` — вместо одного `const` из Go.**

```rust
const MAX_RETRIES: u32 = 3;         // всегда с типом; вычисляется на компиляции и
                                     // подставляется в каждое место использования
static APP_NAME: &str = "fetcher";  // одно место в памяти на всю программу
```

Правило простое: почти всегда бери `const`. `static` нужен, когда важен именно единый адрес
в памяти. `static mut` существует, но требует `unsafe` и в нормальном коде не встречается —
для изменяемого глобального состояния берут `OnceLock`/`Mutex` (модули 08–09).

**4. Циклы: `loop`, `while`, `for` — и `break` со значением.**

```rust
let mut n = 0;
let first_big = loop {           // loop — бесконечный цикл, но он ВЫРАЖЕНИЕ
    n += 1;
    if n * n > 50 { break n; }   // break умеет вернуть значение
};

for i in 0..5 {}                 // 0,1,2,3,4 — полуоткрытый диапазон
for i in 0..=5 {}                // 0..5 включительно
for (i, c) in "abc".chars().enumerate() {}

'outer: for i in 0..10 {         // метка — чтобы выйти сразу из двух циклов
    for j in 0..10 {
        if i * j > 20 { break 'outer; }
    }
}
```

Классического `for i := 0; i < n; i++` в Rust нет вообще: только диапазоны и итераторы
(модуль 07).

## Структуры и `impl`

Три вида структур:

```rust
// 1) с именованными полями (основной вид)
struct User {
    name: String,
    age: u32,
    active: bool,
}

// 2) кортежная — поля без имён, доступ по индексу
struct Point(i32, i32);

// 3) единичная (unit) — без полей, для маркеров/трейтов
struct Marker;
```

Методы живут в блоке `impl` — **отдельно** от объявления полей (как методы Go объявляются
отдельно от структуры, только сгруппированы в `impl`):

```rust
impl User {
    // ассоциированная функция (нет self) — обычно конструктор; зовётся User::new(...)
    fn new(name: String, age: u32) -> Self {
        Self { name, age, active: true }   // Self == User
    }

    // метод: &self — читаем (заём), как func (u User) в Go с получателем по значению-копии,
    // но тут это именно ссылка
    fn greet(&self) -> String {
        format!("Привет, {}!", self.name)
    }

    // &mut self — меняем поля
    fn deactivate(&mut self) {
        self.active = false;
    }

    // self по значению — забирает владение (редко; напр. «потребляющие» преобразования)
    fn into_name(self) -> String {
        self.name
    }
}
```

> **Go-параллель по получателям.** `&self` ≈ получатель-указатель для чтения, `&mut self`
> ≈ указатель для записи, `self` ≈ получатель по значению, но с настоящим move (забирает
> владение). В Go выбор «значение vs указатель» — про копию и мутацию; в Rust — ещё и про
> владение (заём vs передача).

### Как вообще напечатать структуру: `#[derive(Debug)]`

`println!("{}", user)` для своей структуры **не скомпилируется**: `{}` требует трейт
`Display`, который пишут руками (модуль 06). Для отладочной печати есть `{:?}` и трейт
`Debug` — и вот его компилятор сгенерирует по первой просьбе:

```rust
#[derive(Debug)]                  // «сгенерируй мне реализацию Debug»
struct User { name: String, age: u32 }

let u = User { name: "Ann".into(), age: 30 };
println!("{u:?}");                // User { name: "Ann", age: 30 }
println!("{u:#?}");               // то же, но с переносами строк — «красивый» вид
```

Пусть `#[derive(Debug)]` станет рефлексом: без него нельзя ни напечатать структуру, ни
использовать её в `assert_eq!` (он печатает обе стороны при провале теста). Ближайший аналог
из Go — `fmt.Printf("%+v", u)`, который работает всегда и сам; здесь за это просят одной
строкой.

Ещё два полезных derive'а пригодятся сразу:

```rust
#[derive(Debug, Default, Clone, PartialEq)]
struct Config { retries: u32, verbose: bool, name: String }

let a = Config::default();                             // 0, false, "" — нули каждого типа
let b = Config { retries: 5, ..Default::default() };   // «как дефолт, но retries = 5»
assert_ne!(a, b);                                       // == работает благодаря PartialEq
```

`..Default::default()` — синтаксис обновления структуры: задать одно-два поля и не
перечислять остальные. Это ближайшая замена привычке Go «нулевое значение структуры уже
годное».

## Enum — сумм-типы, которых нет в Go

Вот где Rust резко обгоняет Go. `enum` — это не «нумерованные константы», а **тип-сумма**:
значение является **ровно одним** из вариантов, и варианты могут **нести данные разной
формы**:

```rust
enum Shape {
    Circle(f64),                 // несёт радиус
    Rectangle { w: f64, h: f64 },// несёт именованные поля
    Point,                       // без данных
}
```

В Go такого нет. Чтобы изобразить «одно из», там городят интерфейс + несколько реализаций,
или структуру со множеством опциональных полей и флагом-дискриминатором — и компилятор не
гарантирует, что ты учёл все случаи. В Rust `enum` + `match` дают **исчерпывающую**
проверку: забыл вариант — не скомпилируется.

```rust
fn area(s: &Shape) -> f64 {
    match s {
        Shape::Circle(r) => std::f64::consts::PI * r * r,
        Shape::Rectangle { w, h } => w * h,
        Shape::Point => 0.0,
    }   // если убрать любую ветку — ошибка: non-exhaustive patterns
}
```

## `match` — сопоставление с образцом

`match` — это `switch` на стероидах: он сопоставляет **структуру** значения, извлекает
данные из вариантов и **обязан покрыть все случаи**.

```rust
let n = 3;
let label = match n {
    0 => "ноль",
    1 | 2 => "мало",            // несколько образцов через |
    3..=9 => "несколько",       // диапазон
    _ => "много",               // _ — «всё остальное» (как default)
};
```

Ключевые отличия от `switch` в Go:
- **Исчерпываемость**: компилятор требует покрыть все варианты (или поставить `_`). Забыл
  случай `enum` — ошибка компиляции, а не тихий пропуск.
- **Это выражение**: `match` возвращает значение, его можно присвоить.
- **Деструктуризация**: образцы вынимают данные (`Circle(r)` сразу даёт `r`).
- Никаких проваливаний (`fallthrough`) по умолчанию — каждая ветка изолирована.

### Ещё про образцы: guards, `@`, `..`, `matches!`

`match` умеет больше, чем «перечисли варианты»:

```rust
enum Msg { Move { x: i32, y: i32 }, Text(String), Quit }

fn handle(m: &Msg) -> String {
    match m {
        // guard — дополнительное условие поверх образца
        Msg::Move { x, y } if x == y => format!("по диагонали на {x}"),
        // .. — «остальные поля меня не интересуют»
        Msg::Move { x, .. } => format!("сдвиг по x на {x}"),
        Msg::Text(s) if s.is_empty() => "пустой текст".to_string(),
        Msg::Text(s) => format!("текст: {s}"),
        Msg::Quit => "выход".to_string(),
    }
}

// x @ образец — проверить И привязать значение целиком
let kind = match 7 {
    small @ 0..=9 => format!("одна цифра: {small}"),
    other => format!("много: {other}"),
};

// matches! — когда нужен просто булев ответ «подходит ли под образец»
let m = Msg::Quit;
let is_quit = matches!(m, Msg::Quit);          // true, без полного match
```

И одна вещь, которая снимет будущий вопрос «почему у меня здесь `&String`, а не `String`»:
когда ты матчишь **по ссылке** (`match m`, где `m: &Msg`), Rust автоматически делает
привязки ссылками — это называется *match ergonomics*. То есть `Msg::Text(s)` даёт
`s: &String` и **не забирает** строку из сообщения. Раньше для этого писали `ref s`; сейчас
оно происходит само, и структура остаётся целой.

Образцы работают не только в `match`: `let (a, b) = pair;`,
`let Config { retries, .. } = cfg;`, `if let`, `let else`, и даже в параметрах функции
(`fn dist(Point { x, y }: &Point)`). Это одна и та же машинерия сопоставления.

## Нет `nil` — есть `Option<T>`

Самая дорогая ошибка в истории — null. В Go это `nil`: забыл проверить — паника в проде в
самый неудобный момент, и компилятор молчал. В Rust `null` **нет вообще**. «Может быть
значение, а может и нет» выражается типом `Option<T>` из стандартной библиотеки:

```rust
enum Option<T> {     // это обычный enum (уже в прелюдии)
    Some(T),
    None,
}
```

Раз «отсутствие» — это вариант `None`, компилятор **заставляет** его обработать: ты не
можешь случайно использовать `Option<T>` как `T`.

```rust
fn find_user(id: u32) -> Option<String> {
    if id == 1 { Some(String::from("Ann")) } else { None }
}

fn main() {
    match find_user(1) {
        Some(name) => println!("нашли: {name}"),
        None => println!("нет такого"),
    }
}
```

> **Вот в чём выигрыш для Go-разработчика.** В Go `func findUser(id) *User` может вернуть
> `nil`, и если ты забудешь проверить — `panic: nil pointer dereference` в рантайме. В
> Rust тип `Option<String>` физически не даёт обратиться к строке, не разобрав `None`.
> Целый класс «забыл проверить на nil» багов исчезает на компиляции.

### Удобные способы разобрать `Option`

`match` — базовый, но часто многословный. Идиоматичные сокращения:

```rust
let maybe = find_user(1);

// if let — когда интересен один вариант
if let Some(name) = &maybe {
    println!("привет, {name}");
}

// let else — «достань или выйди» (ранний возврат), плоский код без вложенности
let Some(name) = find_user(2) else {
    println!("пользователь не найден");
    return;
};
println!("{name}");   // здесь name точно есть

// комбинаторы — без ветвлений
let len = find_user(1).map(|s| s.len()).unwrap_or(0);   // длина или 0
let name = find_user(2).unwrap_or_else(|| String::from("гость"));
```

- `unwrap()` / `expect("...")` — «дай значение или паникуй». Удобно в прототипах и тестах;
  в продакшене — осознанно (паника = краш). Это мостик к модулю 05 (ошибки): `Option`
  про «есть/нет», `Result` про «получилось/ошибка с причиной».

## Глоссарий модуля

- **Сумм-тип (sum type)** — «ровно одно из перечисленного»; в Rust это `enum` с данными в
  вариантах. Противоположность — тип-произведение (`struct`: «и то, и другое сразу»).
- **Вариант (variant)** — одна из альтернатив enum'а.
- **Исчерпываемость (exhaustiveness)** — требование покрыть в `match` все варианты.
- **Образец (pattern)** — шаблон, который сопоставляется со структурой значения и попутно
  вынимает из него данные.
- **Guard** — условие `if ...` в ветке `match`, дополняющее образец.
- **Деструктуризация** — разбор составного значения на части (`let (a, b) = pair;`).
- **Shadowing (затенение)** — повторное объявление имени, создающее новую переменную.
- **Ассоциированная функция** — функция в `impl` без `self`, зовётся как `Type::name()`;
  обычно конструктор (`User::new`).
- **`Self`** — тип, для которого написан данный `impl` (внутри `impl User` это `User`).
- **`Option<T>`** — «значение есть или нет»: `Some(T)` / `None`. Замена `nil`.
- **`derive`** — атрибут-просьба сгенерировать реализацию трейта (`Debug`, `Clone`,
  `Default`, `PartialEq`, ...).
- **Match ergonomics** — правило, по которому при сопоставлении по ссылке привязки сами
  становятся ссылками.
- **`E0004`** — «non-exhaustive patterns»: в `match` не покрыт какой-то вариант.

## Типичные ошибки и заблуждения

- **«`enum` в Rust — как `iota`-константы в Go».** Нет: это полноценный сумм-тип, варианты
  несут данные разной формы. Это его главная сила.
- **«`match` — просто `switch`».** Он исчерпывающий (забыл вариант — ошибка компиляции),
  это выражение и он деструктурирует. Иной инструмент.
- **«`Option` — это про null, та же беда».** Наоборот: `Option` делает отсутствие **видимым
  в типе** и обязательным к обработке. Забыть нельзя — компилятор не пустит.
- **«`unwrap()` — нормальный способ доставать значения».** `unwrap()` паникует на `None`.
  В прототипе/тесте — ок; в проде предпочитай `match`/`if let`/`let else`/комбинаторы или
  переходи к `Result` и `?` (модуль 05).
- **«Числа приводятся сами».** Нет: приведение явное (`x as u64`), смешивать типы нельзя.
  И помни про панику при переполнении в debug.
- **«`char` — это байт».** Это скаляр Unicode (4 байта). Байт — это `u8`.
- **«Свою структуру можно просто напечатать».** Нужен `#[derive(Debug)]` и `{:?}`; `{}`
  требует руками написанный `Display`.
- **«Shadowing — это мутация».** Нет, это новая переменная с тем же именем (можно даже с
  другим типом). Мутация — только через `mut`.
- **«В `match` по ссылке я забираю данные из варианта».** Нет: при сопоставлении по ссылке
  привязки сами становятся ссылками (match ergonomics), значение остаётся целым.
- **«Для глобальной изменяемой переменной есть `static mut`».** Формально да, но он требует
  `unsafe` и в нормальном коде не используется: берут `OnceLock`, `Mutex` или передают
  состояние явно.
